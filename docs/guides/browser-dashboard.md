# ブラウザ / LAN で Dashboard を共有する

> 対象: 拡張を入れていない参加者や、HTTP で同じ画面を見せたいドライバー  
> 関連: [Live Share 運用](./live-share.md)（エディタ共有） · [非同期 git 共有](./async-sharing.md)（同席できない場合）

## このガイドでできるようになること

Dashboard をブラウザで開き、必要なら LAN 上の他マシンから同じ画面を見る。

**書き込みはサーバが拒否する**（`--host` 時は全クライアント書込不可）。見せるのは現在地・成果物・監査であり、ゲート承認の操作面ではない。

## いつ使うか

| 状況 | このガイド | 代わり |
|------|-----------|--------|
| 拡張未導入の人が同じ Wi‑Fi にいる | ○ LAN 共有 | — |
| モブでコードも一緒に触る | Live Share と併用可 | [live-share.md](./live-share.md) |
| 時間がずれていて同席できない | × | [async-sharing.md](./async-sharing.md) |

## 前提

- リポジトリで `bun install` 済み  
- ワークスペースに有効な Intent / `aidlc/` がある  
- LAN 公開するマシンのファイアウォールで、選んだポートが許可されていること  
- **private な成果物が URL を知っている人に見える**ことを了承していること（チャットの公開チャンネルに URL を貼らない）

## 手順 A: 自分のマシンだけでブラウザ表示

```bash
bun run dashboard
```

期待される結果: ローカルに HTTP サーバが立ち、ブラウザで Dashboard が開く（または表示された URL を開く）。listen は loopback 想定。

## 手順 B: 拡張から LAN 共有（推奨の副経路）

1. ドライバーの IDE でコマンドパレット → **`AIDLC Guide: Share on LAN`**  
2. 確認ダイアログの内容（誰から見えるか・書込不可であること）を読む  
3. 承認すると `--host` 相当でサーバが起動する  
4. 表示された URL を、モブ参加者だけがいるチャネルに共有する

期待される結果: 参加者がブラウザで同じ Now strip / マトリクスを見られる。誰も `[Answer]:` などの書き込みはできない。

## 手順 C: CLI で明示的に `--host`

```bash
bun packages/dashboard-server/src/cli.ts --host
```

ポートやオプションの詳細は起動時のヘルプ / ログを確認する。既定を loopback のままにしておき、LAN は明示操作だけにする、というのが設計上の約束です。

## docs リンクについて

ブラウザ副経路では IDE ファイルオープンに頼れません。参加者にも「docs を開く」を使わせるなら、事前に [ステージ docs の接続先を設定する](./configuring-docs.md) で `stageDocs` または `docsBaseUrl` を入れておく。

## 終了時

- 共有用プロセスを止める（ターミナルで Ctrl+C、または拡張が起動したセッションを終了）  
- Live Share も使っていたら、モブ終了時に **Live Share: Stop Collaboration Session** も忘れずに（[live-share.md](./live-share.md)）

## うまくいかないとき

| 症状 | 確認すること |
|------|----------------|
| 他マシンから開けない | `--host` になっているか、ファイアウォール、正しい IP / ポートか |
| 空の Dashboard | ドライバー側ワークスペースに Intent があるか（サーバの cwd = そのワークスペース） |
| 書込できてしまう | 想定外。`--host` で起動しているか確認し、Issue にする |
