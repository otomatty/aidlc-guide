# カスタマイズページの設計案

日付: 2026-09-14
最終更新: 2026-09-15
状態: 基本方針・主要な操作・エンジン側への共通機能追加を確認し、実装済み。[詳細設計](2026-09-15-customization-page-detailed-design.md)と[実装記録](../../maintenance/customization-implementation.md)を参照。

## 1. 目的と確定事項

開発者が、プロジェクトで使う aidlc-workflows の設定や開発方法を、フォームとページ内AIチャットで編集できるようにする。

| 項目 | ユーザーと確認した方針 |
| --- | --- |
| ページの位置 | 「ステージ一覧」「効果測定」「ドキュメント」「設定」と同じ階層に「カスタマイズ」を追加する |
| 利用者 | 開発者に統一する。管理者との区別、役割別の画面・編集権限は設けない |
| 初回の機能範囲 | ルール、ナレッジ、ワークフロー、エージェント、品質チェック、プラグインの作成・配布を対象にする |
| 編集方法 | フォームとAIへの依頼を行き来し、同じ下書きを編集する |
| 下書きの管理 | 現在の設定に対する下書きは一つ。名前付きの複数案の保存・切り替えは設けない |
| AIとの対話 | カスタマイズページ内のチャット欄で行う |
| AI提案の取り込み | 提案内容を確認し、利用者が「下書きに取り込む」を押して反映する。提案の生成だけでは下書きを変更しない |
| AIの接続方式 | 既存のドキュメントQ&Aと同じ方式で、インストール済みのAIツールを選んで利用する |
| 利用環境 | IDEを主な利用環境とし、ローカルのブラウザー版でも同じ編集・AI相談・差分確認・手動適用を提供する。共有閲覧用ブラウザーは読み取り専用とする |
| 狭い画面の表示 | 「編集／AIチャット」のタブで切り替える。幅が十分なときは編集画面とAIチャットを横並びにする |
| 確定方法 | 複数の変更を下書きにまとめ、差分を確認してから適用する |
| 反映対象 | 今後のワークフローのみ。進行中には反映しない |
| 設定の切り替え | 旧設定でのワークフローが進行中なら、新設定で別の正式なワークフローを始める必要はない。終了後の切り替えでよい |
| 適用操作 | 利用者が手動で適用する。進行中の作業の終了に伴う自動適用は行わない |
| 配布方法 | Guide用の設定ファイルと標準プラグインの両方に対応する。ルールを含む設定の移行はGuide用で扱い、対応する内容は標準プラグインとしても書き出す |
| 設定ファイルの取り込み | 必要な項目を選んで一つの下書きに取り込む。選んだ項目だけ追加・置き換え、ほかの編集は保持する |
| 試行機能 | ユーザーの指示により対象外とする |
| エンジンとの分担 | 設定の生成・更新、適用時の競合防止・復旧をaidlc-workflows側の共通機能として追加する。Guideは画面、下書き、AI提案、取り込み・配布操作を担当する |

## 2. ページ構成の提案

共通ヘッダーに「カスタマイズ」への入口を追加する。既存の「設定」はインストール・更新を引き続き扱う。

ページ上部には対象プロジェクトと変更の状態を表示する。幅が十分な場合、本文は左にカテゴリ、中央に編集画面、右にAIチャットを配置する。

幅が狭いIDEパネルでは、「編集／AIチャット」のタブで表示を切り替え、それぞれにパネルの幅を使う。上下分割やチャットを重ねる表示は採用しない。切替時には編集内容、入力途中のメッセージ、会話、各表示のスクロール位置を保持する。幅が変わって横並びとタブ表示が切り替わる場合も、同じ下書きと会話を引き継ぐ。

AIの提案には変更前後を示す。取り込み後に「編集画面で見る」を押すと、該当するカテゴリ・項目を開く。狭い画面ではこの操作で「編集」タブへ移る。単にタブを切り替える操作では、設定の適用やAI提案の取り込みは行わない。表示を切り替える具体的な幅と、狭い画面でのカテゴリ選択の配置は詳細設計で定める。

利用者別のモードは設けず、各編集画面で必要な詳細項目を展開できる構成にする。

| カテゴリ | 編集内容 |
| --- | --- |
| 開発ルール | コーディング規約、テスト方針、作業方針、禁止事項など |
| ナレッジ | 参考資料の登録・編集と、参照するエージェントの指定 |
| ワークフロー | スコープ、工程の定義・依存関係、成果物、レビュー方針など |
| エージェント | 専門性、責務、作業方針、担当工程など |
| 品質チェック | チェックの定義、対象工程、実行タイミングなど |
| プラグイン | 配布する内容の選択、名前・バージョンの設定、検証、書き出し |

上記は製品として扱いたい範囲であり、全項目を現行エンジンが同じ方式で編集・配布できることを意味しない。現行の制約は第7節に記載する。

画面と編集・検証・適用の処理はIDE版とローカルブラウザー版で共通化し、日常の使いやすさはIDEを基準に設計する。ブラウザー版のAI呼出しとファイル操作は、Guideのローカルサーバーが動くPCで行う。共有閲覧モードでは、画面だけでなく処理の受付側でも編集・適用を拒否する。

### 配布と読み込み

編集するカスタマイズの原本は共通にし、配布時に書き出し形式を選ぶ。

| 形式 | 内容と利用方法 | 制約 |
| --- | --- | --- |
| Guide用の設定ファイル | Guideが編集対応するルールや各種設定をまとめて書き出す。配布先のGuideで読み込み、下書きとして差分を確認してから手動適用する | 読み込みにGuideが必要。形式のバージョンと対象エンジンとの互換性をGuide側で管理する |
| 標準プラグイン | 標準形式が対応する工程・エージェント・センサーなどを、aidlc-workflowsのプラグインとして書き出す | 現行形式で扱えない項目は含められない。既存工程への変更は追加方式など、上流の制約に従う |

標準プラグインに含められない項目と理由を、書き出し前に表示する。含まれない項目を黙って落としたり、二つの形式が同じ内容を配布できると表示したりしない。

Guide用の読み込みも通常の編集・確認・適用の流れを使い、現在の設定を直接上書きしない。適用後はaidlc-workflowsが通常の設定として読む形にし、独自のワークフロー実行エンジンは追加しない。Guide用の形式でも、上流が未対応の実行動作を実現できると約束しない。

Guide用設定ファイルの取り込みは、ルール・工程・エージェントなどの項目単位で選択する方式にする。

- 読み込み内容と現在の下書きを比較し、追加する項目と置き換える項目を示す。
- 同じ項目がある場合は、現在の下書きを残す状態を初期値とし、利用者が選んだ項目だけ置き換える。文章を自動的に合成しない。
- 選ばなかった項目と、読み込みファイルに含まれない項目は変更しない。下書き全体の置き換えや、未選択の新規項目の一括追加は行わない。
- 取り込んだ項目は同じ下書きの中で編集できる。正式な設定への反映は、下書き全体の差分確認と手動適用で行う。

例えば、編集中のテスト方針を残し、配布ファイルからレビュー工程だけを選んで追加できる。

両形式への対応は初回の対象とする。書き出し対象の選択、ファイル構成、同一項目の判定、選択した項目が必要とする参照先の確認、配布ファイルのバージョン互換性は詳細設計で定義する。

## 3. 編集から反映まで

基本の流れは「編集・下書き保存 → 変更確認 → 手動適用」とする。

1. 現在の設定を読み込み、編集用の下書きを作る。
2. フォームによる編集と、利用者が確認して取り込んだAI提案を同じ下書きにまとめる。カテゴリを移動しても下書きを保持する。
3. 下書きは、ワークフローの進行中でも保存できる。未完成の設定は修正が必要な箇所を表示し、適用可能な設定と区別する。
4. 同じ設定を参照する未完了のワークフローがあれば、適用できない理由を表示する。既存の設定ファイルへは書き込まない。
5. 利用者が「変更を確認」で変更の要約とファイル差分を見る。進行中のワークフローがあっても確認できる。影響する工程・エージェントも、参照関係から判定できる範囲で示す。
6. 未完了のワークフローがなくなった後、適用前の検証を通した変更を、利用者が「適用」を押して反映する。適用直前に、対象設定の外部変更と未完了ワークフローの有無を再確認する。

画面で扱う設定は「使用中の設定」と「未適用の下書き」に整理する。下書きの保存と、エンジンが読む設定への反映を混同させない。自動適用の予約や、そのための別の確定状態は設けない。

全カテゴリの変更を一つの下書きに保持し、保存した下書きはページを開き直しても再開できるようにする。一つの下書きに複数のルール・工程・エージェントを含められる。適用に成功した後は、その設定を基に次の編集を始める。適用に失敗した場合は、保存した下書きを維持する。

一時停止や承認待ちは、ワークフローの終了として扱わない。適用時には実際の未完了状態を再確認する。Guide以外で開始・再開されるワークフローとの競合も、エンジン側の共通機能で防ぐ。

詳細調査により、現行2.8.2のlockと未完了検査だけでは競合と強制終了後の部分反映を防げないことが判明した。詳細設計の第11・12節で、エンジンと共有する受付・永続記録・復旧の追加を必須条件としている。

## 4. AIチャットの役割

AIは現在の設定と編集中の下書きを参照し、設定の説明、追加・修正案の作成、変更の要約を行う。変更案には対象の設定と変更内容を示し、利用者が「下書きに取り込む」を押したときに下書きへ反映する。相談や提案の生成だけでは下書きを変更しない。取り込んだ変更はフォームで編集し直せるようにする。

「下書きに取り込む」と「適用」は別の操作とする。AI提案を取り込んだ後も、正式な反映には下書き全体の差分確認と手動適用が必要になる。AIから現行設定へ直接書き込む経路は設けない。取り消し操作と、提案の生成後に対象の下書きが編集された場合の扱いは詳細設計で詰める。

AIの接続には、既存のドキュメントQ&Aと同じインストール済みツールの呼出し方式を使う。現在の対象は Claude Code、Cursor、GitHub Copilot。利用可能なツールの検出、実行・キャンセル・状態表示は既存機構の再利用を検討する。APIキーとモデルを別途登録する接続方式は今回追加しない。

Q&Aの回答生成と、カスタマイズの変更案生成は処理を分ける。後者は下書きの変更として扱い、現行設定への直接書込みを許可しない。AIツールが利用できない場合も、フォームによる編集は利用できる構成を提案する。

## 5. 適用・書き出し前の検証

試行機能の削除後も、適用・配布する設定として成立するかを確認する検証は残す提案とする。修正途中の下書きの保存は許可し、不備がある場合は適用・書き出し前に解消する。

- 必須項目、形式、識別子の重複を確認する。
- 定義した工程・エージェント・成果物の参照が存在するかを確認する。
- 対応するエンジンの検証機構で、工程の依存関係や組み合わせを確認する。
- プラグインの書き出し前に、対象形式で配布できる内容かを確認する。

この検証では、ステージ、アプリケーションコード、テスト、利用者が定義したチェックコマンドを実行しない。自然文のルールに従った成果物が実際に生成されることや、AIの出力品質を保証するものではない。

一時コピーで組込み処理を実行する `aidlc-plugin-test.ts` も、この検証には含めない。定義データの読取り・解析・構造検証と、配布ファイルの生成を対象とする。

エンジンが検証していない項目を成功扱いしない。例えば、現行のプラグイン依存バージョン解決を、検査済みであるかのように表示しない。

## 6. 今回取り除く機能

- 「試す」ボタンと試行用の画面。
- 試行用ワークスペースや実行環境の作成。
- 実際のワークフローから試行入力をコピーする処理。
- 新設定による単独ステージ実行、コード生成、テスト実行。
- 試行結果の履歴と、旧設定・新設定の実行結果の比較。

第5節の設定検証と、第3節の設定ファイルの差分確認は残す。品質チェックを設定する機能は残すが、そのチェックをカスタマイズ画面から試しに実行する機能は含めない。

## 7. 実装調査で分かった制約

- 共通ルールの本文は各ステージで再読込される。開始時にすべての設定内容が固定されるわけではない。進行中に `memory/` を直接上書きすると、今後だけに反映する要件を満たせない。
- プラグインの既存ステージへの追加は、現行2.8.2では追加方式に限られる。上書き・削除を同じ配布方法で実現できると説明してはいけない。
- `contributes.memory` によるルール配布は現行2.8.2で未実装。ルールを含む移行には、第2節で決めたGuide用の設定ファイルを使う。標準プラグインへのルール組込みは、現行版では非対応と表示する。
- `when:` の実行時評価など、宣言できても実行されない機能がある。画面には実際に機能する設定と制約を反映する。
- 現行Guideは設定一般の編集APIを持たない。下書き、適用前の検証、手動適用、書込み時の競合検出を追加する必要がある。
- 現行の生成済みハーネスファイルを直接編集する方式には、更新で失われる問題がある。カスタマイズの原本と配布先を分け、更新時の扱いを設計する必要がある。

## 8. 詳細設計への引き継ぎ

主要な機能範囲、下書きの持ち方、AI提案と設定ファイルの取り込み方、狭い画面でのタブ切替は確認済み。[詳細設計案](2026-09-15-customization-page-detailed-design.md)で、以下を具体化した。

- 各カテゴリの入力項目、編集単位、上流が対応する変更範囲、変更の保存先。
- 下書きの保存・復元・取り消しと、AI提案や読み込み内容の確認中に編集が変わった場合の扱い。
- 外部での設定変更やワークフロー開始との競合検出、適用失敗時の復旧方法。
- 配布形式の構成、項目の識別、参照先とバージョン互換性の確認、上流更新時のカスタマイズの保持。
- 狭い画面でのカテゴリ選択、差分の表示、タブへのフォーカス移動とスクロール位置の保持。

技術上の制約により、確認済みの機能範囲や操作を変更する必要が出た場合は、その変更点と選択肢を利用者に相談する。

2026-09-15、設定の生成・更新と適用時の競合防止・復旧をエンジン側の共通機能にする案を利用者が選択した。この方針を詳細設計へ反映した。既存の2.8.2にその機能が備わっていることを意味せず、対応するエンジンの開発と導入を実装範囲に含める。
