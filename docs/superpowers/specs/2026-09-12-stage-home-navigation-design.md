# ステージ一覧ホームと共通ナビゲーションの設計

日付: 2026-09-12
状態: 確定した方針を実装し、自動検証と共有 UI の画面確認を完了。
対象: VS Code 拡張のダッシュボード。共有 UI を利用するブラウザー版にも表示変更が及ぶため、既存の閲覧動作を維持する。

## 1. 目的

ホームを「ステージ一覧」として位置づける。進行状況を示す「現在地」はホーム専用の情報から、ステージ関連の画面で共有する折りたたみ領域へ移す。全ダッシュボードページに共通ヘッダーを表示し、ホームへ戻る入口を揃える。

## 2. ユーザーと確認した方針

| 項目 | 確定した内容 |
| --- | --- |
| ホーム | 「現在地」を「ステージ一覧」に変更する |
| 成果物マトリクス | ステージ一覧の下にそのまま残す |
| ヘッダーの表示範囲 | ダッシュボード内の全ページ。別タブのセットアップ・インストール・Workflows 更新画面は対象外 |
| ホームへの入口 | ヘッダーに「ステージ一覧」ボタンを常設し、メニューにも同じ項目を残す |
| 現在地の表示範囲 | ステージ一覧、ステージ詳細、成果物の詳細表示、エージェント詳細 |
| 現在地の折りたたみ時 | 進行中のステージ名と状態を1行で表示する |
| 開閉の初期状態 | 初回は閉じる |
| 開閉状態の保持 | ページ移動と次回起動をまたいで記憶する |
| スクロール | ヘッダーだけを固定する。現在地情報は本文と一緒にスクロールする |
| 全体の残り実作業時間 | ヘッダーから展開後の現在地情報へ移す。ステージ単体の残り時間と分けて表示する |
| ステージ詳細と成果物 | 同じページで、ステージ説明の下に成果物を表示する構成を維持する |
| 詳細内のステージ一覧 | 一覧ダイアログを残す。前後のステージへ移動するボタンも維持する |

「成果物詳細」は現行のステージ詳細内にある成果物表示を指す。この変更で独立した成果物ページや「概要／成果物」タブは追加しない。

## 3. 画面構成

### 共通ヘッダー

全ダッシュボードページの上部に固定する。

- 「ステージ一覧」ホームボタン
- 現在のインテント選択
- 接続状態
- 既存の条件付き表示。共有閲覧時の読取専用表示など
- メニュー。「ステージ一覧」「効果測定」「ドキュメント」「設定」と、設定済みのプロジェクトリンク

全体の残り実作業時間はヘッダーから外す。VS Code 内のテーマは引き続きエディターに追随する。

### ステージ関連ページ

固定ヘッダーの下に本文のスクロール領域を置く。本文の先頭に現在地情報、その下にページ固有の内容を配置する。

| ページ | 本文の順序 |
| --- | --- |
| ステージ一覧ホーム | 現在地情報 → ステージ一覧 → 成果物マトリクス |
| ステージ詳細・成果物表示 | 現在地情報 → 選択中ステージの見出しと操作 → ステージ説明 → 成果物 |
| エージェント詳細 | 現在地情報 → エージェントの見出しと操作 → 説明・担当ステージ・ナレッジ |

効果測定、ドキュメント、使い方ガイド、設定では、ヘッダーの下にそのページの本文を表示する。現在地情報は表示しない。ステージから公式文書へ移動した場合も、文書ページには現在地情報を出さない。

### 現在地情報

閉じた状態の例は「進行中：code-generation · 実行中」。展開操作を備えた1行の見出しとする。狭い幅ではステージ名を省略表示しても、状態と展開操作は見えるようにし、完全なステージ名を支援技術から読めるようにする。

展開後は既存情報を引き継ぎ、時間の対象を明示する。

- フェーズ、現在のステージ、スコープ、Depth、ゲート、完了数
- 現在のステージの経過時間
- 現在のステージの残り時間
- ワークフロー全体の残り実作業時間

状態を表す文言・表示は既存のステージ状態に従う。「承認待ち」なども実データから表示する。推定値の注記と取得できない値の扱いは既存の判定を引き継ぐ。

現在地は、表示対象として選んだインテントの現在ステージを示す。過去・未来のステージやエージェントを閲覧しても、閲覧対象に合わせて現在地を変更しない。ワークフローが終了している場合や現在ステージがない場合は、進行中であると誤解させない表示にする。

## 4. ナビゲーション

| 操作 | 結果 |
| --- | --- |
| ヘッダーの「ステージ一覧」 | ホームへ移動する |
| メニューの「ステージ一覧」 | 同じホームへ移動する |
| ホームのステージを選択 | そのステージ詳細へ移動する |
| 成果物マトリクスのセルを選択 | そのステージとユニットの成果物を詳細内に表示する |
| 詳細内の一覧ボタン | ステージ一覧ダイアログを開く |
| ダイアログ内のステージを選択 | ホームを経由せず、選択したステージ詳細へ移動する |
| 詳細内の前後ボタン | 前後のステージ詳細へ移動する |
| 担当エージェントを選択 | エージェント詳細へ移動する |
| エージェント詳細の戻る矢印 | 元のステージ詳細へ戻る |

既存の閉じる操作は維持し、ホームへ戻る場合の行き先・表記を「ステージ一覧」に揃える。ダイアログが開いている場合、最初の Escape はダイアログを閉じる。ヘッダー、現在地の展開操作、本文の順序がキーボード操作でも分かるようにする。

## 5. 実装時の補完方針

以下は確認済みの設計を成立させるための実装方針とする。

### 開閉状態の保存

- 開閉状態はページ固有コンポーネントではなく、ダッシュボード共通の表示状態に保持する。
- VS Code ではワークスペースに紐づく表示設定として `ExtensionContext.workspaceState` に真偽値を保存する。新しい Webview を開いても復元できるようにする。
- 保存するのは開閉状態だけ。ステージ名、時間、インテントの内容は保存値から復元せず、既存のデータ取得から表示する。
- 保存値がない・不正な場合は閉じた状態にする。復元完了前にユーザーが操作した場合は、新しい操作を古い保存値で上書きしない。
- インテントを切り替えても開閉状態は引き継ぐ。表示内容は選択先のインテントへ更新する。
- ブラウザー版は同じ画面構造を使い、少なくともページ移動中の開閉状態を維持する。VS Code ホストがない場合も表示や操作が失敗しないようにする。

### 未作成・未選択・エラー時

現在の `NowStrip` は進行情報に加え、開始フォームや読み込み状態も扱っている。正常な進行情報と、利用開始・復旧に必要な案内を分ける。

- インテント未作成時の開始フォームはホームに常時表示し、折りたたみの中へ隠さない。
- インテント未選択時の選択案内、読み込み失敗時の再試行も、開閉操作なしで利用できるようにする。
- `no-active-intent` と `state-missing` の既存の区別を維持する。状態ファイルが見つからない既存インテントで新規開始フォームを出さない。
- 情報の一部だけ取得できない場合は、取得できた内容と必要な注記を維持する。古い時間を別インテントの値として表示しない。

### レイアウト

ヘッダーの高さを固定値で仮定せず、本文は実際のヘッダー高の下に配置する。ページ固有のパネルが現在地情報に重ならないよう、全ページのスクロール領域と本文の起点を揃える。

現在地情報を展開してもヘッダーは固定したままにする。文書内リンクや見出しへのフォーカス移動時に、移動先がヘッダーへ隠れないことを確認する。

## 7. 受け入れ条件

1. 拡張を開くとステージ一覧ホームへ到達でき、一覧の下に成果物マトリクスがある。未設定時の既存セットアップ導線も維持される。
2. 全ダッシュボードページでヘッダーが見え、常設ボタンとメニューの両方からホームへ戻れる。
3. 現在地情報は指定したステージ関連画面だけに表示され、過去・未来のステージを開いても現在ステージと混同しない。
4. 初回は閉じており、閉じた状態でステージ名と状態を1行表示する。ページ移動と VS Code の次回起動後も開閉状態を復元する。
5. 現在地情報を展開するとステージ単体と全体の残り時間を区別して読める。ヘッダーに全体の残り時間が重複して表示されない。
6. ヘッダーだけが固定され、現在地情報と本文は一緒にスクロールする。狭い幅・ヘッダー折り返し・長い文書でも内容が隠れない。
7. ステージ詳細の説明・成果物の縦並び、ユニット切替、ファイル切替、質問への回答入力を維持する。
8. 詳細内の一覧ダイアログと前後移動が機能する。ダイアログ内からの移動、Escape、フォーカスの復帰を維持する。
9. インテント未作成・未選択・読み込み失敗時の案内や操作が折りたたみに隠れない。インテント切替時に古い情報が残らない。
10. ブラウザー版・共有閲覧でも共通 UI が壊れず、読取専用の動作を維持する。

既存の `app.test.tsx`、`header.test.tsx`、`reducer.test.ts` でページ構成と遷移を確認する。`detail-panel.test.tsx`、`agents.test.tsx` は成果物・一覧ダイアログ・戻る動作、`preflight-wizard.test.tsx`、`intents.test.tsx` は未作成・未選択の回帰確認に使う。

時間表示は `timings.test.tsx`、`select-timing.test.ts` の判定と更新タイミングを維持する。開閉やページ移動でポーリングを追加しない。永続化と復元はホスト側と UI 側の両方で検証する。固定位置・重なり・スクロールは DOM テストに加え、ビルドした共有 UI のブラウザー表示で確認する。VS Code 実機での表示確認は別途必要。

## 8. 実装の進め方

1. 共通レイアウトとホームの名称・入口を変更する。
2. 現在地情報の表示条件・折りたたみ・時間表示の移動を実装する。
3. 開閉状態の保存と復元を追加する。
4. 既存テストを更新し、ページ遷移・保存復元・空状態・スクロールを検証する。実装後に `bun run check` を実行する。

## 9. 実装・検証記録

- 共通ヘッダーと本文スクロール領域を分け、現在地情報をステージ関連ページで共有した。
- 開閉状態を VS Code のワークスペース設定に保存し、初回・再起動・遅延した復元通知・保存失敗をテストした。
- インテント選択は共通ヘッダーに統一し、未選択時にダイアログが二重表示される問題を修正した。
- ビルドした共有 UI を通常幅と320px幅で確認した。ヘッダー固定、本文と現在地のスクロール、詳細の一覧ダイアログ、エージェント詳細、設定・文書の表示範囲を確認した。長い注記は折り返し、狭い幅での横はみ出しを解消した。
- `bun run build:extension` が成功した。VS Codeへのインストール・実機操作・リリースは実施していない。
- `VITEST_MAX_WORKERS=2` で `bun run check` が成功した。lint、整形、型検査、文書索引、全テスト、カバレッジ条件、監査シャード検査、依存監査を通過。脆弱性の検出は0件。並列数の制限は検証プロセスだけに適用し、テスト設定は変更していない。
- 制限なしの全体実行では、既存のサーバー起動待ちとファイル検索テストで各1件のタイムアウトが別々の実行で発生した。サーバー起動テストは単独実行で通過し、並列数を制限した全体実行では両方とも通過した。
