## [0.7.2] - 2026-06-14

Documentation re-architecture, framing pass. Reframes the project from "one core, three harnesses" to "one core, many harnesses" — the harness set is an open, growable family (today Claude Code, Kiro CLI, Codex CLI), not a hardcoded three — across the README, the repo `AGENTS.md`, the three guide front doors, and the architecture/porting reference. The Kiro and Codex shipped onboarding docs (`dist/<harness>/AGENTS.md`) change: their identity is now anchored to the shared core rather than to Claude, and the Codex `AGENTS.md` no longer leaks "Claude Code runs your shell non-interactively" in its bun bullet. No behavior change to any distribution. Maintainers and Kiro/Codex users should regenerate (`bun scripts/package.ts`) and re-copy `dist/<harness>/`.

* **README per-harness badges.** The single combined `harnesses-Claude · Kiro · Codex` badge is replaced by one badge per harness (Claude Code · Kiro CLI · Codex CLI), so adding a harness appends one line. The version badge is unchanged.
* **Codex `AGENTS.md` bun bullet corrected.** It inherited Claude Code's PATH prose ("Claude Code runs your shell non-interactively"); it now describes the non-interactive shells the harness spawns in harness-neutral terms. Kiro `AGENTS.md` no longer says "two harnesses" and anchors its tools to `core/tools/` rather than "the Claude Code harness".
* **Anti-rot guard.** `t55` gains a check (test 8) that fails CI if closed-count harness framing ("three harnesses", "generated three ways", "add a fourth", …) re-enters the authored docs, outside a carve-out for `CHANGELOG.md` and the directory-name "three senses of harness" note.
