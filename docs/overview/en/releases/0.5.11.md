## [0.5.11] - 2026-06-02

Extends the internal `aidlc-orchestrate next` engine to cover every non-happy-path the prose orchestrator handles — jumps, resume, init, scope/config changes, and environment-scope validation — each emitted as a typed directive. The engine still stands beside the prose orchestrator and nothing in the workflow calls it yet, so your `/aidlc` runs are unchanged. `next` remains read-only: it never mutates state, validates the jump direction and the environment scope by composing the existing pure-read tools, and emits `ask` rather than ever calling AskUserQuestion. No upgrade action required.

* `bun .claude/tools/aidlc-orchestrate.ts next` now emits the full directive surface: jump targets (`--stage`/`--phase`) resolve their forward/backward/redo direction and in-scope validity through `aidlc-jump.ts resolve`, so a jump to a stage your scope skips comes back as an `error` with the same wording the jump tool prints; `--resume` over an existing workflow and a freeform request with no workflow yet come back as `ask` (the engine never calls AskUserQuestion); `--init` on an existing workspace returns the verbatim `aidlc-state.md already exists … Use --force to reinitialize.` guard as an `error`, while a clean-workspace `--init` and a scope/config change return a `print` naming the command to run (the engine performs no mutation). An invalid `AWS_AIDLC_DEFAULT_SCOPE` returns an `error` carrying the verbatim `Invalid AWS_AIDLC_DEFAULT_SCOPE "…". Valid scopes: …` message.
