## [0.6.8] - 2026-06-13

Hardens the 0.6.7 recovery paths against the defects found shipping inside them, and changes the workflow-birth contract: explicitly naming a scope on a fresh project now starts the workflow instead of erroring. A stale stage re-report can no longer demote a gate-held next stage; Request Changes works even when the optional `gate-start` was skipped; single-stage runs no longer leak into the main workflow's runtime graph or session counts. Re-copy the shipped `.claude/` to pick it up. (Landed on the single-harness `main` line; this branch carries it into the multi-harness core in 0.7.4.)

* `/aidlc --scope <scope>` (and `/aidlc <scope>`) on a fresh project now births the workflow: the engine names the `init --scope <scope>` move and continues, instead of the old circular "Start a workflow with /aidlc <scope>" error. Bare `/aidlc` with no named scope still errors; its guidance now reads "Name a scope to start a workflow (/aidlc --scope <scope>) or scaffold one with /aidlc --init." An explicit `--scope` flag outranks a positional scope, and `--resume` never starts a new workflow.
* `bun .claude/tools/aidlc-orchestrate.ts report --stage <prev>` replayed after the workflow has moved on is now an idempotent `done` — previously it silently demoted an awaiting-approval (`[?]`) or revising (`[R]`) next stage back to in-progress and double-logged `STAGE_STARTED`. The `aidlc-state.ts advance` replay guard covers the same gate-held states.
* `bun .claude/tools/aidlc-state.ts reject <slug>` now accepts an in-progress stage: when `gate-start` was skipped, reject backfills the missing `STAGE_AWAITING_APPROVAL` row before recording the rejection instead of erroring with "requires one of: awaiting-approval".
* Backfilled gate rows (report recovery and reject self-heal) carry `Recovered=true` in the audit trail, so a gate held for a human decision is distinguishable from a gate backfilled at commit; `gate-start` gained an internal `--recovered` flag.
* Single-stage runs (`--single` / the `/aidlc-<stage>` runner skills) no longer contaminate the main workflow: runtime-graph compile and the state tool's audit dedup skip rows tagged `single-stage:`, so graphs, summaries, and replay counts cover only the main workflow.
* Live TUI test harness recognises the Windows npm shims `claude.cmd` / `claude.ps1`, keeping `--setting-sources` isolation intact on Windows runs.
* New live journey `tests/integration/t143-scope-start-birth.test.ts` drives `/aidlc --scope bugfix` end-to-end on a fresh project; docs reconciled (gate-start optional + engine backfill; 0.6.7 summary-reconciliation wording corrected to its real Status=Completed boundary).
