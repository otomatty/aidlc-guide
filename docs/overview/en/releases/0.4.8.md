## [0.4.8] - 2026-05-27

Lands the headline data-plane integration: a `Write|Edit` PostToolUse hook (`aidlc-sensor-fire.ts`) that reads the compile-resolved `sensors_applicable` array off the active stage's `stage-graph.json` node and spawns the dispatcher per matching `matches:` glob. Authoring direction is invisible past compile — the hook reads a list regardless of how the resolver populated it ("the dispatcher does no resolution walks at runtime. Stage entry reads `sensors_applicable` off the node — already looked up, already attached."). After this release ships, customers using AIDLC for actual TS/JS coding work see eslint + tsc integrated automatically into Construction; Inception/Operation markdown writes get `required-sections` + `upstream-coverage` advisory checks. Workflow continues advisory — no gate veto, no blocking; the ralph driver upgrades this to blocking semantics for Construction-phase sensors in a later release.

G1.5 lock-in: the two unscoped framework manifests gain `matches: "**/aidlc-docs/**"` (the leading `**/` consumes any absolute-path prefix Claude Code passes via `tool_input.file_path`; the trailing `/**` matches every artifact under `aidlc-docs/` at any depth, including flat `aidlc-docs/foo.md` paths). Manifest declares its own scope; no hook-side default. The compile snapshots `matches` from each manifest into every importing stage's `sensors_applicable[].matches`, so the hook reads cached glob strings without re-opening manifests at fire time. The `**/aidlc-docs/**` form (vs the draft `**/aidlc-docs/**/*.md`) is load-bearing: the dispatcher uses a home-grown `globToRegex` that translates `**` → `.*` and rejects flat-aidlc-docs paths under the `*.md`-suffixed form, even though `Bun.Glob` (the hook's matcher) accepts both. Two glob engines, one common form.

**Three forward-notes:**

* **`runtime-graph.json` `sensor_firings[]` population deferred.** This release ships the surface that emits `SENSOR_*` audit rows via the dispatcher; `aidlc-runtime.ts:319` continues to hardcode `sensor_firings: []` on every compiled `RuntimeStage`. A later gate ritual is the first consumer that walks `audit.md` since each stage's `started_at` to populate the array.
* **First-fire banner deferred.** A one-line stderr banner on first invocation against a workspace pointing users at `docs/guide/<NN>-learning-loop.md` is envisioned. The doc ships later; banner with no link is dead weight, so it lands together.
* **`sensor-fire.last` mtime semantics for the doctor.** The hook touches `aidlc-docs/.aidlc-hooks-health/sensor-fire.last` after passing the input + recursion + audit-existence + state + test-run-mode guards but BEFORE the active-stage and graph-read guards. This means "fresh heartbeat + zero `SENSOR_FIRED` rows" can mean either (a) healthy hook firing on a stage with empty `sensors_applicable` like `workspace-scaffold`, or (b) hook crash mid-dispatch. The doctor must distinguish by reading `Current Stage` from state, looking up the stage's `sensors_applicable` length, and only flagging when (`length > 0` AND `gap > 24h` AND intervening Write/Edit audit rows exist). The runtime-compile equivalence "post-heartbeat ≡ reached dispatch" does NOT carry to this hook because Steps 9-10 add additional post-heartbeat early-exits.

* `aidlc-claude-code/.claude/hooks/aidlc-sensor-fire.ts` (new) — PostToolUse Write|Edit hook. Twelve-step flow: `resolveProjectDirFromHook` → TTY guard → stdin parse → file_path extract → `.aidlc-sensors/` recursion guard (dual-separator) → audit-existence guard → state-existence + Test Run Mode skip (touches `sensor-fire.skipped` per G2) → heartbeat → active-stage lookup via `getField(state, "Current Stage")` → `loadGraph().find(s => s.slug === currentStage)` typed-wrapper read → per-entry `Bun.Glob` filter + `spawnSync("bun", [...aidlc-sensor.ts, fire, <id>, --stage, <slug>, --output-path, <path>], {timeout: 90_000})` → `process.exit(0)` advisory always. Hook-level failures (timeout SIGTERM/ETIMEDOUT, true spawn failure, non-zero dispatcher exit) recorded via `recordHookDrop(...)`; sensor verdicts surface through the dispatcher's audit rows and detail files — hook never propagates exit codes (G5).
