## [0.3.0] - 2026-05-15

Foundation release. v0.3.0 reshapes how stages, scopes, agents, and artifacts are defined so later releases can ship Construction worktrees, three-compartment stages, sensors, the Ralph loop driver, the fitness compiler, and the visual workflow designer without rewriting plumbing. By design no new user-facing workflows — your v0.2.0 workflows run the same way. State file format bumps from v5 to v6 with no field changes; in-flight workflows archive-and-reinit:

    mv aidlc-docs aidlc-docs-v5-archive && /aidlc --init --force --scope <scope>

* **BREAKING for CI and shell automation**: `/aidlc --doctor` now exits non-zero when any check fails (previously always exited 0). Any CI job or `set -e` shell script that invoked doctor and continued on will now abort. Restore the old behaviour with `|| true`
* New `bun .claude/tools/aidlc-graph.ts` lets you inspect the stage dependency graph from the command line — see which stages produce or consume an artifact, list every artifact, view a scope's stage path, validate a scope, find cycles. The visual workflow designer shipping in v0.11.0 will read from `aidlc-graph.ts export`
* `/aidlc "<freeform description>"` now infers your scope from natural language — `/aidlc "debug the auth flow"` picks `bugfix`, longer descriptions fall back to `feature` unless a clear keyword matches. Word boundaries prevent `debug` from matching the substring `bug`
* Stage files now use YAML frontmatter for their dependency contracts (slug, phase, lead agent, artifacts produced and consumed, required upstream stages). Stage bodies are unchanged — the prose your orchestrator reads is the same. Adding or modifying a stage now means editing one place: the YAML at the top of its `.md` file. The format is documented in `docs/reference/13-stage-definition.md`
* Adding a custom scope no longer requires editing TypeScript. Edit `.claude/tools/data/scope-mapping.json`, run `bun .claude/tools/aidlc-utility.ts scope-table`, commit
* Adding a custom agent no longer requires editing TypeScript. Drop a `.md` file with the right frontmatter into `.claude/agents/`
* Agent files now reference stages by slug (`intent-capture`, `code-generation`) rather than numeric ID (`1.1`, `3.5`). Slugs are the canonical stage identifier; numeric display orders stay in `stage-graph.json` for graph machinery. Contributors writing custom agent files should use slugs
* `/aidlc --help` output is now generated from your live scope configuration, so per-scope stage counts always match what the orchestrator will actually run. Previously the help text had hardcoded counts (`bugfix ~8`, `mvp ~25`, etc.) that drifted as scopes evolved
* New stability-policy chapter at `docs/reference/15-stability-policy.md` codifies pre-1.0 semantics, the archive-and-reinit pattern for state-schema bumps, and the count-pin pattern that keeps numbers in docs from drifting away from the code
* `/aidlc --doctor` reports a missing `aidlc-docs/` directory as a failure now (was passing silently); also gains graph-level health checks (cycle detection, orphan stage files, scope validation, keyword-overlap detection)
* `/aidlc --init` on an existing workspace exits with a clear error instead of hanging or asking clarifying questions in non-interactive mode
* Statusline progress bar now tracks the current phase rather than the full workflow — previously the bar could appear stuck for several stages because it was workflow-scoped while the N/M ratio was phase-scoped
* `tests/run-tests.sh --parallel N` runs test files concurrently within a tier. Integration and workflow tiers drop from ~30 minutes to ~8–10 minutes at `--parallel 4`
* Welcome-message scope table fix: `--scope sec-patch` (a typo in the welcome banner that previously produced an `Unknown scope` error) now correctly maps to `security-patch`, and the missing `workshop` row is included
