## [0.3.8] - 2026-05-18

Adds the `aidlc-worktree` CLI primitive with `create`, `merge`, `discard`, `list`, and `verify` subcommands. The orchestrator dispatches `pipeline-deploy-agent` (which reads team practices to pick branching flags) and then calls `verify` as a deterministic post-dispatch backstop confirming the audit event landed. The three `WORKTREE_*` events follow audit-of-intent semantics — emit fires before `git`, and `doctor` reconciles disk vs audit drift if a kill-9 / OS-crash interrupts the operation between those points. **Constraint:** `aidlc-worktree` must run from the main repo checkout, not from a sibling worktree under `.claude/worktrees/<slug>/`. Solo Bolts as of this patch — the dispatch creates worktrees, but state and audit don't fork yet. The Construction orchestrator's per-Bolt loop in `SKILL.md` now includes Step 0 (worktree create dispatch + verify) and Step 6.5 (worktree merge dispatch + verify); the verify backstop is what makes the agent dispatch deterministic without prose-grepping audit.md.

* `bun .claude/tools/aidlc-worktree.ts create --slug <slug> --base <branch>` adds a per-Bolt worktree at `.aidlc/worktrees/bolt-<slug>` on a new `bolt-<slug>` branch, emits `WORKTREE_CREATED` audit event before invoking git
* `bun .claude/tools/aidlc-worktree.ts merge --slug <slug> --target <branch> --strategy <squash|merge|rebase> [--message <msg>]` performs the merge per the chosen strategy from the current cwd (which must be on `<target>`), emits `WORKTREE_MERGED`, removes the worktree and deletes the branch on success. Conflicts leave the worktree intact and exit non-zero with a JSON conflict envelope including `conflict_files` and a `detail` field the orchestrator's halt-and-ask quotes verbatim. Rebase strategy fetches `<target>`'s remote first and errors when no remote is configured
* `bun .claude/tools/aidlc-worktree.ts discard --slug <slug>` removes the worktree and deletes the branch, emits `WORKTREE_DISCARDED`. Idempotent — succeeds silently when the worktree is already gone
* `bun .claude/tools/aidlc-worktree.ts list` returns the JSON-shaped list of `bolt-*` worktrees (read-only, no audit emission)
* `bun .claude/tools/aidlc-worktree.ts verify --event <WORKTREE_*> --slug <slug> [--max-age-seconds <n>]` greps `aidlc-docs/audit.md` for the most recent matching block, exits 0 within the staleness window (default 60s), exits non-zero with `{verified: false, reason: "absent" | "stale (last seen <ts>)"}` otherwise. The orchestrator's deterministic post-dispatch backstop — same code path for production and tests
* All `aidlc-worktree` failures route through `emitError` with `[slug=<slug>]` prepended to the error message so the `ERROR_LOGGED` row carries the affected Bolt slug for `doctor` correlation
* Sibling-worktree rejection: running `aidlc-worktree` from inside a non-main worktree errors pre-audit with `aidlc-worktree must run from the main repo checkout, not from a sibling worktree at <cwd>`. Teams dogfooding the framework from `.claude/worktrees/<dev-slug>/` should `cd` to the main checkout before running `/aidlc`
* `pipeline-deploy-agent` now loads `.claude/practices/` between agent-specific KB and team-shared knowledge in its Knowledge Loading order. New `aidlc-knowledge/shared/practices-reading.md` documents the empty-template detection, semantic-topic matching, and `team.md → org.md → hardcoded defaults` fallback chain other agents will adopt later
* `aidlc-knowledge/pipeline-deploy-agent/branching-strategies.md` rewritten: each of the five strategies now has an Execution-runbook + Failure-modes sub-section with the explicit `bun .claude/tools/aidlc-worktree.ts create ...` incantation; new top-level Response-contract section documents the JSON envelope the agent returns to the orchestrator
* `audit-format.md:122-124` and `docs/reference/12-state-machine.md:278-280` Emitter cells for `WORKTREE_CREATED`, `WORKTREE_MERGED`, `WORKTREE_DISCARDED` now point at `aidlc-claude-code/.claude/tools/aidlc-worktree.ts`. New paragraph in `docs/reference/12-state-machine.md` § Audit-first atomicity documents the audit-of-intent exception: `WORKTREE_*` events record the orchestration intent, not the on-disk outcome
