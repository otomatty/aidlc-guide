## [0.7.1] - 2026-06-13

Hardening pass over the one-core-three-harnesses build. Fixes a harness-neutrality bug that broke two core methodology paths on the Kiro and Codex distributions, closes a drift-guard blind spot, and corrects a generated install doc. No change to the Claude distribution's behavior. Maintainers and Kiro/Codex users should regenerate (`bun scripts/package.ts`) and re-copy `dist/<harness>/`.

* **Kiro/Codex: rule-directory paths now resolve correctly.** The tools hardcoded a `rules/` path segment, but Kiro ships rule layers at `.kiro/steering/` and Codex at `.codex/aidlc-rules/`. On those harnesses the Inception practices-discovery promotion gate failed closed ("aidlc-team.md not found"), §13 learnings were written to an unread directory, and the doctor's rule-drift check saw zero rules. A new `rulesSubdir()` seam (mirroring `harnessDir()`) resolves the right directory per harness; the Claude distribution is unaffected.
* **`.mcp.json` and `.gitignore` are now drift-guarded.** Both Claude project-root install files shipped outside `package.ts --check`; a hand-edit or stale `.mcp.json` passed CI green. They are now authored under `harness/claude/` and regenerated + checked like every other file.
* **Codex `AGENTS.md` install doc corrected.** It described a Claude config (Opus/Bedrock anthropic model IDs, a Read/Edit/… tool allowlist, a `.mcp.json`, and `.codex/skills/`) that the Codex distribution does not ship. It now documents the real `config.toml` (Bedrock `openai.gpt-5.5`/`gpt-5.4`), `[mcp_servers]` tables, the Starlark `default.rules` allowlist, and `.agents/skills/`.
* `t150` test 6 now pins the real shipped `trust-seed.toml` hashes via the exported `trustEntries()` (it previously hashed a non-shipped spike path); the statusline hook uses the shared project-dir seam instead of a `.claude`-hardcoded copy; contributor docs (`05-agent-system.md`, `10-knowledge-system.md`) and the Kiro guide corrected to the `core/` authoring model.
