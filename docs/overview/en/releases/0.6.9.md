## [0.6.9] - 2026-06-13

Ports the multi-harness runtime seam onto the framework core ahead of the one-core-three-harnesses restructure: the deterministic tools and hooks now resolve their harness directory (`.claude` / `.kiro` / `.codex`) through a single `harnessDir()` seam instead of hardcoding `.claude/`, and `/aidlc --doctor` grows per-harness wiring checks (Kiro agent config, Codex `config.toml`/`hooks.json`/version pin) plus a multi-harness-coexistence advisory. No layout change and no behavior change for Claude Code — in a `.claude/` tree every path still resolves to `.claude/`, so the regenerated distribution is byte-identical. Re-copy the shipped `.claude/` to pick it up.

* `/aidlc --doctor` now reports harness-specific wiring: on a Kiro tree it checks `agents/aidlc.json` + `settings/cli.json`; on a Codex tree it checks `config.toml`, `hooks.json`, `rules/default.rules`, and a `codex >= 0.139.0` version pin; on any tree it flags a detected multi-harness install (advisory, never blocking).
* Stage prose and the orchestrator skill present approval gates as "structured questions" (the harness binds the rendering — `question-rendering.md` ships beside the Claude orchestrator) rather than naming `AskUserQuestion` directly, so the same core text is correct under every harness.
* No new commands or flags. Existing `/aidlc` behavior under Claude Code is unchanged.
