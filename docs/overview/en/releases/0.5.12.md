## [0.5.12] - 2026-06-03

Cuts the `/aidlc` orchestrator over to the deterministic orchestration engine (`aidlc-orchestrate.ts`), which was built and proven in the prior releases but until now stood beside the prose orchestrator unused. The orchestrator's `SKILL.md` drops from 895 lines of inter-stage dispatch prose to a short forwarding loop — get a directive from the engine, do that one move, report the outcome, repeat — bringing the file under the Agent Skills 500-line limit. Behaviour is unchanged: scope resolution, stage walking, gates, jumps, resume, and workflow completion all now flow through the engine that a differential corpus already proved reproduces the prose's directive stream across all 9 scopes. The change is reversible by a single revert. This release also corrects four latent no-state engine defects in the workflow-birth paths the cutover leans on (a bare known-scope positional, a no-state skip-stage jump, an invalid `--scope` over an active workflow, and a no-state coverage hole in the differential corpus). No upgrade action required.

* `/aidlc` now consults the deterministic engine for every between-stage decision instead of running dispatch prose — no observable change to starting, resuming, jumping, or completing a workflow, but the routing is now tool-owned and reversible.
* `bun .claude/tools/aidlc-orchestrate.ts next bugfix` (a bare known-scope name with no workflow yet) is recognised as the scope rather than read as freeform intent — it returns the same "no workflow state" error as `next --scope bugfix`, instead of a scope-confirmation defaulting to `feature`.
* `bun .claude/tools/aidlc-orchestrate.ts next --scope <scope> --stage <stage>` with no workflow yet now errors `Stage "<stage>" is skipped for scope "<scope>". Choose a different stage or change scope.` when the stage is out of scope, matching the with-workflow behaviour (previously it emitted a run-stage directive).
* `bun .claude/tools/aidlc-orchestrate.ts next --scope <invalid>` now errors `Unknown scope "<invalid>". Valid scopes: …` even when an active workflow supplies a valid scope (previously the invalid flag was silently ignored and the current stage ran).
