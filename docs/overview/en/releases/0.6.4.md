## [0.6.4] - 2026-06-09

Closes a build-time gap for harness engineers and fork authors: `bun .claude/tools/aidlc-graph.ts compile` now rejects a stage whose `lead_agent` or any `support_agents` entry names an agent with no matching `.claude/agents/*.md` file. Previously the compile skipped this cross-check, so a stage pointed at a misspelled or missing agent compiled clean and only surfaced at run time as a "subagent not registered" `Task` error during the stage it leads (e.g. Code Generation). The check is the same agent-registration rule `/aidlc --doctor` already runs against your installed graph — now wired one layer earlier, at the build step that regenerates `stage-graph.json`. The reserved `orchestrator` pseudo-agent (the conductor itself, named as `lead_agent` on the bootstrap initialization stages) is exempt by design — it has no agent file. This is a build-step guard only; the shipped graph is unchanged and `/aidlc` runtime behaviour is identical, so there is no upgrade action for users who only run workflows. Re-copy the shipped `.claude/` to pick it up.

* `dist/claude/.claude/tools/aidlc-graph.ts` — `compileStageGraph` now passes `ctx.agents` (the slugs from `loadAgents()`) into `validateStageFrontmatter`, activating the agent-registration cross-check (Rule 9) at compile. A stage referencing an unknown agent fails the compile with `lead_agent "<name>" has no matching .claude/agents/*.md`, naming the offending stage file.
* `dist/claude/.claude/tools/aidlc-stage-schema.ts` — adds the exported `RESERVED_AGENT_SLUG` (`"orchestrator"`) constant and exempts it from Rule 9 for both `lead_agent` and `support_agents`, so the bootstrap initialization stages stay valid.
