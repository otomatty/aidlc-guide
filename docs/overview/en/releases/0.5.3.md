## [0.5.3] - 2026-06-01

MCP servers are now declared once in a shipped registry and inherited by every agent. A new `aidlc-claude-code/.mcp.json` declares five public MCP servers — `context7` (HTTP, third-party; auth via `${CONTEXT7_API_KEY}` env passthrough) and four AWS servers run through `uvx` (`aws-mcp`, `aws-pricing`, `aws-iac`, `aws-serverless`) that authenticate with your standard AWS credential chain. Declared servers are provisioned to the Claude Code session, and subagents inherit all session MCP tools by default — so there is no per-agent grant step: the developer and aws-platform agents reach the servers they need by inheritance. (An agent that must be *prevented* from a server is narrowed via its `tools:` allowlist with fully-qualified `mcp__<server>__<tool>` ids; that is a separate concern this release does not exercise.) A new guard test pins the registry shape and the inheritance invariant — no agent carries a bare `mcp__<server>` grant token, which would be a no-op. No committed credentials: the registry carries only env-var placeholders. **Prerequisite:** the four AWS-backed servers require an AWS account with IAM credentials available to your shell; `context7` requires `CONTEXT7_API_KEY` in your environment. Servers you have no credentials for are simply unavailable — they do not block the framework. No upgrade action required.

* `aidlc-claude-code/.mcp.json` (new) — the shared MCP server registry. Declares `context7` (HTTP endpoint, `${CONTEXT7_API_KEY}` header) and `aws-mcp` / `aws-pricing` / `aws-iac` / `aws-serverless` (each launched via `uvx`). Credentials flow through environment passthrough only; no keys are committed.
* `tests/unit/t110-mcp-server-grants.sh` (new, 32 assertions) — guard test pinning the registry contract and the inheritance access model: `.mcp.json` is valid JSON and declares exactly the five expected servers as the sole top-level key (with `threat-composer-ai` deferred); each server's config shape is usable (context7 `type: http` + url + key header; each aws-* `command: uvx` + the expected `<pkg>@latest` first arg, aws-mcp carrying `AWS_REGION=us-east-1`); no committed secrets (credential-position values are `${VAR}` placeholders, no literal-key shapes); and no agent carries a bare `mcp__<server>` grant token while every fully-qualified `mcp__<server>__<tool>` entry names a declared server (access is by inheritance, not per-agent grants). Deterministic, bun-only (no `jq`).
* `aidlc-claude-code/.claude/CLAUDE.md` — documents the MCP registry, the inheritance model, and the AWS-account / `CONTEXT7_API_KEY` prerequisite.
* User-facing docs: a new "MCP Servers (optional)" setup section in `docs/guide/01-getting-started.md`, an "MCP servers are shared, not per-agent" note in `docs/guide/05-agents.md`, a full "MCP Servers" architecture section (registry schema, provisioning→inheritance, why there is no per-agent grant) in `docs/reference/14-claude-features.md`, an inheritance pointer in `docs/harness-engineering/03-adding-an-agent.md`, and an "MCP server" glossary entry.
