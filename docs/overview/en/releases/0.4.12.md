## [0.4.12] - 2026-05-30

Application Design now prompts an explicit architecture trade-off block whenever a design choice has more than one viable approach. The `application-design` stage's Step 5 (decisions.md guidance) gains an "Architecture options" sub-section: present Option A / Option B with pros, cons, and reversibility, give a recommendation tied to NFRs, let the team choose at the gate, then record the chosen option plus an **Alternatives Rejected** section in the ADR. Single-option choices state why and skip the block. No behavioural change to tooling — this is additive stage-authoring guidance that aligns the stage body with the inception phase rule's ADR requirement (Context, Decision, Consequences, Alternatives Rejected). No upgrade action required.

* `aidlc-claude-code/.claude/skills/aidlc/stages/inception/application-design.md` — added the "Architecture options (when >1 viable approach)" sub-section to Step 5, using the field name **Alternatives Rejected** to match `aidlc-phase-inception.md`.
* `aidlc-claude-code/.claude/tools/aidlc-version.ts` — bumped 0.4.11 → 0.4.12.
