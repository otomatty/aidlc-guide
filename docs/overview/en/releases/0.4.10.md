## [0.4.10] - 2026-05-29

The headline learning gate: a new `aidlc-learnings.ts` tool implementing the §13 Learnings Ritual as tool-as-actor (replaces the prior LLM-as-actor §13 prose; the "steering loop" is renamed to the "learning loop" throughout). Between a gated stage's completion verification and its approval, the orchestrator runs `aidlc-learnings.ts surface --slug <slug>`; the tool reads the stage's `memory.md` (via the new `parseMemoryEntries` helper), surfaces each non-blank entry under Interpretations / Deviations / Tradeoffs verbatim as a candidate plus a read-only "parked open questions" list, and emits a structured JSON candidate set. The orchestrator renders AskUserQuestion; the user ticks candidates to keep and may type free-text additions, picking which of the four headings each belongs under — **the heading pick is the user's only classification, and the destination is derived from it, not picked.** Before any write, the orchestrator runs a single-line section-level admission conflict check against `aidlc-org.md`'s matching section; a contradicting entry is rejected with the org sentence quoted inline and the user revises, skips, or escalates (no override path). Conflict-clear selections are persisted via `aidlc-learnings.ts persist`, which writes dated rolling entries to the two-surface `.claude/rules/aidlc-project-learnings.md` (default) and `aidlc-team-learnings.md` files — a separate surface from the practices files, never `## Corrections` and never the practices-discovery topical sections. A one-click "promote scope" affordance widens a candidate from project to team; there is no org-learnings file and no widen-to-org path. All writes go through one `withAuditLock` with a decide-inside-lock transaction and content-presence idempotency (a `<!-- cid:<slug>:<id> -->` marker per written line) so a crashed run recovers without double-appending. Audit count grows 61 → **63**: `RULE_LEARNED` and `SENSOR_PROPOSED`.

When a learning is a sensor-binding addition, the same locked transaction does the pull-authoring two-write install: it scaffolds a project-tier `<project>/.claude/sensors/aidlc-<id>.md` manifest (with a `matches:` capability glob) AND atomically appends the new id to the originating stage's `sensors:` frontmatter list. The sensor binds and fires from the next workflow's compile — the never-edits-stage-files rule is lifted for sensor-binding frontmatter edits only (the immutable `## Steps` / `## Sensors` / `## Learn` body is untouched; stage files are now framework-and-loop-edited, documented in CLAUDE.md). `SENSOR_PROPOSED` records the manifest path, the bound stage(s) (`Destinations`), and `source: orchestrator | user_addition`.

This also closes the `runtime-graph.json sensor_firings[]` work carried since the runtime-graph compile shipped: `aidlc-runtime.ts compile()` now walks `SENSOR_FIRED` / `SENSOR_PASSED` / `SENSOR_FAILED` / `SENSOR_BUDGET_OVERRIDE` rows in each stage's window, pairs by 8-hex `fire_id` correlator (positional pairing breaks under the 4-sensors-per-Write fan-out), and populates `sensor_firings[]` on every `RuntimeStage` and `BoltInstance`. Orphan FIRED rows are `result: "incomplete"` — immediately in a closed stage window, or after a deterministic 60s cutoff (computed from the max audit timestamp, no wall-clock) in an open window. The same compile pass wires `learnings_captured.{from_orchestrator, from_user_addition}` from the new audit rows (the previously reserved slot). `SensorFiring` gains `fire_id` and widens `result` to `passed | failed | budget-override | incomplete`.

Skipped in TEST_RUN_MODE: the gate ritual surfaces no candidates and persists nothing.

**Deferred / named (not built here):** `RuntimeStage.consumes[]` (a dispatcher perf win) is deferred; the SIGKILL/uncaught-SIGTERM lock-leak in `withAuditLock` is deferred to the mtime-lock-reap (the lock-acquire-failure stderr now names the lock path and manual remedy); a migration helper for v0.4.x forks that customised sensor manifests with `applies_to:` is deferred to a dedicated fork-upgrade task; edit-inferred learning candidates from artefact diffs (§13 "Source 3") are deferred.
