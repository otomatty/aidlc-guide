## [0.5.16] - 2026-06-04

Relocates the framework's shared methodology spine into a new `.claude/aidlc-common/` directory, a peer of `.claude/skills/`, and brings the `aidlc` skill into conformance with the published Agent Skills specification. The 32 stage bodies move from `.claude/skills/aidlc/stages/<phase>/` to `.claude/aidlc-common/stages/<phase>/`, and the four protocol files (`stage-protocol.md`, `stage-protocol-governance.md`, `stage-protocol-recovery.md`, `stage-definition.md`) move from `.claude/skills/aidlc/` to `.claude/aidlc-common/protocols/`; they join the conductor persona already homed at `.claude/aidlc-common/conductor.md`. The relocation is transparent to the engine — `stage-graph.json` regenerates byte-identically and every tool that resolves a stage file (the orchestration engine, the graph compiler, the learnings gate, the doctor) now reads from the new location. Customisers who edit stage files should look under `.claude/aidlc-common/stages/` rather than `.claude/skills/aidlc/stages/`. Upgrade action: when you take this version, your on-disk stage and protocol files move to `.claude/aidlc-common/`; re-apply any local stage customisations there.

* Stage files now live at `.claude/aidlc-common/stages/<phase>/<slug>.md` and the stage-protocol / stage-definition reference files at `.claude/aidlc-common/protocols/`. `/aidlc --doctor` resolves them from the new location; customising a stage means editing it there.
* The `aidlc` skill validates clean against the Agent Skills specification, and a conformance guard (`tests/unit/t123-skills-spec-conformance.sh`) now checks every shipped skill dir on each test run (`name` matches its directory, `description` present, `SKILL.md` body within the 500-line limit).
