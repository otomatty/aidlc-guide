## [2.5.40] - 2026-08-05

Adds per-stage and per-workflow token-usage and cost tracking plus an opt-in metrics emission seam. On Claude Code, a new fold hook registered for both PreToolUse and PostToolUse records transcript usage in a durable, gitignored `.aidlc-sessions/usage-ledger.json`; the statusline gains a current-workflow/current-session `↑in ↓out $cost` segment, and `STAGE_COMPLETED` / `WORKFLOW_COMPLETED` audit events gain correctly scoped token and cost rollups. Everything remains off by default and additive: unknown models record tokens with a null cost, metrics emit only when `AIDLC_METRICS_ENDPOINT` is set, and non-Claude harnesses simply have no producer. **Upgrade:** re-copy your `dist/<harness>/` shell into the project. No action is required to stay silent; opt into metrics with `AIDLC_METRICS_ENDPOINT`, and override rates with `AIDLC_MODEL_RATES` or the installed `tools/data/model-rates.json`.

* New Claude-only `aidlc-fold-usage.ts` registrations run before and after every tool call: PreToolUse seals the completing main-transcript call and flushes completed subagent calls before workflow-engine boundaries, PostToolUse provides the normal holdback fallback, and the Stop hook flushes every remaining main/subagent group at turn-end, including a complete final JSONL record with no trailing newline.
* Ledger updates serialize across processes, use writer-unique atomic temporary files, and retain stage, workflow, and session ownership at the transcript-message boundary so concurrent sessions and lifecycle transitions cannot lose or misattribute usage. A malformed EOF fragment also keeps the possibly related preceding group pending, preventing split-message double counts.
* The statusline reports only the active session, `STAGE_COMPLETED` reports the completed stage, and `WORKFLOW_COMPLETED` reports the full active intent. Unknown-price models remain tokens-only rather than emitting a fabricated `$0`.
* Model normalization enforces provider/model token boundaries and resolves exact generation keys from the effective rate table, including generations added through `AIDLC_MODEL_RATES`.
* Metrics emission is opt-in via `AIDLC_METRICS_ENDPOINT` and uses a detached Bun/TypeScript worker with native `fetch()`, adding no HTTP executable dependency. The endpoint, custom headers from `AIDLC_METRICS_HEADERS`, and metric body travel in a JSON envelope over stdin; endpoint and headers are removed from the child environment and nothing sensitive enters process arguments. Batch audit appends use the same metrics tap as single events.
