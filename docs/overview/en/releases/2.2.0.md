## [2.2.0] - 2026-07-04

Adaptive Workflows (roadmap Goal 3): a composer agent under `/aidlc` that fits the ceremony to the task. Describe the work and the engine routes by keyword inference - a clear match gets a one-line confirm naming the matched scope, rich or unmatched prose gets a compose offer instead of the old silent feature default. The composer reads the task and the workspace scan, proposes the EXECUTE/SKIP stage grid with a per-SKIP rationale, and after your approval authors it as a scope and starts the workflow in the same turn. Point it at a scan report (`/aidlc compose --report sonar.json`) to triage findings into a compact fix-and-ship run, or run `/aidlc compose` mid-workflow to re-shape the pending stages in place. Composed scopes ship with `keywords: []` so a one-off plan never rewires future keyword routing; making a scope inferable is an explicit gate choice. (The roadmap's 2.2.0/2.3.0 assignments swap: adaptive workflows ships now as 2.2.0; reviewer-as-verifier moves to 2.3.0 and carries the Full GA declaration - this cut does NOT declare GA.) **Upgrade:** re-copy your `dist/<harness>/` shell into the project.

* NEW `/aidlc compose "<task>"` (and the `/aidlc-compose` shortcut skill): force the composer even when a stock scope matches. `--new-scope` forces synthesizing a custom scope; `--report <path>` composes from a scan report. The compose verb is deliberately NOT a workspace verb, so Kiro's off-band verb-intercept never captures it.
* Cold-start freeform routing changed: `/aidlc "<description>"` now runs keyword inference. A clear keyword hit asks a one-line confirm naming the MATCHED scope (e.g. bugfix, not feature); no hit or rich prose asks the compose offer. The old static feature-default confirm is gone.
* NEW read-only `detect` utility subcommand (`--json`): prints the workspace scan (project type, languages, frameworks, build system) plus the resolved scopes dir and scope-grid path - how the composer is told where scope data lives per harness.
* NEW `validate-grid --proposal <path> [--strict] [--project-type <t>] [--keywords <csv>]` on `aidlc-graph.ts`: validates an arbitrary EXECUTE/SKIP grid. Lenient mode mirrors `validate-scope` (off-path required producer = advisory); `--strict` (the recompose mode) hard-rejects a starved required input; `--keywords` hard-rejects any granted keyword an existing scope already claims, naming the incumbent (the composer runs this before writing gate-granted keywords). `validate-scope` behavior is unchanged.
* NEW `recompose --skip <slugs> --add <slugs>` utility subcommand: flips PENDING, ahead-of-cursor stages' plan suffixes on the live state file under the audit lock, strict-validated against NEW starvation, derived state fields rebuilt, `RECOMPOSED` audited. Rejects flips of completed/in-progress/skipped stages, behind-cursor stages, and the first EXECUTE stage of Construction (the walking-skeleton gate anchor). The rebuilt Stages-to-Skip row preserves birth's annotated entries verbatim for stages whose skip-membership did not change, so a skip+add round trip leaves the row byte-identical.
* Chat-first in-flight reshape: mid-workflow, plain chat that names skipping/dropping/adding stages of the running workflow ("can we skip market research?") is recognized by the conductor and routed through the same approve/edit/reject gate and the same `recompose` verb - no literal `compose` needed. When the request names specific stages imperatively, the conductor may present the gate directly without dispatching the composer agent (the verb's validation guards both paths identically); open-ended requests ("what can we cut?") still dispatch the composer. Never under autonomous Construction. On Kiro and Codex the literal `/aidlc compose "<request>"` verb remains the documented reliable path.
* Jump, finalize, lookup, and `--status` now honour the live plan: per-stage EXECUTE/SKIP suffix overrides (a recomposed plan) win over the static scope grid in jump target validation, the forward-skip/backward-reset loops, phase targeting, the Next Stage projections, and status counts.
* NEW `RECOMPOSED` audit event (the taxonomy is now 69 events).
* NEW `aidlc-composer-agent` (14 agents now): dispatched by the conductor for compose requests; on Kiro it ships a hand-authored agent config whose sandbox grants the two scope-registry write paths (the conductor's own sandbox still cannot write them).
* Kiro IDE: delegated subagents now get their tools. The IDE resolves a delegate's tool grants from the agent `.md` frontmatter, not from the agent-v1 JSON the Kiro CLI reads, so dispatched agents (the composer first among them) ran toolless there - "terminal tool not available". The kiro-ide packaging now injects `tools: ["read", "write", "shell"]` into the five delegation-target agent files (reviewers included - the stage protocol has them append a `## Review` section to the artifact); the other harnesses are untouched. Note the IDE grant is unscoped, wider than the CLI JSON sandbox. The composer persona also gains an explicit degraded rule: if it cannot run its deterministic steps it returns a structured failure status, never an unvalidated grid.
* Stop hook: a pending in-flight compose proposal (the conductor's `aidlc/.aidlc-compose-pending` marker) lets the turn end at the approve/edit/reject gate; autonomy-guarded and fail-open.
* The scope-grid "regenerated, never hand-edited" rule gains one carve-out: the dispatched composer appends approved composed scopes to the runtime scope registry. Note a maintainer `aidlc-graph.ts compile` still drops a composed grid entry (composed scopes have no per-stage frontmatter tags); the composer is instructed never to run compile.
