## [0.4.11] - 2026-05-29

Closes the management-plane half of the control/data-plane redesign. `/aidlc --doctor` gains two new advisory rows that observe rule/sensor state without changing how rules concatenate at runtime. No new flags — doctor stays single-purpose; both rows render quietly when there's nothing to surface. No new audit event types: this wires the emitter for the reserved `GUARDRAIL_LOADED` event, so the v0.5.0 audit count stays at 63.

* `/aidlc --doctor` now reports **Rule drift**: it surfaces team/project (and team/project-learnings) rule files whose `##` headings overlap a populated heading in `aidlc-org.md`, quoting the org sentence inline so you can review for contradiction. The row is advisory — it never fails the health check or blocks a workflow. The semantic contradiction verdict is the orchestrator's at observation time, not doctor's; doctor surfaces the candidate, you (or the orchestrator) judge it.
* `/aidlc --doctor` now reports **Paired sensor coverage**: `Paired sensor coverage: P/(M-X) guardrails paired (X feedforward-only)`, where the denominator counts guardrails that need a sensor (M-X) and the numerator counts those whose named sensor resolves (P). For each rule carrying `pairing: <sensor-id>`, doctor asserts the named sensor exists in at least one stage's resolved sensor set; `pairing: feedforward-only` rules count separately. This is a file-existence check, not a semantic one — it confirms the binding resolves, not that the sensor fits the rule.
* The doctor paired-coverage row now emits the reserved `GUARDRAIL_LOADED` audit event when it resolves the guardrail set. No new event type; the audit registry count is unchanged.

No action needed on upgrade. If you script against `/aidlc --doctor` exit codes, note both new rows are advisory and never change the exit status.
