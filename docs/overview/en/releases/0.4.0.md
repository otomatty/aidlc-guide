## [0.4.0] - 2026-05-20

Construction worktrees + split-safe state/audit + practices discovery. Construction Bolts now execute in their own git worktree at `.aidlc/worktrees/bolt-<slug>/`, eliminating race conditions on shared state, audit, and working tree across parallel Bolt batches and workshop scenarios. State and audit fork to the worktree on Bolt start and merge back on gate approval, with deterministic conflict resolution.

A new Inception stage `practices-discovery` at slot 2.2 captures team branching strategy, walking-skeleton stance, testing posture, deployment, and code style — affirmed once per project, then read by Construction so worktree dispatch and walking-skeleton sequencing reflect the team's voice rather than scope-hardcoded defaults. State template bumps from v6 to v7 with three real field additions; v6 workspaces archive-and-reinit:

    mv aidlc-docs aidlc-docs-v6-archive && /aidlc --init --force --scope <scope>

* **BREAKING — state template v6 → v7.** Three new fields populated by Construction worktree dispatch and the practices-discovery affirmation gate: `Worktree Path`, `Bolt Refs`, `Practices Affirmed Timestamp`. `/aidlc --doctor` exits non-zero on a v6 state file with archive-and-reinit advice. No migration tooling — see `docs/reference/15-stability-policy.md` for the precedent
* **Construction-phase worktree isolation** — every Bolt runs in its own git worktree at `.aidlc/worktrees/bolt-<slug>/` on branch `bolt-<slug>`. Parallel Bolt batches no longer race on shared state, audit, or working tree. Aborted Bolts' worktrees are preserved by default for inspection; `aidlc-bolt abort --discard` cleans up explicitly. Halt-and-ask AUQs render the worktree path and branch name verbatim
* **New Inception stage `practices-discovery` at slot 2.2** — discovers team branching strategy, walking-skeleton stance, testing posture, deployment patterns, and code style from evidence (brownfield: multi-agent scan of git, configs, code, and reverse-engineering artifacts) or `AskUserQuestion` (greenfield); affirmation gate promotes drafts to `.claude/practices/team.md` and `.claude/rules/aidlc/guardrails/project-guardrails.md`. Inception phase grows from 7 → 8 stages; total 31 → 32
* **`bun .claude/tools/aidlc-worktree.ts`** new subcommands: `create --slug <slug> --base <branch>`, `merge --slug <slug> --target <branch> --strategy <squash|merge|rebase>`, `discard --slug <slug>`, `list`, `verify --event <WORKTREE_*> --slug <slug>`, `info --slug <slug>`. The `info` JSON envelope returns `{slug, path, branch_name, audit_timestamp, merge_held}` — the `merge_held` field powers the multi-failure HOLD-MERGE invariant during halt-and-ask
* **`bun .claude/tools/aidlc-bolt.ts`** new flag-driven branches: `start --worktree --slug <slug>`, `complete --merge --slug <slug>`, `abort --slug <slug> --reason <text> [--discard]`, `hold-merge --slug <slug>`, `release-merge --slug <slug>`, and `dispatch-event --event MERGE_DISPATCH_INVOKED|RETURNED|FALLBACK --slug <slug>`. The `hold-merge`/`release-merge` pair routes the HOLD-MERGE invariant through tooling instead of prose contract; `dispatch-event` wires the three pre-registered `MERGE_DISPATCH_*` events around every pipeline-deploy-agent dispatch
* **`bun .claude/tools/aidlc-state.ts`** new subcommands: `fork --slug <slug>`, `merge --slug <slug>` (per-Bolt state isolation with workflow-level fields untouched + alphabetical-slug tiebreak), `practices-event --type discovered|affirmed|override|empty`, and `practices-promote --team-practices <path> --discovered-rules <path>` (the cross-row write that takes practices-discovery drafts to team harness config)
* **`bun .claude/tools/aidlc-audit.ts`** new subcommands: `audit-fork --slug <slug>`, `audit-merge --slug <slug>`. Per-Bolt audit isolation with SHA-256 prefix-hash sanity check on merge — refuses with `prefix-hash` error if main audit's prefix at the recorded `Fork Boundary` byte offset has been edited or truncated since fork. `AIDLC_AUDIT_LOCK_RETRIES` and `AIDLC_AUDIT_LOCK_RETRY_MS` env-var overrides for the lock budget
* **`/aidlc --doctor`** extends with four new orphan-reconciliation rows that print between the State Version line and the graph-level checks: orphan worktrees (classified as active fork / preserved-by-abort / cleanup-orphan / unmatched), stale `bolt-*` branches (worktree gone but no terminal `WORKTREE_DISCARDED`/`MERGED` audit row), orphan state files (worktree state file with no entry in main's `Bolt Refs`), and orphan audit (three reconciliation surfaces under one label: `AUDIT_FORKED`-without-disk, orphan-delta drift, `PRACTICES_OVERRIDE` Reason discriminator routing)
* **`/aidlc --doctor`** also gains two new advisory rows: practices staleness (90-day threshold against `Practices Affirmed Timestamp`) and `MERGE_DISPATCH` orphan-INVOKED count (pair-matched per slug against terminal `_RETURNED`/`_FALLBACK` rows)
* **Multi-failure halt-and-ask** — when ≥2 Bolts in a parallel batch fail, AUQs render sequentially in slug order; all successful Bolts hold their merge-dispatch via per-Bolt `Merge-Held: true` marker until every failed AUQ resolves. Marker survives session-kill via worktree-state persistence; `aidlc-bolt complete --merge` refuses with `{ok:false, reason:"merge-held", ...}` envelope while held
* **Practices-aware orchestration in SKILL.md** — Construction reads team practices once at start (`extractMarkdownSection` over `team.md → org.md → hardcoded defaults`). Walking-skeleton stance is dynamic from practices; bolt-plan marker conflicts emit `PRACTICES_OVERRIDE` with `Reason: bolt-plan-marker-conflict` (discriminator field on the existing event, not a new event type). Ten agents (architect, aws-platform, compliance, delivery, design, developer, devsecops, operations, product, quality) gained Knowledge Loading entries citing `.claude/practices/`
* **Audit taxonomy 41 → 55 events across 12 → 15 categories.** Seven worktree-lifecycle events (`WORKTREE_CREATED`, `WORKTREE_MERGED`, `WORKTREE_DISCARDED`, `STATE_FORKED`, `STATE_MERGED`, `AUDIT_FORKED`, `AUDIT_MERGED`), four practices events (`PRACTICES_DISCOVERED`, `PRACTICES_AFFIRMED`, `PRACTICES_OVERRIDE`, `PRACTICES_SECTION_EMPTY`), three merge-dispatch events (`MERGE_DISPATCH_INVOKED`, `_RETURNED`, `_FALLBACK`). `tests/unit/t28-audit-event-sync.sh` pins the count
* **Configuration-layers principle** — new section in `docs/reference/01-architecture.md` documents the two-axis routing model (authorship × consumption) for `.claude/` vs `aidlc-docs/`. New `.claude/practices/` namespace with three layers: `org.md` (framework defaults in team voice), `team.md` (this team's affirmed practices, populated by practices-discovery), `project.md` (project-specific overrides). Anchors v0.5.0+ routing decisions
* **New chapter `docs/guide/workshop-mode.md`** — multi-developer manual recipe for the `workshop` scope. Claim semantics ride on `git push` of `bolt-<slug>` to the shared remote (first push wins, late claimants get a non-fast-forward rejection). No new CLI; the manual recipe is the contract until a real workshop dogfood surfaces concrete requirements for an automated `--claim-bolt` utility (deferred)
* **Performance baseline** — `time bun aidlc-worktree.ts create --slug <s> --base main` measured at **520ms median** (range 485–567ms across 6 warm runs; 819ms cold-cache; 30ms bun startup baseline) on a 100MB synthetic fixture (101MB `.git` of `dd if=/dev/urandom` blobs — pathological worst case for `git worktree add` because random data does not compress). Of that, raw `git worktree add` accounts for ~336ms median; the framework adds ~190ms for slug validation, branch existence check, audit emission, and lock acquisition. Slightly above the <500ms target on this adversarial fixture; real repositories with compressible assets will perform better. First baseline of its kind — informative, not a regression. Track in v0.5.0 if customer-facing fixtures push it higher
* **Phase 0 Harness Setup precursor** — practices-discovery is the operational-truth precursor to v0.10.0's Phase 0 Harness Setup, which will own architectural rules via the fitness-contract compiler. Distinct concerns: practices captures the team's voice on how they work; Phase 0 captures the harness engineer's contract on what the project commits to. v0.10.0 plan-time decision resolves the boundary
