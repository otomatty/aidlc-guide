## [0.3.2] - 2026-05-17

Pre-registers 14 audit events (worktree, practices, merge-dispatch) so downstream work can `import` constants without racing on `tests/unit/t28-audit-event-sync.sh`'s pinned count. No emitters ship in this patch — each pre-registered event has a `Reserved` Emitter cell in `audit-format.md` and `docs/reference/12-state-machine.md` that the consumer replaces with the real file path in the same commit it adds the emit call. The audit taxonomy now declares 55 events across 15 categories (was 41 across 12).

* `bun .claude/tools/aidlc-audit.ts append <name>` accepts 14 new event names: 7 worktree-lifecycle (`WORKTREE_CREATED`, `WORKTREE_MERGED`, `WORKTREE_DISCARDED`, `STATE_FORKED`, `STATE_MERGED`, `AUDIT_FORKED`, `AUDIT_MERGED`), 4 practices (`PRACTICES_DISCOVERED`, `PRACTICES_AFFIRMED`, `PRACTICES_OVERRIDE`, `PRACTICES_SECTION_EMPTY`), 3 merge-dispatch (`MERGE_DISPATCH_INVOKED`, `MERGE_DISPATCH_RETURNED`, `MERGE_DISPATCH_FALLBACK`)
* `tests/unit/t28-audit-event-sync.sh` pin bumped from 41 to 55, matching the new `## Event Registry (55 events, 15 categories)` header in `aidlc-knowledge/shared/audit-format.md` and the `**55 events across 15 categories.**` prose in `docs/reference/12-state-machine.md`
* Three new `### ` category subsections (Worktree, Practices, Merge Dispatch) added to both audit reference docs in matching shape
* `tests/feature/t48-audit-event-emitters.sh` forward-emitter check skips rows whose Emitter cell starts with `Reserved` (existing behaviour at line 101) — pre-registered rows pass until the consumer replaces `Reserved` with the real `tools/*.ts` path in the same commit it adds the emit call
