## [0.7.4] - 2026-06-14

Absorbs the v0.6.8 engine hardening, the test-harness's Windows wave, and main's v0.6.9/v0.6.10 repo-review batches into the one-core-many-harnesses model, so every harness (Claude / Kiro / Codex) carries them. The v0.6.8 birth-seam and single-stage fixes were authored against the single-harness `.claude/` tree; here they are re-homed into `core/` (and `harness/<name>/` for the orchestrator skill) so `bun scripts/package.ts` regenerates them into all three distributions — a naive copy into the generated `dist/` would have been clobbered on the next build. The v0.6.10 batch adds lost-update safety to state writes, makes `/aidlc --doctor` cover all 10 hooks and run cold-safe, and lets the swarm convergence check run on native Windows. Re-copy your `dist/<harness>/` to pick it up.

* **Workflow-birth, idempotent re-reports, and reject self-heal now ship to every harness.** Explicitly naming a scope on a fresh project (`/aidlc --scope <scope>` or `/aidlc <scope>`) births the workflow; a stale re-report after the workflow moved on is an idempotent `done`; Request Changes works even when the optional `gate-start` was skipped (backfilled gate rows carry `Recovered=true`); single-stage runs no longer leak into the main workflow's runtime graph or counts. The birth directive resolves its tools through the harness-dir seam, so it names the correct tree on Kiro and Codex, not a hardcoded `.claude/`.
* **Windows platform-invariance.** Path resolution across the engine and sensors is backslash/drive-letter aware (`fileURLToPath`, normalized glob comparison); the test runner is the native `bun tests/run-tests.ts` with `tests/run-tests.sh` kept as a POSIX wrapper; the Windows EC2/SSM harness (`tests/harness/windows/`) ships.
* **New tests:** `t143-scope-start-birth` (live scope-birth journey), `t152-windows-portability` (the renumbered Windows guard — `t144` is the harness-seam test on this branch), and `t153-engine-directive-harness-seam` (guards that no engine directive hardcodes `.claude/tools/` instead of the harness-dir seam). `BOLT_FAILED` and `SENSOR_FAILED` are now covered (audit floor 27).
* **Also absorbs the v0.6.9 repo-review batch.** State-file writes are now atomic (`core/tools/aidlc-lib.ts` `writeStateFile` routes through `writeFileAtomic` — temp + rename — with a read-only-target guard preserving the deliberate write barrier). The learning gate's `--test-run` skip is restored (`aidlc-learnings.ts` read the state field as `Test-Run Mode` (hyphen) while every writer uses `Test Run Mode` (space), so the skip was dead code). CHANGELOG version link references were removed (a distributed file should not embed a repository host); `t68` is redesigned — the version pin is the heading, headings must be unique, and a net-new guard fails if any link reference or host URL reappears. `LICENSE` is now MIT-0; the `--debug` failures-file extractor matches bun's `(fail)`/`error:` output.
* **And the v0.6.10 C2b + doctor + swarm batch.** State transitions are now lost-update safe: the 11 state-mutating subcommands (`set` / `set-skeleton-stance` / `checkbox` / `advance` / `finalize` / `complete-workflow` / `gate-start` / `approve` / `reject` / `revise` / `skip`) each wrap their read→decide→audit→write inside the audit lock, so concurrent writers (the swarm referee, parallel Bolts, hooks) serialise instead of clobbering each other (`fork` / `merge` were already locked; v0.6.9's atomic write didn't cover the lost update). No CLI surface change. `/aidlc --doctor` now presence-checks every hook `settings.json` wires — all 10 framework hooks, sourced from the wiring rather than a hardcoded list that silently skipped 3 (`aidlc-runtime-compile.ts`, `aidlc-sensor-fire.ts`, and the flow-altering `aidlc-stop.ts`) — and a wired-but-missing hook now fails loudly. `--doctor` is also read-only / cold-safe: on a project with no `audit.md` it creates nothing (it previously scaffolded `aidlc-docs/` + `audit.md` via its own emits, though `--doctor` runs before `--init`); initialized projects still record both events. And the swarm convergence check runs its check command through the OS shell instead of a hardcoded `bash` argv, so it no longer spuriously fails on native Windows PowerShell — still using `/bin/bash` on POSIX where present so a bash-specific check keeps its interpreter.
