## [0.5.20] - 2026-06-06

Ships the swarm's deterministic convergence **referee**, `aidlc-swarm.ts`. The swarm fires only under human-granted Construction autonomy inside a live `/aidlc` session, so the conductor (that session) owns the fan-out and the retry loop; the tool owns only what must be deterministic — the convergence verdict, the anti-tamper guard, the serialised merge-back, and the typed failure envelope. It is stateless (no iteration counter) and re-exposed as three subcommands. `prepare` forks an isolated git worktree per unit (composing `aidlc-worktree create` + `aidlc-bolt start --worktree`) and records batch start. `check <unit>` returns a stateless verdict from the project's own check command (exit 0 = green — a worker's self-claim is never trusted) plus an anti-tamper compare of a protected file against its forked-git baseline. `finalize --claimed` re-verifies every unit the conductor claims converged before any merge, serialised-merges only the genuine passes (the existing HOLD-MERGE lock), and returns the typed envelope (`unsatisfiable`, `budget-exhausted`, `cap-exhausted`, `error`). Because `finalize` re-verifies, a red unit cannot merge even if the conductor lies or misremembers — the lying-conductor guard. Nothing invokes the referee automatically yet; it is wired to the conductor in v0.5.21. No upgrade action.

* New tool surface `bun .claude/tools/aidlc-swarm.ts prepare|check|finalize`. `prepare --batch <n> --units <a,b,c> [--base <branch>] [--degraded-from <subagent|ultracode>]` forks the worktrees; `check <unit> --check-cmd <cmd> [--test-file <path>]` prints `{converged, tampered, reason}` and exits 0 iff genuinely converged (emits no audit); `finalize --batch <n> --units <a,b,c> --claimed <a,b> --check-cmd <cmd> [--test-file <path>] [--reasons <unit>=<reason>,…]` prints the JSON envelope (`{units, converged, failed, merge_failures}`) and exits 0 when every claimed unit re-verified and merged, 2 when any unit failed or a merge failed (the conductor takes the baton). `--reasons` lets the conductor attribute a typed reason (`unsatisfiable` / `budget-exhausted` / `cap-exhausted`) to a *declined* unit it did not claim — recorded faithfully on `SWARM_UNIT_FAILED`, defaulting to `cap-exhausted`, and never able to override a claimed-but-red unit's `error` verdict. The retired headless `run` verb, the `claude -p` worker, the triple cap, and the `AIDLC_SWARM_CLAUDE_BIN` test seam are all gone — the runaway backstop is now the harness 8-block Stop-hook ceiling.
* A new audit event `SWARM_DEGRADED` records a loud downgrade — `AIDLC_USE_SWARM=1` was requested but the Workflow tool was unavailable, so the conductor ran the subagent floor (the referee makes the substrate difference invisible to convergence). The two previously-reserved per-Unit events now emit from `finalize`: `SWARM_UNIT_CONVERGED` (re-verified green and untampered) and `SWARM_UNIT_FAILED` (not claimed, claimed-but-red, or tampered, with the typed reason). The batch-level trio stays reserved until the conductor wiring lands. The audit taxonomy grows from 66 to 67 events.
