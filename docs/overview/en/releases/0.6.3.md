## [0.6.3] - 2026-06-09

Clarifies two pieces of conductor guidance so the orchestrator stops misreading them at run time. First, on a multi-agent stage that runs `mode: inline` (every multi-agent stage in the shipped graph), `support_agents` are perspectives the conductor adopts in its own context — it loads each support agent's file and knowledge the same way it loads the lead, and never calls `Task` for them; `Task` is reserved for `mode: subagent` stages. This removes the "support-agent subagent types aren't registered" fallback you would see when a support agent on an inline stage (e.g. AWS-platform or compliance during Feasibility / Application Design) was dispatched as a Task instead of read as a persona. Second, new reference material handed in mid-stage (a reference code package, an example repo, a spec) is now explicitly classified as evidence for the *current* stage, never an instruction to advance — so supplying a package during Functional Design no longer skips the remaining design/NFR stages and jumps to Code Generation; routing changes only on an explicit `--stage` / `--scope` action through the normal impact/gate flow. No upgrade action; re-copy the shipped `.claude/` to pick it up.

* `dist/claude/.claude/aidlc-common/conductor.md` — "Framing the persona" now ties support-agent handling to `directive.mode`: inline support agents are loaded as personas in the conductor's context, `Task` is reserved for `mode: subagent`, and a missing Task subagent-type registration on an inline stage is called out as expected (not an error to route around).
* `dist/claude/.claude/aidlc-common/protocols/stage-protocol.md` — §5 "Multi-agent stages" mirrors the same rule: inline support agents are adopted perspectives, not Task dispatches.
* `dist/claude/.claude/aidlc-common/protocols/stage-protocol-recovery.md` — §7 Change Handling adds "New reference material supplied mid-stage": treat it as evidence/input, stay on the current stage, fold it into the current questions/artifacts/memory, and continue through the normal `report → next` transition; advance only on an explicit user jump/scope change.
