## [0.5.14] - 2026-06-04

Adds the framework's first flow-altering hook: a `Stop` hook (`aidlc-stop.ts`, wired into the `aidlc` skill frontmatter) that enforces the interactive forwarding loop. When the conductor tries to end its turn, the hook runs the orchestration engine (`aidlc-orchestrate next`); if the workflow is complete (`done`) it lets the turn end, and if a step is still pending it blocks the stop and re-feeds the next move so the loop runs to completion regardless of whether the LLM remembered to consult the engine. The injected message is phrased only as the work still owed — never an override-shaped instruction — so a buggy or compromised engine can only ever continue sanctioned work, never hijack the session. Recursion is bounded two ways so a stuck loop can never trap a session: a no-progress block counter under an 8-block ceiling (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`, default 8) and Claude Code's own `stop_hook_active` signal; once the ceiling is reached the hook releases the turn. User interrupt (Esc) is never affected — Stop hooks do not fire on interrupt. The hook is a no-op outside an AIDLC workflow and fails open on any unexpected error, so a non-AIDLC session is never blocked. No upgrade action required.

* The shipped `aidlc` skill now registers a `Stop` hook. On the interactive path the forwarding loop is harness-enforced: a turn that ends with a pending workflow step is blocked and the next step is injected back, until the engine reports the workflow is `done`. Set `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` to tune the recursion ceiling (default 8); when the no-progress block streak reaches it, the hook lets the turn end. The hook does nothing outside an AIDLC workflow and never affects a manual interrupt.
* The framework now ships 10 hooks (was 9).
