## [0.3.3] - 2026-05-17

Adds the path-helper primitive that downstream Construction-worktree work (`aidlc-worktree.ts`, state fork/merge, audit fork/merge) composes over, plus the `.gitignore` reservation for the runtime namespace at repo root. No behaviour change in this patch — `worktreePath()` has no callers yet; it ships ahead of its consumers so test fixtures and the keystone can reference the path.

* `worktreePath(projectDir, boltSlug)` exported from `.claude/tools/lib.ts` returns `<projectDir>/.aidlc/worktrees/bolt-<slug>`. Pure path construction; mirrors `stateFilePath` and `auditFilePath`. Composes with them so `stateFilePath(worktreePath(p, slug))` and `auditFilePath(worktreePath(p, slug))` yield the in-worktree state and audit paths state fork and audit fork will read and write
* `.gitignore` reserves `/.aidlc/` at repo root for AIDLC runtime state. Anchored (leading `/`) so a stray `.aidlc/` inside `node_modules/` or a nested package isn't silently swallowed. Distinct from the existing `.claude/worktrees` entry — `.aidlc/worktrees/` is the Construction-Bolt runtime path; `.claude/worktrees/` is the framework-development worktree convention. Both coexist intentionally
* `tests/unit/t69-worktree-path.sh` pins the helper's behavioural contract: `.gitignore` entry present, output absolute when `projectDir` is absolute, output ends with `/bolt-<slug>`, and slug passes through unsanitised (validation deferred to the `aidlc-worktree.ts` create-time check)
