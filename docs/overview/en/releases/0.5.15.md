## [0.5.15] - 2026-06-04

Restores `--test-run` persistence at both workflow birth AND resume, which the orchestration-engine cutover (0.5.12) silently dropped on both legs. When that release moved orchestration from `SKILL.md` prose into the engine, two re-stamp paths were lost. (1) Birth: the engine's `--init` directive builder threaded `--scope`/`--depth`/`--force` but not `--test-run` — so `/aidlc <scope> --test-run` scaffolded state WITHOUT the `Test Run Mode: true` field that `init` writes only when it receives the flag. (2) Resume: the old prose ran `aidlc-utility.ts enable-test-run` whenever `--test-run` re-entered an already-scaffolded workflow, re-stamping the field; the cutover deleted that instruction with no replacement, so a `--test-run` resume over a stamp-less workflow never re-stamped. That field is what the jump tool reads on resume to detect test-run mode (it reads the field, not the CLI flag), so either drop meant a `--test-run` run could lose its automation marking and start prompting at gates. The engine now restores both: it threads `--test-run` into the scaffold command at birth, and on resume it emits a run-then-continue `print` naming `enable-test-run` when `--test-run` re-enters a workflow whose state lacks the field — the same engine-names-the-move / conductor-runs-the-tool shape it already uses for scope-change and jumps, so `next` stays read-only. This makes good on 0.5.12's "behaviour is unchanged" promise. No action is needed for existing workflows. No upgrade action required.

* `/aidlc <scope> --test-run` (and `/aidlc --init --test-run`) once again records `Test Run Mode: true` in `aidlc-docs/aidlc-state.md` at workflow birth, so test-run mode survives across resume in a fresh session.
* `/aidlc <scope> --test-run` re-entering an EXISTING workflow whose state file lacks the `Test Run Mode` field (e.g. a workflow first started without `--test-run`, then resumed with it) now re-persists the field instead of silently running without it — restoring the resume-time `enable-test-run` re-stamp the prose orchestrator ran before the cutover. Between 0.5.12 and this release the flag was dropped on both the birth and resume legs, so an automated/CI run could lose its test-run marking and start prompting at gates.
