## [0.1.0] - 2026-04-24

Initial public release.

* `/aidlc` orchestrator skill with 5 phases (Initialization, Ideation, Inception, Construction, Operation) and 32 stages
* 11 domain-expert agents: product, design, delivery, architect, aws-platform, compliance, devsecops, developer, quality, pipeline-deploy, operations — invoked by the orchestrator based on stage and scope
* 9 adaptive scopes (enterprise, feature, mvp, poc, bugfix, refactor, infra, security-patch, workshop) that route through different stage subsets
* `--depth` flag with three levels (minimal, standard, comprehensive) to control process rigor per stage
* `--test-strategy` flag with three levels (Nyquist Minimal, Standard, Comprehensive) independent of depth — workshop scope defaults to Minimal
* `--stage`, `--phase`, `--scope` jump flags for moving directly into a specific point in the workflow
* `--status`, `--doctor`, `--help`, `--init`, `--test-run` utility handlers
* Bolt-by-Bolt Construction: dependency DAG execution with walking skeleton mode, autonomy mode, and per-bolt quality gates
* Stage protocol with approval gates at every stage, structured question format, and session resume from any checkpoint
* TypeScript hooks for audit logging (37-event taxonomy), state preservation, statusline sync, and session recovery — runs natively on Windows without Bash
* `AWS_AIDLC_DEFAULT_SCOPE` environment variable so organizations can pin a default scope at the shell or profile level
* Statusline showing current phase, stage, agent, model, and context usage with phase-scoped progress
* Three-tier test suite (smoke, unit, feature, integration) with LLM-behavioral tests via `--test-run`
* `BOLT_*` audit event taxonomy for Construction phase tracking
* Two-tier documentation: User Guide (`docs/guide/`) and Developer Reference (`docs/reference/`)
* Promoted 7 agents (architect, compliance, devsecops, developer, quality, pipeline-deploy, operations) to Opus; shipped Bedrock model IDs as defaults
* Pinned orchestrator to Opus with 1M context on Bedrock
* `/aidlc --help` documents all CLI utilities and flags with examples
* Windows compatibility: hooks and the statusline ported from Bash to TypeScript; `--doctor` is platform-aware; no jq or Bash prerequisites
* macOS compatibility across the test suite (BSD vs GNU utilities, whitespace padding, AppleDouble sidecar files)
