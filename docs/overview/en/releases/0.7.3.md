## [0.7.3] - 2026-06-14

Single-source onboarding docs. The three shipped onboarding docs (`dist/claude/.claude/CLAUDE.md`, `dist/kiro/AGENTS.md`, `dist/codex/AGENTS.md`) now all render from one hand-authored skeleton — `core/templates/onboarding.md` + per-harness fills — instead of being three independently-maintained artifacts (Claude hand-authored, Codex a regex-rewrite of Claude's CLAUDE.md, Kiro a hand-fork that had drifted to "two harnesses" and was missing whole sections). Adding a harness now means authoring one `onboarding.fills.ts`; the doc generates complete and drift-guarded. No behavior change to any distribution. Maintainers and Kiro/Codex users should regenerate (`bun scripts/package.ts`) and re-copy `dist/<harness>/`.

* **Onboarding docs are generated, not hand-maintained.** `bun scripts/package.ts` renders each harness's CLAUDE.md/AGENTS.md from `core/templates/onboarding.md`; `--check` drift-guards them like every other generated file. The Codex `AGENTS.md` no longer derives from Claude's CLAUDE.md, so Claude-specific prose can no longer leak into it.
* **Kiro's onboarding doc gained the Documentation and Automated-Testing coverage it was missing**, and its identity is anchored to the shared core (not "vs Claude").
* **New test** `t151-onboarding-skeleton` proves a brand-new harness renders a complete onboarding doc from the skeleton (every section present, no unsubstituted tokens) — the "4th harness for free" guarantee.
