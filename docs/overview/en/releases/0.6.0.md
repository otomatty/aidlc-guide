# aidlc-workflows 0.6.0

[All releases / 更新履歴一覧](../changelog.md) · [改善点の日本語ガイド](../release-highlights.md)

## [0.6.0] - 2026-06-07

**The orchestrator is unbundled: a deterministic engine decides what happens next, the `/aidlc` session carries it out, and the framework gained a family of typeable runner commands plus an autonomous build swarm.** For everyone running `/aidlc`, invocation is unchanged — the recomposition is internal. What's new is the surface around it: one-word `/aidlc-<stage>` and `/aidlc-<scope>` runner commands; a `--single` mode that runs a stage in isolation without touching your workflow; and, under human-granted Construction autonomy, a swarm that fans out independent build units in parallel and converges them behind a deterministic referee. Under the hood, the routing logic moved out of `SKILL.md` (now a ~170-line forwarding loop) into the `aidlc-orchestrate` engine, which emits a typed directive on every turn; scope membership is now file-authored (`.claude/scopes/aidlc-<name>.md` + a `scopes:` tag on each stage) and the old `scope-mapping.json` is gone.

**Upgrade.** Re-copy the shipped `.claude/` over your project's `.claude/` (`cp -r dist/claude/.claude/ your-project/.claude/`). Because every framework hook is now registered project-wide in `settings.json` (the skill-scoped hooks moved there), re-copy the shipped `settings.json` or merge its `hooks` block so the relocated hooks are registered — `aidlc/SKILL.md` no longer carries a `hooks:` block. The state template is unchanged, so existing workspaces stay schema-compatible.

**For everyone running `/aidlc`**

* **`/aidlc` works exactly as before** — full orchestrator, scope detection, every flag. No breaking changes to how you invoke a workflow.
* **New `/aidlc-<scope>` runner commands.** `/aidlc-bugfix`, `/aidlc-feature`, `/aidlc-mvp`, `/aidlc-security-patch` drive a workflow with a fixed scope and no detection — the same workflow as `/aidlc --scope <name>`, as their own typeable command. Every other scope stays reachable via `/aidlc --scope <name>`.
* **New `/aidlc-<stage>` runner commands + `--single`.** One command per runnable stage (e.g. `/aidlc-code-generation`) runs that stage in isolation via `--single` and never advances your main workflow's stage pointer — the isolation is tool-enforced. `/aidlc-init` packages `/aidlc --init`.
* **An autonomous build swarm.** After you grant Construction autonomy, eligible independent build units fan out in parallel (across isolated worktrees) and converge behind a deterministic referee that re-verifies every unit before merge — a unit that fails, or is falsely claimed converged, returns the baton to you. Set `AIDLC_USE_SWARM=1` to drive the fan-out with an inline workflow; unset it for the parallel-subagent floor.
* **Skill-picker discoverability.** Every `/aidlc-*` runner surfaces in Claude Code's `/` picker, no manual registration.

**For harness engineers and contributors**

* **Scope is a file-authored primitive.** A scope is a `.claude/scopes/aidlc-<name>.md` file (identity) plus a `scopes:` tag on each member stage (membership), transposed at compile into `scope-grid.json`. The `scope-mapping.json` data file is removed; adding a scope is now purely additive, no code edit.
* **Runners are generated, not hand-written.** `aidlc-runner-gen.ts` emits a runner per runnable stage and per shipped scope from the compiled graph; drift guards fail CI if the on-disk set diverges. "To add a stage, write a stage file" then regenerate — the runner follows.
* **The orchestration engine + typed directive contract.** `aidlc-orchestrate.ts` (`next`/`report`) owns all between-stage routing and emits a validated typed directive; `SKILL.md` is the conductor that acts on it. New reference chapter [Engine and Skill System](https://github.com/awslabs/aidlc-workflows/blob/HEAD/docs/reference/17-skill-system.md) and User Guide chapter [Skills and Runner Commands](https://github.com/awslabs/aidlc-workflows/blob/HEAD/docs/guide/17-skills.md) document both.
* **Audit taxonomy grows to 67 events** — six `SWARM_*` events for the batch lifecycle (`SWARM_STARTED`, `SWARM_UNIT_CONVERGED`, `SWARM_UNIT_FAILED`, `SWARM_BATON_RETURNED`, `SWARM_COMPLETED`, `SWARM_DEGRADED`).
* `dist/claude/.claude/tools/aidlc-version.ts` — bumped 0.5.21 → 0.6.0.
