## [2.1.3] - 2026-06-28

Closes the rubber-stamp trap that let an agent on a long (enterprise-scope) workflow mark every remaining stage complete with no real output, and stops the Stop hook from nagging a human who just wants to chat mid-workflow. Four interlocking fixes land together (they all touch `aidlc-state.ts` / the Stop hook, so shipping separately would force hard conflicts): a first-class **park** command gives the conductor a clean multi-session exit, a deterministic **artifact guard** refuses to complete a stage with no evidence of work on disk, an **autonomy guard** keeps an unattended swarm/Bolt run from self-parking, and a **conversational carve-out** lets a chat turn end without being nudged back into the loop. **Upgrade:** re-copy your `dist/<harness>/` shell into the project. CI/scripts breaking change: every `aidlc-state.ts` subcommand that completes a stage (`approve`, `advance`, `finalize`, `complete-workflow`) now refuses to mark it `[x]` when the stage's declared `produces[]` artifacts are absent; pass `--test-run` or set `AIDLC_SKIP_ARTIFACT_GUARD=1` for automated dry runs.

* **Park (#365, #367):** `bun .claude/tools/aidlc-orchestrate.ts park` parks the workflow at the current inter-stage boundary and emits a new `parked` directive; the Stop hook treats `parked` as a terminal allow, so a long workflow can pause and resume in a later session with `/aidlc --resume` instead of rubber-stamping stages to reach `done`. No stage is advanced and nothing is marked complete.
* **Artifact guard (#366):** `approve`, `advance`, `finalize`, and `complete-workflow` now verify on-disk evidence before marking a stage `[x]`: a declared `produces[]` artifact must exist under the intent's record dir, and a `workspace_requires` stage (today only `code-generation`) must additionally show real source work outside the `aidlc/` workspace tree (git-aware when the workspace is a git repo, else a filesystem-existence check). Bypass with `--test-run` or `AIDLC_SKIP_ARTIFACT_GUARD=1`.
* **Autonomy guard (#365):** an autonomous Construction run (`Construction Autonomy Mode: autonomous`) can never self-park: both `aidlc-state.ts park` and the Stop hook's `parked` allow decline under autonomous mode, so an unattended run keeps moving.
* **Conversational carve-out (#365):** the Stop hook no longer nags a human who is just chatting mid-workflow. When the harness delivers a transcript (Claude and Codex pass `transcript_path`), the hook reads it and, if the most recent human prompt was answered with no workflow-engine call (`aidlc-orchestrate` / `aidlc-state`), it allows the turn to end with zero nudges. As a portable backstop on every harness (including Kiro, which delivers no transcript), the no-progress block cap now defaults to **2 in an interactive run** (down from 8 - issue #365's own recommended workaround) so a chatting or pausing human is released after one nudge; an **autonomous** Construction run keeps the long cap of 8 and the carve-out is disabled there (the unattended loop must keep moving). `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` still overrides both.
* New audit events `WORKFLOW_PARKED` / `WORKFLOW_UNPARKED` and state subcommands `park` / `unpark`; the audit taxonomy grows from 67 to 69 events.
