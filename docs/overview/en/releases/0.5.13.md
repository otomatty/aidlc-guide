## [0.5.13] - 2026-06-04

Extracts the conductor's execution-quality prose out of the orchestrator's `SKILL.md` into a shared `aidlc-common/conductor.md`, and the engine now delivers that persona in-context on the first stage of a workflow (so framework and hand-written runners get the same conductor with no per-skill wiring). The same release names and tools the one workflow decision the engine cannot compute on its own: the first Construction Bolt's approval gate depends on a team's walking-skeleton stance, which is read from free-form `## Walking Skeleton` practices prose. Rather than put that judgement in a deterministic tool, the engine emits that gate as `"unresolved"`, the conductor classifies the prose and hands the stance back via a new `report --skeleton-stance` flag, and the next `next` emits the now-determined gate. Behaviour is unchanged for anyone running a Construction workflow — the gate still presents at the first Bolt — and the engine still owns the transition. No upgrade action required.

* `bun .claude/tools/aidlc-orchestrate.ts report` accepts a new `--skeleton-stance <on|off|scope-dependent>` flag. It records the classified walking-skeleton stance and does not commit a stage transition; the following `next` reads it and resolves the first Construction Bolt's gate. An invalid stance value, a stance reported when the workflow is not parked on the first Construction Bolt, or a stance reported with no workflow state each return a clear error.
* The `run-stage` directive emitted by `bun .claude/tools/aidlc-orchestrate.ts next` may now carry `gate: "unresolved"` (instead of a boolean) for the first Construction Bolt before its stance is classified. Every other stage still carries a boolean gate. Scripts that parse the directive's `gate` field should treat it as `boolean | "unresolved"`.
* The first `run-stage` directive of a workflow now carries an optional `conductor_persona` string (the shared execution-quality persona, read from `.claude/aidlc-common/conductor.md`); later directives omit it. No skill references that file by path — the engine delivers it.
