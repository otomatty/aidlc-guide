## [2.3.1] - 2026-07-10

Authored agents no longer carry raw model pins: the authored contract on every agent is now a work-shaped `tier:` (`judgment` | `balanced` | `templated`), which the build projects into each harness's native model/effort keys. On Claude Code the nine judgment agents stop pinning Opus; the balanced/templated agents still project to a Sonnet-class model. The nine judgment agents (architect, aws-platform, compliance, composer, design, developer, devsecops, product, quality) become `model: inherit` with no effort pin on Claude Code, so a session running Fable (or any other model, at any effort) keeps it in delegated work - the framework never silently downgrades your session choices. The two balanced reviewers and three templated planners keep a Sonnet-class model; only the templated tier steps effort down (`medium`). To restore the old always-Opus behavior for one agent, edit the projected value in your installed copy (e.g. set `model: opus` in that agent's `.claude/agents/*.md`); to cap every agent when building from source, set `tier_cap:` in `core/memory/org.md`/`project.md` frontmatter or run the packager with `AIDLC_TIER_CAP=<tier>`. **Upgrade:** re-copy your `dist/<harness>/` shell into the project.

* Claude Code: judgment agents ship `model: inherit` and no `effort:` line (session model and effort win); balanced ships `model: sonnet` with no effort pin; templated ships `model: sonnet` + `effort: medium`. A pinned `effort:` overrides the session in both directions, so absence is deliberate.
* Codex CLI: judgment agent TOMLs omit `model` and `model_reasoning_effort` and inherit the shipped `.codex/config.toml` session defaults (verified live on codex-cli 0.142.5); balanced pins `openai.gpt-5.4` with inherited effort; templated pins `openai.gpt-5.4` + `medium`.
* Kiro CLI/IDE: judgment agent JSONs omit `"model"` (the agent-v1 schema falls back to your default model); balanced/templated pin `claude-sonnet-4.5`. Behavior change on Kiro: ALL five delegation-target agent JSONs previously pinned `claude-opus-4.8`, so the three judgment targets (architect, composer, developer) now follow your default model, and the two balanced reviewers (product-lead, architecture-reviewer) step down from opus-4.8/xhigh to sonnet-4.5/high. The authored agent JSONs no longer carry a `"model"` field at all - the build owns it. `settings/cli.json` gains a `claude-sonnet-4.5 -> high` entry in `chat.modelDefaults` beside the existing `claude-opus-4.8 -> xhigh` (effort rides on the model on Kiro; when two tiers share a model the higher tier's effort wins; cli.json is CLI-only - the IDE applies its extension defaults).
* New pack-time cost cap: `tier_cap:` in the space-memory frontmatter (`org.md` -> `team.md` -> `project.md`, last writer wins) collapses higher tiers for every projection; the `AIDLC_TIER_CAP` env var overrides it per invocation. An invalid value fails `bun scripts/package.ts` loudly.
* Authored agent frontmatter no longer carries `model:` - a raw `model:`/`effort:` in `core/agents/*.md` is a projection bypass and the tests now pin its absence. Custom user-authored agents in your own project keep using `model:` as before; only the shipped roster is tier-projected.
