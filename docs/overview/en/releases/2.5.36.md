## [2.5.36] - 2026-08-03

Adds an optional declared workspace manifest for multi-repo teams. AI-DLC already auto-discovers sibling code repos on disk at intent birth; this release lets a team also declare that expected set in a `repos.json` file at the workspace root and reconcile it with a new `aidlc-workspace-sync` tool that clones missing repos, maintains a managed `.gitignore` block, and generates a VSCode multi-root workspace. The manifest is a convenience layer only: disk discovery remains the runtime source of truth, so a repo works the moment it is cloned whether or not it is declared. `--doctor` gains three advisory rows about manifest state. **Upgrade:** re-copy your `dist/<harness>/` shell to pick up the new tool; without `repos.json`, sync stays dormant and doctor adds only the advisory workspace-records row.

* New tool `aidlc-workspace-sync.ts` (run `bun <harness-dir>/tools/aidlc-workspace-sync.ts [--force]`): reads an optional `repos.json` (`{ "org", "repos": [{ "name", "branch"?, "url"? }] }`) at the workspace root, clones declared-but-missing repos on their declared branch, rewrites the managed block in the workspace `.gitignore`, and writes `aidlc.code-workspace`. Reconciles serialize under a workspace lock that cannot be reaped while its owner is alive; clones and generated files are staged before a reversible transaction. Concurrent manifest or output edits abort instead of applying stale state, no-replace installs close the final path race, and prior generated files are retained for recovery. Exit `0` in sync, `1` blocked/error with live paths unchanged, `2` synced with advisory warnings.
* Orphan safety: a checkout on disk but not in `repos.json` leaves the active sibling set only with `--force` after the tool overrides configurable status defaults, checks untracked and ignored content (including empty directories), hidden index state, stashes, refs and reflogs, unreachable Git objects, linked worktrees, submodules, and LFS object stores. Matching live refs must have fetchable object graphs - an advertised OID alone is not recovery proof - and local remotes whose storage or object alternates depend on the checkout cannot authorize removal. After revalidation, the checkout moves into transaction quarantine and receives the full local and live-remote proof again; its quarantined copy is retained in an ignored `.aidlc-workspace-sync-recovery-*` directory instead of being recursively deleted, so even a concurrent writer holding the directory open cannot lose a late write. Inspect and manually delete retained recovery copies when no longer needed. Existing repos are never re-cloned or branch-switched; their `branch` mismatch is advisory.
* `/aidlc --doctor` gains three advisory rows (they never change the exit code): uncommitted changes under `aidlc/`, `repos.json` vs on-disk sibling drift, and a stale managed `.gitignore` block. Doctor and sync share the same strict manifest schema, including safe immediate-child names, so invalid JSON or schema never appears synchronized. The drift and gitignore rows appear only when a `repos.json` exists, so single-repo installs do not gain manifest-specific rows.
* User Guide documents the optional manifest in Spaces and Intents and the tool invocation in CLI Commands, both stressing that the manifest never overrides runtime disk discovery.
