## [0.6.2] - 2026-06-09

Hardens two framework sensors and lands the test suite's all-TypeScript port. The `type-check` sensor no longer reports a clean PASS when `tsc` fails to load its config: a config-load failure (e.g. TS18003 "No inputs were found", which exits non-zero but carries zero parseable diagnostics) now propagates `tsc`'s exit code so the dispatcher records it as `script-error` rather than a false green. The sensor dispatcher gains an `AIDLC_SENSOR_SCRIPT_DIR` seam so per-sensor scripts resolve from an overridable directory — unset in production (sibling resolution against the tools dir, exactly as before), set only by tests that exercise stub scripts so they never write into the shipped `.claude/tools/` tree. No upgrade action; re-copy the shipped `.claude/` to pick it up.

* `dist/claude/.claude/tools/aidlc-sensor-type-check.ts` — propagates `tsc`'s non-zero exit when zero diagnostics parse, so a broken `tsconfig` surfaces as `script-error: exit-<n>` instead of a silent clean PASS. A genuine type error (non-zero exit with parsed diagnostics) still flows through as `pass:false`/FAILED, unchanged.
* `dist/claude/.claude/tools/aidlc-sensor.ts` — `resolveScriptPath` honours an optional `AIDLC_SENSOR_SCRIPT_DIR` override (mirroring `AIDLC_SENSORS_DIR` for manifests); unset, it resolves against the tools dir as before.
