## [0.3.10] - 2026-05-19

Adds `audit-fork` and `audit-merge` subcommands to `aidlc-audit.ts`, completing the audit half of the per-Bolt fork/merge primitive (alongside worktree create/merge and state fork/merge). Both subcommands follow audit-of-intent semantics extended from the `WORKTREE_*` events: `AUDIT_FORKED` and `AUDIT_MERGED` emit to the main audit *before* the disk operation, so a kill-9 between emit and disk surfaces as a phantom audit row reconciled by `--doctor`. The worktree audit is byte-for-byte self-contained at fork instant — its copy includes the `AUDIT_FORKED` entry by virtue of the emit-then-copy order. Delta detection at merge is parse-driven (locate the AUDIT_FORKED block in the worktree audit, take everything after its closing separator); the `Fork Boundary` field on AUDIT_FORKED anchors a SHA-256 prefix-hash sanity check that refuses to merge if main audit's prefix has been tampered with mid-Bolt. Solo Bolts as of this patch — no SKILL.md call sites yet (wired in a later release).

* `bun .claude/tools/aidlc-audit.ts audit-fork --slug <slug>` emits `AUDIT_FORKED` to the main audit, then mkdirs `<worktree>/aidlc-docs/` and copies the main audit byte-for-byte to the worktree. The `Fork Boundary` field records the byte offset of the main audit immediately BEFORE the AUDIT_FORKED row landed; `Source Audit Hash` records SHA-256 of those same prefix bytes. The worktree's copy of the AUDIT_FORKED row carries the same fields, so audit-merge can recover them without inspecting main
* `bun .claude/tools/aidlc-audit.ts audit-merge --slug <slug>` reads the worktree audit's most recent AUDIT_FORKED entry for the slug, recomputes main audit's prefix-hash at byte `Fork Boundary` and refuses with `prefix-hash` error if it disagrees with the recorded `Source Audit Hash`. On success, locates the byte position immediately after the AUDIT_FORKED block's closing `\n---\n`, appends the post-fork delta to main, and emits `AUDIT_MERGED` (with `Entries Merged`, `Source Audit Hash`, `Fork Boundary`) to the main audit only. Lock budget extended from 5s default to 20s (`acquireAuditLock(projectDir, 200, 100)`) to absorb N=4-8 Bolt-merge contention
* All `aidlc-audit audit-fork` / `audit-merge` failures route through `appendAuditEntry("ERROR_LOGGED", ...)` with `[slug=<slug>]` for `--doctor` correlation; post-emit failures additionally tag the message with `[fork-emitted:<timestamp>]` so doctor can distinguish "intent recorded, disk operation never landed" from earlier failure modes
* `audit-format.md:127-128` and `docs/reference/12-state-machine.md:283-284` Emitter cells for `AUDIT_FORKED` / `AUDIT_MERGED` now point at `aidlc-claude-code/.claude/tools/aidlc-audit.ts`. Required Fields cells updated to include `Fork Boundary` and the per-event extra fields
* `docs/reference/12-state-machine.md` § "Audit-of-intent exception" renamed to § "Audit-of-intent semantics" — the pattern now covers 5 events (3 `WORKTREE_*` + 2 `AUDIT_*`). `STATE_FORKED` / `STATE_MERGED` deliberately stay under the strict audit-first invariant — state writes are idempotent where `git worktree add` is not, so a failed state write surfaces as recoverable drift instead of an unrecoverable orphan. The 2-row event-group/emitter/disk-op table documents only the audit-of-intent half; STATE_* lives under the strict-first section above
* New worktree-tier test `tests/worktree/t07-audit-fork-merge.sh` (31 assertions across three phases): smoke (fork creates byte-identical worktree audit; AUDIT_FORKED in both audits with matching Fork Boundary; merge appends delta; AUDIT_MERGED in main only), edge cases (empty delta; missing aidlc-docs subdir auto-created; missing main audit fails loud; prefix-hash mismatch refusal; N=2 lock contention via 50ms stagger; lock-timeout failure path with planted stuck lock; 65-char slug rejected with length error; post-emit failure ERROR_LOGGED carries `[fork-emitted:<iso-ts>]` for doctor correlation), and property (N=4 alphabetical / reverse-alphabetical / same-second-timestamps / one-empty-delta scenarios all preserve per-Bolt fork→merge bracket order in the merged main audit)
* `BOLT_SLUG_REGEX` and `validateBoltSlug(slug)` exported from `lib.ts` — centralises the kebab-case Bolt slug regex (was previously duplicated as `SLUG_RE` in `aidlc-worktree.ts` and `SLUG_REGEX` in `aidlc-audit.ts`). Adds 64-char max-length check so pathologically long slugs fail fast with a clear error instead of surfacing as cryptic mkdir/copy failures. `aidlc-audit.ts` adopts the helper now; `aidlc-worktree.ts` keeps its tool-local `SLUG_RE`
* `AIDLC_AUDIT_LOCK_RETRIES` and `AIDLC_AUDIT_LOCK_RETRY_MS` env-var overrides for `audit-merge`'s lock budget — defaults stay at `200 × 100ms = 20s` for parallel-Bolt contention; tests dial these down so the lock-timeout failure path runs in ~100ms instead of 20s. Lock-timeout error message now reports the actual budget exhausted (`Failed to acquire audit lock after N × Mms = X.Xs retries; another merge in flight?`)
* `audit-merge` prefix-hash mismatch error now distinguishes truncation from mid-prefix mutation: when `mainBuf.length < boundary`, the error reads "expected at least N bytes, got M" so doctor can surface the right failure mode
* `appendAuditEntryUnlocked` is adopted on both the happy and error paths of `audit-merge` so the delta-append + AUDIT_MERGED emit (happy) and the delta-append + ERROR_LOGGED emit (catch) each run inside a single locked critical section, with no release-and-reacquire across either boundary
