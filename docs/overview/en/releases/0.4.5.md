## [0.4.5] - 2026-05-25

Both halves of the control-plane substrate now flip to pull authoring: each stage explicitly imports its sensors via a `sensors:` field in frontmatter, and the rule resolver's `paths:` glob mechanism on phase rules disappears in favour of the stage's existing `phase:` field as the pull import for its matching phase rule. Both halves now mirror how stages already declare `consumes`, `requires_stage`, `produces` — frontmatter declares; the resolver looks up. Org/team/project rules continue to attach to every stage automatically by filename. There is now one authoring direction across all stage relationships: stage frontmatter is the single source of truth for what fires when this stage runs.

`aidlc-graph compile` now also walks `.claude/sensors/`, indexes manifests by id, looks up each stage's imports, and bakes a per-stage `sensors_applicable` array into every node of `data/stage-graph.json`. Manifest schema simplifies: `applies_to:` is gone (scope lives on the stage side); `matches` moves to a top-level capability filter consumed by the PostToolUse hook at fire time. The rule resolver's glob machinery (`globToRegex`, synthesised concrete-path matching) deletes entirely.

The 32 stage YAML files gain explicit `sensors:` import lists. The `## Sensors` body compartments are rewritten from "bulleted inventory" to per-stage prose — naming what the stage produces, what each imported sensor checks on those outputs, what failure looks like. The list-of-sensors duplication goes (frontmatter owns that); the per-stage narrative stays. Stage YAML files become framework-and-loop-edited: the learning-loop ritual will append new sensor ids to a stage's `sensors:` list during the gate, where push authoring would have just edited a manifest. Stage files were never strictly framework-immutable on disk; pull authoring makes the edit boundary honest. Every stage node now carries the full resolved control-plane view that the dispatcher and PostToolUse hook read directly.

Sensor pull (the new resolver):

* `aidlc-claude-code/.claude/tools/aidlc-sensor-schema.ts` (new) — capability-descriptor schema. No `applies_to`. BOM-tolerant. Cross-checks `id:` against filename. Tolerates unknown keys.
* `aidlc-claude-code/.claude/tools/aidlc-lib.ts` — extends `parseStageFrontmatter` ARRAY_KEYS with `"sensors"` and `emitStageFrontmatter` FIELD_ORDER with `"sensors"`, so the new field round-trips through parse + emit cleanly.
* `aidlc-claude-code/.claude/tools/aidlc-stage-schema.ts` — adds optional `sensors: string[]` field to stage frontmatter.
* `aidlc-claude-code/.claude/tools/aidlc-graph.ts` — `loadSensors()` walker (returns `Map<id, SensorFile>` for O(1) lookup); `resolveSensorsForStage()` (id-lookup with throw-on-unknown); `SensorResolution` type and `GraphStage.sensors_applicable` field. `FIELD_ORDER` extends with `sensors_applicable` after `rules_in_context`. New `AIDLC_SENSORS_DIR` and `AIDLC_STAGES_DIR` env-seams.
* `aidlc-claude-code/.claude/sensors/aidlc-{required-sections,upstream-coverage,linter,type-check}.md` — `applies_to:` and `icon:` removed; `matches` moved to top level on `linter` and `type-check`.
* 32 stage YAML files under `aidlc-claude-code/.claude/skills/aidlc/stages/` — each gains a `sensors:` field with explicit id list. `## Sensors` body compartments rewritten from list-with-bullets to per-stage prose. Heading retained.
* `tests/feature/t89-compile-sensors-applicable.sh` (new) — 22 TAP assertions covering import-lookup, matches-passthrough, schema rejections (null/scalar/empty-string), unknown-id-throw, duplicate-id-throw, id-filename-mismatch, unknown-keys-tolerated (forward-compat), BOM-frontmatter, round-trip determinism, compile-snapshot semantics, and `--check` drift on sensor-manifest edits.
