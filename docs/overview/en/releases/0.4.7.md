## [0.4.7] - 2026-05-27

Ships the first emitter of the four `SENSOR_*` audit events pre-registered earlier. The `aidlc-sensor.ts` dispatcher CLI is a thin routing surface (Q4/Q5): it looks up a manifest by id, generates an 8-hex Fire id correlator, emits `SENSOR_FIRED` under one `withAuditLock`, spawns the per-sensor script (no lock held), and emits the paired terminal row (`SENSOR_PASSED` | `SENSOR_FAILED` | `SENSOR_BUDGET_OVERRIDE`) under a second `withAuditLock`. Two lock windows split across the spawn solve the spawn-window starvation that one-lock-across-spawn would create — long-running sensors (60s tsc) no longer pin the audit lock during their work.

Four framework sensors become real tool calls via their own scripts (`aidlc-sensor-required-sections.ts`, `aidlc-sensor-upstream-coverage.ts`, `aidlc-sensor-linter.ts`, `aidlc-sensor-type-check.ts`). Pull authoring at the manifest level: each manifest's `command:` declares HOW the sensor runs; the dispatcher routes; the per-sensor script does the work. Forks adding custom sensors write a manifest plus a script — no framework-code change.

**Three known limitations are documented forward:**

* **`sensor_firings[]` population deferred.** `aidlc-runtime.ts:319` continues to hardcode `sensor_firings: []` on every compiled `RuntimeStage`. This release emits the audit rows for the four `SENSOR_*` events; a later gate ritual is the first consumer that walks `audit.md` since each stage's `started_at` to populate the array. That consumer must also tolerate orphan FIRED rows (FIRED with no terminal pair, e.g., from a process crash between lock window A and lock window B); pair them as `result: "incomplete"` rather than discarding the FIRED. The current `SensorFiring.result` enum is `"passed" | "failed"`; a later release extends it to cover the four audit-emit terminals: `"passed" | "failed" | "budget-override" | "incomplete"`. The `SensorFiring` interface also gains a `fire_id: string` field so audit-walking can pair by Fire id (load-bearing under the parallel 4-sensors-per-Write fan-out — terminal rows interleave by spawn duration, not by FIRED order; positional pairing breaks). The dispatcher emits `Fire id` on every row.
* **Lock-orphan recovery covers `process.exit()` paths only.** The on-exit handler installed by `withAuditLock` reaps the lock dir on Node's normal exit (including `process.exit()`). SIGKILL — and external SIGTERM with no signal handler — does NOT trigger Node's exit event; the lock dir survives, and the next fire burns the 5s mkdir-EEXIST retry budget before throwing. There is no mtime-based lock-reap in `aidlc-lib.ts` today. Mtime-reap deferred to v0.6.0.
* **Type-check sensor attributes diagnostics to the file tsc reports, not the file that introduced the regression.** The wrapper post-filters tsc's whole-project output to errors whose `file` field equals or contains `--file-path`. Cross-file regressions (e.g., a removed export breaking the consumer) report against the consumer file in tsc's output, not against the file that triggered the change. The sensor emits PASS for `<path>` while the consumer file shows the error; the regression surfaces only when the consumer is later edited and re-fired against. Multi-file attribution model deferred to v0.6.0+.
* **Audit event taxonomy is closed by design.** `aidlc-audit.ts` carries a closed `VALID_EVENT_TYPES` Set (61 events) and throws on unknown types. Forks adding custom sensors plug into the existing four `SENSOR_*` event slots (FIRED, PASSED, FAILED, BUDGET_OVERRIDE); fork-defined event names (e.g., `SENSOR_BENCHMARK_REGRESSED`) are NOT v0.5.0 scope. The closure is intentional: open-ended event names break audit grep regexes, doctor-row counts, downstream parser determinism, and the t28 audit-event-sync drift gate. Pull authoring at the manifest/stage level (forks add their own manifest + script and import via `sensors:`) is fully supported within the closed taxonomy. Custom-event-name extensibility revisited in v0.6.0+ if fork pressure surfaces.

* `aidlc-claude-code/.claude/tools/aidlc-sensor.ts` (new) — dispatcher CLI. Subcommands: `list`, `describe <id>`, `fire <id> --stage <slug> --output-path <path>`. Validates inputs + resolves graph + generates Fire id pre-lock (so a malformed stage file fails validation and exits 1 without ever opening a lock — orphan-FIRED prevention). Truth table for outcome decision (branch-a-precedes-branch-0 ordering: timeout-SIGTERM → BUDGET_OVERRIDE before true-spawn-failure → script-error). Detail-file path keyed on Fire id makes collisions a 1-in-4-billion event by construction; `wx`-flag write + `renameSync` retained as defence-in-depth. CLI exits non-zero only on dispatcher invocation errors; sensor outcomes are advisory and always emit a paired terminal row. Subprocess primitive is `node:child_process spawnSync` (matches `aidlc-bolt.ts:84` precedent — Bun's sync return shape doesn't expose `signal === "SIGTERM"` cleanly).
* `aidlc-claude-code/.claude/tools/aidlc-sensor-required-sections.ts` (new) — counts distinct `^## ` headings (dedupe by exact text); pass = (count ≥ 2). Stdout JSON carries `pass`, `h2_count`, `headings`, and `findings_count` (the script computes `max(0, 2 - h2_count)` itself; dispatcher reads the field generically). Dispatcher is sensor-id-agnostic for findings derivation — adding a new framework sensor in v0.6.0 doesn't require a switch arm in the dispatcher.
* `aidlc-claude-code/.claude/tools/aidlc-sensor-upstream-coverage.ts` (new) — case-insensitive word-boundary check for each artifact in `--consumes`, accepting either `\b<slug>\b` literal or `[[<slug>]]` wikilink form. Pass = every consumed artifact appears at least once. `--consumes` empty or absent collapses to `pass=true reason="no upstream"`.
* `aidlc-claude-code/.claude/tools/aidlc-sensor-linter.ts` (new) — wraps `bunx eslint --format json --max-warnings=-1`. Probes config via `bunx eslint --print-config <path>`; on no-config or eslint-unavailable, exits 127 (dispatcher → PASSED Note=tool-unavailable per branch b). `pass = errorCount === 0` only — warnings DO NOT FAIL (real configs ship `no-unused-vars: warn`; warning-as-failure would spam SENSOR_FAILED on every Write under the fan-out).
* `aidlc-claude-code/.claude/tools/aidlc-sensor-type-check.ts` (new) — wraps `bunx tsc --project <tsconfig> --incremental --tsBuildInfoFile <under aidlc-docs/.aidlc-sensors/> --noEmit --pretty false`. `--project` honours the project's actual settings (bare-file `tsc foo.ts` ignores tsconfig and falls back to ES3 defaults — checked-but-meaningless on any real project). Continuation lines (indented related-info) appended to the previous error's `message` rather than dropped (Findings count would otherwise under-report).
* `aidlc-claude-code/.claude/sensors/aidlc-{linter,required-sections,type-check,upstream-coverage}.md` — `command:` rewritten to point at the per-sensor script (e.g., `bun .claude/tools/aidlc-sensor-linter.ts`). The dispatcher reads the manifest, extracts the .ts basename, and resolves it sibling-style to itself (mirrors `aidlc-bolt.ts:84`).
