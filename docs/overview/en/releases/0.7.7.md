## [0.7.7] - 2026-06-15

Makes the "one core, many harnesses" promise literally true at runtime: adding a harness is now one `harness/<name>/` dir + one `manifest.ts` row (+ optional `emit.ts`), with **zero edits to shared code**. Previously the runtime carried two hardcoded harness lists — the harness-dir set and the rules-subdir rename map in `core/tools/aidlc-lib.ts`, plus the packager's `HARNESS_NAMES` — so a genuine 4th harness would have mis-resolved its directory (falling back to `.claude`) and its renamed rules dir. The packager now discovers harnesses by scanning `harness/` for manifests, the harness dir is derived open-set from the shipped layout, and the rules-subdir rename ships per-tree in a new generated `tools/data/harness.json` the runtime reads. No behavior change to the Claude, Kiro, or Codex distributions — every existing tree regenerates byte-identical except for the new descriptor file. Maintainers regenerate (`bun scripts/package.ts`) and re-copy `dist/<harness>/`.

* **New generated file `tools/data/harness.json`** ships in every distribution (`{"harnessDir": ".claude", "rulesSubdir": "rules"}` for Claude, `"steering"` for Kiro, `"aidlc-rules"` for Codex). It is the open-set source of truth for the rules-subdir rename; `package.ts --check` drift-guards it like every other generated file. Never hand-edit it — it regenerates from the harness manifest.
* **`bun scripts/package.ts` now builds whatever harnesses exist under `harness/`** (any dir with a `manifest.ts`), instead of a hardcoded `claude`/`kiro`/`codex` list. A new harness is picked up by the default build and `--check` with no packager edit.
* No CLI surface change; no new commands or flags. The `AIDLC_HARNESS_DIR` / `AIDLC_RULES_SUBDIR` test seams are unchanged.
