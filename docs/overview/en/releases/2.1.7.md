## [2.1.7] - 2026-07-03

Closes the dangling-consume gaps behind the incremental scopes (issue #461). The lean scopes deliberately skip upstream producer stages, but three downstream consumers of the stage `consumes:` contracts did not honor that design: the run-stage directive pointed the executing agent at input files that can never exist (leaving the fallback to per-run improvisation), the upstream-coverage sensor demanded the output prose reference artifacts that were never produced (a guaranteed recurring `SENSOR_FAILED` in six scopes), and nothing distinguished a deliberate scope shortcut from an accidental new dangling edge. Also widens `security-patch` with `requirements-analysis` — the one dangling edge with no in-scope substitute — so a CVE response records an auditable statement of the vulnerability and its remediation criteria. **Upgrade:** re-copy your `dist/<harness>/` shell into the project.

* `security-patch` now includes `requirements-analysis` (10 of 32 stages, was 9). The `requirements` artifact that `nfr-requirements` and `code-generation` hard-require now has an in-scope producer; the scope stays Minimal depth so the requirements pass scales with the patch.
* The run-stage directive splits declared inputs by on-disk presence: `consumes` lists only inputs that exist; a new optional `consumes_absent` field lists the missing REQUIRED ones, each annotated `expected: true` (producer skipped by the active scope — absence is by design) or `expected: false` (producer on the path but the file is missing). Absent optional (`required: false`) inputs are dropped silently — an optional input that does not exist is not a gap. The conductor is instructed to proceed with the stage's documented fallback on expected-absent inputs and to surface unexpected gaps via the recovery protocol, instead of failing a read and improvising.
* The upstream-coverage sensor now checks only consumed artifacts that exist on disk, eliminating the false `SENSOR_FAILED` audit rows the lean scopes produced on every run of a stage whose upstream producer is skipped.
* Stage bodies that read inputs unconditionally (functional-design, nfr-requirements, nfr-design, infrastructure-design, ci-pipeline, deployment-pipeline, deployment-execution, refined-mockups, code-generation) now read each input "(if exists)" with an explicit fallback (requirements, the reverse-engineered code knowledge base, or the workspace's existing configuration), and the recovery protocol gains the producer-is-SKIP branch (re-running the producer is not an option when the scope excludes it).
* The exact per-scope advisory edge set (the deliberate producer-skipped shortcuts) is pinned in the test suite, so a new dangling required consume fails CI as a scope-authoring error instead of hiding among the accepted advisories.
