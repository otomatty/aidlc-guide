## [0.3.11] - 2026-05-19

`aidlc-bolt.ts` worktree subcommands — the per-Bolt lifecycle integration on top of the `aidlc-worktree` primitive, state fork/merge, and audit fork/merge. Three new flag-driven branches mirror the lifecycle's three terminal states: `start --worktree` (delegates to `aidlc-state fork` + `aidlc-audit audit-fork`), `complete --merge` (delegates to `aidlc-state merge` + `aidlc-audit audit-merge`), `abort [--discard]` (third terminal verb, optional worktree tear-down). Atomicity follows the shipped `handleSetAutonomy` precedent: validate inputs FIRST, emit primary audit event AFTER validation, THEN delegate to the state/audit subprocess CLIs which emit their own events inside `withAuditLock`. Failures emit a `BOLT_FAILED` recovery row plus a `{ok:false, slug, stage, reason, detail}` envelope for halt-and-ask consumption. SKILL.md per-Bolt loop is updated to use the new flags as single-call lifecycle boundaries (replaces the separate Step 0.6 / Step 6.8 prose with `aidlc-bolt --worktree`/`--merge` invocations that own the audit + delegate ordering). The three pre-registered `MERGE_DISPATCH_*` events get their emitter wiring at SKILL.md Steps 0 and 6.5 via `bun aidlc-audit.ts append --event MERGE_DISPATCH_* ...` — no new tool code, no new audit registration.

* `bun .claude/tools/aidlc-bolt.ts start --name "<bolt-names>" --batch <n> [--walking-skeleton true|false] [--worktree --slug <kebab-slug>]` — `--worktree` requires `--slug`, rejects csv `--name`. After BOLT_STARTED, spawns `aidlc-state.ts fork --slug <slug>` (emits STATE_FORKED, registers slug in main's Bolt Refs, byte-copies state to `<worktreePath>/aidlc-docs/aidlc-state.md`) then `aidlc-audit.ts audit-fork --slug <slug>` (emits AUDIT_FORKED audit-of-intent, byte-copies main audit). Audit order: `BOLT_STARTED → STATE_FORKED → AUDIT_FORKED`
* `bun .claude/tools/aidlc-bolt.ts complete --name "<bolt-names>" --batch <n> [--merge --slug <kebab-slug>]` — `--merge` requires `--slug`, rejects csv `--name`. After BOLT_COMPLETED, spawns `aidlc-state.ts merge --slug <slug>` (emits STATE_MERGED, removes slug from Bolt Refs, applies per-field merge rule from worktree state) then `aidlc-audit.ts audit-merge --slug <slug>` (emits AUDIT_MERGED, appends post-fork delta from worktree audit). AIDLC metadata consolidates BEFORE SKILL.md Step 6.5's git-merge dispatch
* `bun .claude/tools/aidlc-bolt.ts abort --name "<name>" --slug "<slug>" --reason "<text>" [--discard]` — third terminal verb. Emits BOLT_FAILED with `Reason: aborted` (sub-classifier; no new event type, audit count stays at 55). Default preserves the worktree directory for inspection. With `--discard`, spawns `aidlc-worktree.ts discard --slug <slug>` (audit-of-intent emits WORKTREE_DISCARDED before tear-down) and reports `discarded: true` in the JSON response
* `bun .claude/tools/aidlc-bolt.ts fail` gains optional `--slug <kebab-slug>` for halt-and-ask correlation — `aidlc-worktree info --slug` reads the most-recent WORKTREE_CREATED entry and joins on the slug field downstream
* All three new flag branches print a `{ok: false, slug, stage: "start-worktree"|"complete-merge"|"abort-discard", reason, detail}` envelope on stdout when sub-step delegation fails. Distinct from `aidlc-worktree merge`'s `{status: "conflict", conflict_files, ...}` envelope so halt-and-ask can render different prompts. Subprocess timeouts at 30s match the merge-dispatch budget; on SIGTERM the reason is `*-timeout` rather than `*-failed`
* SKILL.md Construction Flow per-Bolt loop refactored: Step 1 now invokes `aidlc-bolt start --worktree --slug <slug>` as a single tool call replacing the previous Step 0.6 (state-fork) + Step 1 (BOLT_STARTED) split. Step 6 now invokes `aidlc-bolt complete --merge --slug <slug>` replacing the previous Step 6 + Step 6.8 split. Steps 0.6 / 6.8 prose removed (delegation now lives inside `aidlc-bolt`)
* `MERGE_DISPATCH_INVOKED` / `_RETURNED` / `_FALLBACK` events at `audit-format.md:147-149` stay Reserved — emitter assignment deferred. Reason: SKILL.md prose telling the LLM to call `aidlc-audit.ts append` for these events would violate the t48 "no prose audit emission" invariant the project enforces (the LLM under `claude -p` can hallucinate permission policies on prose-directed tool calls; the documented fix is to route emission through a dedicated tool subcommand). A later change owns the per-Bolt orchestrator rewrite and will absorb dispatch instrumentation via a new `aidlc-bolt dispatch-event` (or equivalent) subcommand. Audit count stays at 55 — events were pre-registered, no new registration needed
* `abort --discard` now spawns `aidlc-worktree discard` BEFORE emitting `BOLT_FAILED` (was the reverse). Reason: emit-then-discard left audit + reality divergent on discard timeout — audit said "aborted" while the worktree still existed on disk and the slug remained in main's Bolt Refs. Default-path (no `--discard`) ordering unchanged
* `audit-format.md:113` and `docs/reference/12-state-machine.md:236` BOLT_FAILED rows updated to document the new optional fields (`Bolt slug`, `Reason: aborted`) and the new emitter (`tools/aidlc-bolt.ts abort` alongside `fail`)
* New `tests/unit/t77-bolt-worktree-flags.sh` (28 assertions) — pins atomicity ordering, complete 5-field envelope shape (`ok`, `slug`, `stage`, `reason`, non-empty `detail`), abort sub-classifier, default-abort worktree directory preservation, regression guards on existing no-flag paths
* New `tests/feature/t78-bolt-worktree-lifecycle.sh` (13 assertions) — end-to-end Bolt-with-worktree lifecycle: start --worktree → simulate per-Unit work → complete --merge round-trip with the canonical 6-event audit sequence; abort --discard with real git worktree verifies BOLT_FAILED emit AFTER successful discard AND directory teardown; abort-without-discard preservation; two parallel-batch Bolts (alpha + beta) cleanly round-trip without state interference
* New `tests/fixtures/state-construction-with-worktree.md` (v7 fixture, populated `Bolt Refs: [foo]`) consumed by t77 + t78
* `bun .claude/tools/aidlc-utility.ts version` prints `aidlc 0.3.11`
