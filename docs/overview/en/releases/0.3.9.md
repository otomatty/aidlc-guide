## [0.3.9] - 2026-05-18

Practices-discovery stage at slot 2.2. New Inception stage that discovers a team's branching, walking-skeleton, testing, deployment, and code-style stance from evidence (brownfield) or AskUserQuestion (greenfield), then at an affirmation gate promotes the affirmed content from per-workflow audit trail (`aidlc-docs/inception/practices-discovery/`) into team-authored harness config (`.claude/practices/team.md` + `.claude/rules/aidlc/guardrails/project-guardrails.md`). The cross-row promotion is the structurally distinctive pattern this stage introduces — every other stage writes to one row of the two-axis configuration model; practices-discovery writes both, and the affirmation gate is what makes the cross-row write legitimate. Inception phase grows from 7 stages to 8 stages (slot 2.2 filled). Total stages 31 → 32.

* State fork/merge (no version bump). New `bun .claude/tools/aidlc-state.ts fork --slug <slug>` and `merge --slug <slug>` subcommands isolating per-Bolt state inside Construction worktrees. Fork copies main `aidlc-docs/aidlc-state.md` byte-identically to `<worktreePath>/aidlc-docs/aidlc-state.md`, registers the slug in main's `Bolt Refs`, and emits `STATE_FORKED` (strict audit-first — the audit-of-intent exception at `docs/reference/12-state-machine.md:322` stays bounded to the three `WORKTREE_*` events because state fork is idempotent where `git worktree add` is not). Merge reads the worktree state, applies workflow-level-fields-untouched + alphabetical-slug tiebreak as defence-in-depth, emits `STATE_MERGED` with a `Conflict resolution` audit field, then removes the slug from `Bolt Refs`. Both subcommands validate slug against kebab-case `^[a-z][a-z0-9-]*$` before any path construction (path-traversal guard) and embed `[slug=<slug>]` in error messages for doctor correlation. Idempotent: re-running `merge` for an already-merged slug exits non-zero with `already merged: not in Bolt Refs` and emits no second audit row; re-running `fork` for an already-active slug exits non-zero with `slug already in Bolt Refs` (recovery hint in the message) and emits no phantom STATE_FORKED row. New helpers `parseRefsList` / `emitRefsList` / `appendSlug` / `removeSlug` in `lib.ts` handle the list-shaped `Bolt Refs` value (with `[empty list]` literal placeholder when empty) — `setFieldStrict` is a scalar primitive that cannot append. New `withAuditLock(projectDir, fn)` helper in `lib.ts` — atomic locked-section primitive with a `process.on("exit")` safety net so `process.exit(1)` inside the body still releases the lock dir (Bun's `process.exit` skips `finally`, which would otherwise poison the project for ~5s on the next invocation). New `appendAuditEntryUnlocked(...)` in `aidlc-audit.ts` — the locking variant's body without the lock acquisition, for callers (fork/merge) that already hold the lock via `withAuditLock`; `emitError` detects whether a `withAuditLock` is in flight and uses the unlocked variant accordingly so `ERROR_LOGGED` lands without deadlocking on its own lock acquisition. Bug-fix in same change: `getField`/`setField`/`setFieldStrict` regex tightened from `\s*` to `[ \t]*` so empty-value fields no longer return / replace the next bullet line (latent bug surfaced by `Bolt Refs:` empty default — no caller before read or wrote a legitimately-empty field). New SKILL.md per-Bolt Steps 0.6 (state fork after worktree-create-verify, before BOLT_STARTED) and 6.8 (state merge after worktree-merge-verify). `audit-format.md:125-126` and `docs/reference/12-state-machine.md:281-282` Emitter cells now point at `tools/aidlc-state.ts`. New `tests/unit/t76-state-fork-merge.sh` (16 assertions) pinning the contract — happy round-trip, slug validation, missing worktree dir, v6-state failure, audit-first Parts A+B, workflow-level-untouched, alphabetical-slug tiebreak, idempotency, lock-timeout, concurrent forks, plus three regression tests: B2 (no phantom STATE_FORKED on duplicate fork), B1 (lock dir released even when `errorWithSlug` calls `process.exit` inside the locked block), M1 (audit `Target state hash` matches the actual post-write main state SHA, computed inside the lock against the final merged content). Solo Bolts and parallel batches now run on isolated state files
