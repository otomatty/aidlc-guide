## [2.5.55] - 2026-08-07

Hardens the human-authorization boundary and adds unit-of-work lifecycle receipts, closing the reliability and authorization gaps reported in the brownfield Codex evaluation (issue 681). **Upgrade:** re-copy your `dist/<harness>/` tree into the project; if your CI drives gates against bare fixtures via the audit CLI, set `AIDLC_ALLOW_DIRECT_AUDIT_EVENTS=1` in those runs (the test suite sets it automatically).

* The public audit CLI is now a diagnostic escape hatch only: `aidlc-audit.ts append` / `append-batch` refuse authority-bearing receipts (`HUMAN_TURN`, `GATE_APPROVED`, `GATE_REJECTED`, `QUESTION_ANSWERED`, `REVIEW_REQUESTED`, `REVIEW_COMPLETED`, `SWARM_STARTED`, `SWARM_UNIT_CONVERGED`, `AUTONOMY_MODE_SET`, and the four `UNIT_*` lifecycle receipts) with an error naming the owning tool; `append-raw` refuses taxonomy `**Event**:` lines and line-breaking headings; audit field names use a strict single-line label grammar, closing control-character injection as well as the exact `Event` key.
* `aidlc-bolt.ts set-autonomy --mode autonomous` requires a fresh human turn (the ladder-prompt answer), and one audit lock now covers the presence check, receipt, and state write so concurrent grants consume that turn exactly once; switching back to `gated` needs no presence. The error tells the conductor to ask the human to confirm autonomy in a typed message.
* Human-presence freshness is now shard-aware: a candidate human turn must be provably newer than every latest resolution; when any resolution shares its second-precision timestamp in another audit shard, the gate fails closed and asks for a fresh turn instead of trusting shard filename order.
* Cancellation boilerplate ("Cancelled", "dismissed", "timed out", empty text) is refused as an interview answer (`aidlc-log.ts answer`), an approval choice (`approve --user-input`), and rejection feedback (`reject --feedback`) — a dismissed question widget can no longer mint a `QUESTION_ANSWERED` or commit a gate. A substantive rejection now also requires and consumes a fresh human turn, matching approval.
* New unit-of-work lifecycle receipts on inline per-unit Construction stages: `aidlc-state.ts unit start|pause|resume|complete` emits `UNIT_STARTED` / `UNIT_PAUSED` / `UNIT_RESUMED` / `UNIT_COMPLETED` (event taxonomy 78 → 82). `unit start` accepts safe legacy DAG names, including digit-leading names such as `2fa`, but must match the engine's exact routed stage/Unit pair, so dependencies and earlier same-batch Units cannot be bypassed. Autonomous swarms preserve those legacy Unit identities while deriving deterministic, collision-resistant internal Bolt slugs for worktree operations. A retained autonomy grant no longer blocks receipts after a backward jump to an inline stage; swarm-owned stages still refuse interactive receipts. State-mirrored checkpoint text stays on one line, and every receipt carries an exact stage-attempt `Run floor`; unit-major receipts survive their stage's later start, while workflow/jump/rejection boundaries invalidate them. Cross-shard same-second boundary ambiguity invalidates prior receipts instead of trusting shard filename order, and lifecycle ties preserve a possible pause or other non-terminal state instead of settling or resuming the unit. Receipt mode remains active across attempts, so stale rows cannot restore artifact-only settlement. `unit complete` requires regular artifact files; directories named `*.md` do not count. Once any receipt exists for a stage, the engine requires a receipt per unit.
* Swarm `prepare` now stamps successfully prepared worktrees with the exact stage attempt; failed re-prepares cannot relabel preserved worktrees. `finalize` refuses a stale prepared attempt before merge and carries the captured token into `SWARM_UNIT_CONVERGED`, closing same-second and late-retry convergence replay. In-flight worktrees prepared by the preceding unstamped release remain finalizable when their frozen fork evidence and hash prove they belong to the current attempt; stale or incomplete legacy preparations still fail closed.
* A paused unit hard-stops the engine: `next` emits an ask naming the unit, its recorded `--reason`, and `--next-action` (`unit_state: paused`) until an explicit `unit resume`, and `report --result awaiting-approval` is refused while a unit of the stage is paused. `unit start` refuses while another unit is open (one active unit at a time).
* The state file mirrors the active checkpoint under `## Runtime State` (`Active Unit`, `Unit State`, `Unit Pause Reason`, `Unit Next Action`) so `--status` and session resume land on the exact stopping point.
