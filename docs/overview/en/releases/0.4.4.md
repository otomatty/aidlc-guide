## [0.4.4] - 2026-05-25

Ships the rule-resolution half of the control-plane substrate. `aidlc-graph compile` now walks `.claude/rules/`, resolves the strict-additive chain (org → team → project → phase, where the phase rule's `paths:` glob matches the stage's synthesised artefact path), and bakes a per-stage `rules_in_context` array into every node of `data/stage-graph.json`. Strict-additive runtime: every applicable rule appears in the chain; nothing drops; the `enforcement:` and `overrides:` keywords are removed from the schema. Conflicts (narrower contradicting broader policy) are rejected at admission gates (practices-discovery, memory gate) by section-level LLM check — not at runtime. Compile now runs under `withAuditLock` with atomic temp-rename writes (`writeFileAtomic`); concurrent invocations serialise and crash mid-write leaves consumers reading the previous compile, never a half-written file. Filename regex permits future `aidlc-{team,project}-learnings.md` surfaces. The compile-output schema change drives the version bump; `data/stage-graph.json` grows about 25% (~+6KB on the 32-stage graph).

* `aidlc-claude-code/.claude/tools/aidlc-rule-schema.ts` (new) — sibling of `aidlc-stage-schema.ts`. Parses and validates rule frontmatter (`paths:` string list + `pairing:` scalar — `feedforward-only` or `aidlc-<sensor-id>` shape). Strips a leading UTF-8 BOM (U+FEFF) before matching the `^---\r?\n` anchor — macOS/Windows editors occasionally save markdown with a BOM; without stripping, the file would parse as frontmatter-less and silently drop `paths:` and `pairing:`. Tolerates unknown keys for forward-compat; throws `<file>: <message>` on schema violations.
* `aidlc-claude-code/.claude/tools/aidlc-graph.ts` — `RuleResolution` and `GraphStage.rules_in_context` interface fields; new `loadRules()` walker (anchored filename regex, deterministic `(scope-priority, filename)` sort, `AIDLC_RULES_DIR` env-seam for fixture isolation); new `resolveRulesForStage()` strict-additive chain builder; zero-dep `**`/`*` glob matcher synthesising `aidlc-docs/<phase>/<slug>/` from each stage. `FIELD_ORDER` extends with `rules_in_context` after `outputs`. `compile` write site wraps in `withAuditLock` + `writeFileAtomic`.
* `aidlc-claude-code/.claude/tools/aidlc-lib.ts` — `listField` and `scalarField` promoted from file-private to exported (rule-schema reuses the zero-dep YAML primitives). New `writeFileAtomic(path, data)` helper — temp + POSIX rename, with cleanup of the temp on write failure. `withAuditLock` is now reentrant within a single process for the same `projectDir` — nested calls bump a depth counter rather than self-deadlocking on the OS-level lock (the prior behaviour burned the 5-second mkdir retry budget before throwing). Cross-process locking is unchanged. The signature is also tightened to forbid `async` callbacks (`fn: () => T extends Promise<unknown> ? never : T`) so a future caller can't pass a Promise-returning function and have the lock release before the work settles.
* `aidlc-claude-code/.claude/tools/data/stage-graph.json` — regenerated. Every stage node grows `rules_in_context`; lengths are 3 (org+team+project) on Initialization stages and Construction stages whose synthesised path doesn't match the phase rule's globs, 4 (org+team+project+phase) elsewhere.
* `tests/fixtures/designer-export/export.json` — regenerated. `aidlc-graph export` propagates `rules_in_context` through `.stages[]`; the byte-equal pin in `t66:879` would otherwise drift.
* `tests/feature/t88-compile-rules-in-context.sh` (new) — 16 TAP assertions across 9 fixture sub-directories under `tests/fixtures/v05-mr7a-rule-resolution/` (org-only, org-team-project, phase-paths-match, phase-paths-no-match, phase-no-paths, all-four, pairing-feedforward-only, zero-rules, bom-frontmatter); covers `--check` drift detection on rule-file edits, round-trip determinism, glob-anchor regression (prefix-only globs don't match concrete paths), schema rejection of invalid `pairing` values, and BOM-prefixed frontmatter parsing.
* `tests/feature/t66-graph-library.sh` — eight new cases (74 → 82 tests): `loadGraph()` carries `rules_in_context` as array; `FIELD_ORDER` places it after `outputs`; canonical-emitter pin proves the field populates from `AIDLC_RULES_DIR`; `compile --check` detects rule-file drift via the env-seam; round-trip stability; concurrency wrap (parallel compiles serialise to a byte-equal serial result); `withAuditLock` reentrancy regression guard (nested same-pd is fast and holds the lock throughout outer scope); exit-handler deregistration regression guard (sequential calls don't accumulate listeners).
