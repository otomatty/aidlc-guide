## [0.7.0] - 2026-06-13

**One core, three harnesses.** This consolidating minor closes the dist-unified effort: AI-DLC now ships from a single hand-authored source — a harness-neutral `core/` plus a thin `harness/<name>/` surface per CLI — that `bun scripts/package.ts` regenerates into three committed, drift-guarded distributions: `dist/claude/`, `dist/kiro/`, and `dist/codex/`. The Claude distribution is byte-identical to 0.6.x; Kiro and Codex are now first-class, regenerated from the same core rather than maintained on separate branches. It also closes the version-stream deferral both ports carried ("the real minor settles at unification"). Install by copying `dist/<harness>/` into your project as before — no build step for users; maintainers run the packager and never hand-edit `dist/`.

* **Three harnesses, one install table.** Claude Code (`dist/claude/.claude/`), Kiro CLI (`dist/kiro/.kiro/` + `AGENTS.md`), Codex CLI ≥ 0.139.0 (`dist/codex/`). See the README "Pick your harness" table and `docs/harness-engineering/`.
* **`bun scripts/package.ts`** regenerates all three dists from `core/` + `harness/`; `--check` is the CI drift guard; `codex trust --project <dir>` prints the Codex hook-trust pre-seed. Contributors edit `core/` or `harness/<name>/`, never `dist/`.
* **No user-facing command/flag/behavior change** for existing Claude Code users — `dist/claude/.claude/` is byte-identical to 0.6.x; this release changes where maintainers edit and adds two new harnesses.
* New "porting AIDLC to a new harness" guide in `docs/harness-engineering/`; architecture reference updated for the core/harness/dist split.
