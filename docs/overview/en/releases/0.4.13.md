## [0.4.13] - 2026-05-30

Makes the documentation surface public-GitHub-ready and integrates the shipped v0.5.0 chapters into a coherent book. The docs are now split by reader into three guides — a **User Guide** (build software with AIDLC), a new **Harness Engineer Guide** (reshape how AIDLC behaves through configuration — stages, agents, scopes, rules, sensors, knowledge — without writing code), and the **Developer Reference** (change the AIDLC codebase itself). The Developer Reference is renumbered along conceptual dependency — Plane Architecture moves to the front as the lens, Sensor and Rule chapters sit paired after the agent/hook mechanics, and Runtime Graph follows the State Machine. The stability-policy chapter folds its rename=major/addition=minor rule into the artifact-vocabulary chapter. The User Guide gains v0.5.0 coverage: the Rules and the Learning Loop chapter (with a worked example), user-facing Sensors, the three new CLI tools, a planes orientation, and the runtime-graph artifact. The README header is rewritten and now links all three guides. The first time a Sensor fires in a workspace, a one-line banner points you at the loop chapter. A per-page coherence pass across all three guides reconciled the docs with the shipped v0.5.0 code — agent support matrices, hook counts, stage-count and audit-event totals, the §13 Learnings Ritual / Phase Boundary Verification split, sensor `matches` and prefix semantics, and the scope/stage tables now match the graph and tools. The dead guardrail-learning subsystem is retired in the same pass (audit taxonomy drops to 61 events). No upgrade action required.

* The first time a Sensor fires in a workspace, the `aidlc-sensor-fire` hook prints a one-line first-fire banner (pointing at the Rules and the Learning Loop guide chapter) and drops a `.first-fired` marker so it shows once, not on every fire.
* `docs/reference/` chapters are renumbered: Plane Architecture is now `02`, Sensor System `07`, Rule System `08`, Runtime Graph `13`; `09-testing.md` and `12-state-machine.md` keep their numbers. If you bookmarked reference chapters by number, re-check the links.
* `docs/guide/08-guardrails.md` is renamed to `docs/guide/08-rules-and-the-learning-loop.md` and rewritten for the v0.5.0 strict-additive rule model (org → team → project → phase → stage). The dead `org-guardrails.md` / `project-guardrails.md` / `overrides:` / `enforcement:` model is gone from the guide.
* New `docs/harness-engineering/` **Harness Engineer Guide** (8 chapters) documents reshaping AIDLC through configuration rather than code — anatomy of a stage (surfacing the stage-definition schema), adding a stage, adding an agent, scopes, rules and the learning loop, sensors, and team knowledge. Each chapter links down to the authoritative Developer Reference chapter. The `docs/guide/12-customization.md` "Extending AI-DLC" section now points into this guide, and the README Documentation table lists all three reader guides.
* The stability-policy chapter (`docs/reference/15-stability-policy.md`) is removed; all cross-references are updated.
* The dead guardrail-learning subsystem is retired: the `GUARDRAIL_TRIGGERED` and `GUARDRAIL_LEARNED` audit events, the `aidlc-guardrail.ts` tool, and the stage-protocol §12 governance flow are removed (superseded by the live §13 Learnings Ritual). The audit taxonomy drops from 63 to **61 events**. The separate live `GUARDRAIL_LOADED` doctor event is unaffected, and the word "guardrail" still denotes a Rule throughout the docs. If you grepped audit logs for `GUARDRAIL_TRIGGERED` / `GUARDRAIL_LEARNED`, those rows are no longer emitted.
* Documentation now consistently reports 9 framework hooks (was 7 — adds `aidlc-sensor-fire` and `aidlc-runtime-compile`) and the 61-event audit taxonomy.
* The shipped `.claude/settings.json` now sets `AWS_REGION` (`us-east-1`) — Bedrock requires it and Claude Code does not read it from `~/.aws`. If your Bedrock region isn't `us-east-1`, override `AWS_REGION` in `.claude/settings.local.json` (the example file gains a commented `AWS_REGION`/`AWS_PROFILE` pair). Getting Started gains a full **AWS Bedrock Setup** section (model-access form, IAM policy, credential options, region override, and the `claude` sign-in wizard), linking the AWS quick-setup guide. Install instructions switched to Claude Code's native installer (`curl … claude.ai/install.sh | bash` / `irm … claude.ai/install.ps1 | iex`), with separate Windows PowerShell and CMD blocks.
* `aidlc-claude-code/.claude/tools/aidlc-version.ts` — bumped 0.4.12 → 0.4.13.
