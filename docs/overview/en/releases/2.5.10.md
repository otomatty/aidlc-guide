## [2.5.10] - 2026-07-23

Restores hook firing on Kiro IDE >=1.0.1xx, where the IDE silently stopped executing the legacy `.kiro.hook` format the harness shipped (field-proven on 1.0.165: no `HUMAN_TURN` minting, no `SESSION_STARTED`, no artifact audit rows, no sensor firing). Eight of the nine Kiro IDE hooks now ship in both the legacy format (for pre-1.0 IDE builds) and the IDE's v2 hook schema (for 1.x+); `session-end` stays legacy-only (see below). Coexistence is safe: on pre-1.0 IDEs the v2 files are ignored, on 1.x+ only v2 fires (legacy files appear struck-through and never execute), no double-firing observed on any generation tested. **Upgrade:** copy the tree CONTENTS - `mkdir -p your-project/.kiro && cp -R dist/kiro-ide/.kiro/. your-project/.kiro/` - a plain `cp -r dist/kiro-ide/.kiro your-project/.kiro` nests a second `.kiro` inside your existing `.kiro/` and the IDE never sees the new hooks. Do NOT delete existing `.kiro/hooks/aidlc-*.kiro.hook` files (they serve pre-1.0 IDE builds). Do NOT click the IDE's per-hook "Migrate" button on aidlc hooks (the v2 versions are already shipped; an IDE-generated twin could double-fire).

* Eight Kiro IDE hooks added in v2 schema (`.kiro/hooks/aidlc-*.json`, `{"version":"v1","hooks":[{name,trigger,matcher,action}]}`, PascalCase triggers) alongside the existing legacy files: session-start as `SessionStart` (a real once-per-session event on 1.x; the legacy file keeps its per-prompt behavior on pre-1.0), mint as `UserPromptSubmit`, block as `PreToolUse`, audit-logger as `PostToolUse` matcher `fs_write|str_replace|fs_append`, runtime-compile + sync-statusline as `PostToolUse` matcher `execute_bash`, log-subagent as `PostToolUse` matcher `invoke_sub_agent`, stop as `Stop`. Same adapter targets, same commands; v2 hooks hot-load on current IDEs without a restart.
* `session-end` ships NO v2 registration: the IDE's `Stop` trigger fires at the end of every assistant turn, not at conversation close, so a v2 registration would append a spurious `SESSION_ENDED` between prompts in the same session. It stays legacy-only (pre-1.0 behavior unchanged) until the IDE exposes a genuine session-end event. `SESSION_STARTED` IS emitted on 1.x (via the `SessionStart` trigger); `SESSION_ENDED` is NOT emitted on 1.x.
* The adapter's `log-subagent` target now no-ops with a VISIBLE hook drop when the tool payload is empty (the IDE 1.x case - the payload arrives on stdin, which the adapter does not read): previously it forwarded a real `SUBAGENT_COMPLETED` row with `Agent Type: unknown` and recorded no drop, so `--doctor` could not surface the degradation. A non-empty payload without an identity marker keeps the documented `unknown` fallback.
* The Kiro install commands in the README and harness guides now use content-copy semantics (`mkdir -p` + `cp -R <src>/. <dst>/`) for both `.kiro` and the `aidlc/` workspace shell, on both Kiro trees (CLI and IDE) - the previous `cp -r <src> <dst>` form silently nested the tree inside an existing target directory.
* Known boundary (payload-dependent targets): on IDE 1.x `audit-and-sensors` and `log-subagent` fire but no-op, because 1.x delivers the tool payload on stdin and the adapter reads only the 0.12 `USER_PROMPT` env channel (empty on 1.x). The stdin context channel lands as a follow-up.
* Known boundary (Stop trigger): the IDE's `Stop` trigger cannot block and stdout at exit 0 is ignored (platform limitation). The `aidlc-stop` hook fires for observability/audit purposes only; enforcement of the forwarding-loop contract on this harness relies on the conductor's own Stop protocol, not on the hook's `block` verdict.
* The remaining five hooks (mint, block, session-start, runtime-compile, sync-statusline) are payload-independent and fully functional on IDE 1.x: `SessionStart`/`UserPromptSubmit` stdout IS added to context and `PreToolUse` exit 2 DOES block.
* Kiro CLI (`dist/kiro/`) is unchanged: its hooks ride the agent-JSON `hooks` block, not hook files.
* Docs updated (`docs/guide/harnesses/kiro-ide.md`, `docs/guide/harnesses/kiro-cli.md`, `README.md`, `docs/reference/kiro-ide-hook-payload.md`). No command or flag changes; no breaking change for CI or scripts.
