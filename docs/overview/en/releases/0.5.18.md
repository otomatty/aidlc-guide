## [0.5.18] - 2026-06-04

Adds the runner-skill layer over the engine and moves every framework hook into project-wide `settings.json`. **(1) Stage-runners + `--single`:** a per-stage runner skill for every runnable stage, behind a new engine `--single` mode, so you can run one stage on its own without advancing your main workflow. Each `/aidlc-<stage>` command (e.g. `/aidlc-application-design`, `/aidlc-code-generation`) drives that single stage — the engine emits one run-stage directive and its gate, the conductor runs it, and a synthetic-id record is committed to the audit log. The load-bearing guarantee is tool-enforced: a `--single` run NEVER touches your main workflow's `Current Stage`, and an attempt to advance the main workflow from a single run returns an error. The three bootstrap **initialization** stages get no per-stage runner — they have no standalone meaning (you cannot scaffold half a workspace), so the whole initialization phase is packaged as one `/aidlc-init` command wrapping `/aidlc --init`. **(2) Scope-runners:** a typeable one-word command per scope (`/aidlc-bugfix`) that drives the workflow with a fixed scope and no scope detection — first batch `bugfix`, `feature`, `mvp`, `security-patch`; every other scope stays reachable via `/aidlc --scope <name>`. Both runner families are generated from a single `aidlc-runner-gen.ts` (stage-runners from the compiled stage list, scope-runners over `.claude/scopes/*.md`) and kept in step by drift guards. **(3) The hooks move:** the six workflow-spine hooks (audit-logger, sensor-fire, sync-statusline, runtime-compile, validate-state, log-subagent) plus the `Stop` hook move out of `aidlc/SKILL.md` frontmatter into the project-wide `settings.json` hooks block, joining SessionStart + SessionEnd. Every hook self-gates (it no-ops when no workflow is active), so always-on is safe — and every entry point, including the new runners and any hand-written customer runner, inherits the deterministic spine with no per-runner `hooks:` block. Upgrade action: when you take this version, re-copy the shipped `.claude/settings.json` (or merge its `hooks` block) so the relocated hooks are registered; the `aidlc/SKILL.md` frontmatter no longer carries a `hooks:` block.

* New typeable commands: one `/aidlc-<stage>` per runnable stage (29 — e.g. `/aidlc-functional-design`, `/aidlc-deployment-execution`), each running that stage in isolation and stopping with your main workflow pointer untouched; plus `/aidlc-init`, which runs the whole initialization phase (`/aidlc --init`: scaffold + detect + state-init) in one step.
* New typeable scope commands `/aidlc-bugfix`, `/aidlc-feature`, `/aidlc-mvp`, and `/aidlc-security-patch` run the full workflow with that scope baked in (no scope detection). Every other scope is still reachable via `/aidlc --scope <name>`.
* New engine flow `aidlc-orchestrate next --stage <slug> --single` (emit one run-stage directive for the stage) and `aidlc-orchestrate report --single --stage <slug> --result completed` (commit a synthetic-id STAGE_STARTED/STAGE_COMPLETED pair, audit-only). A `report --single` with no `--stage`, or any single-stage run of an initialization stage, returns an `error` — single runs cannot advance or bootstrap the main workflow (which is why initialization ships as `/aidlc-init`, not per-stage runners).
* New tool `bun .claude/tools/aidlc-runner-gen.ts`: `write` regenerates the 29 stage-runner dirs + the `/aidlc-init` wrapper from the compiled stage list (pruning any stale per-init-stage runner) and `check` is its drift guard asserting the stage-runner set equals the runnable-stage set; `scopes [--all] [--check]` emits/validates scope-runner skills over `.claude/scopes/*.md`; `list` prints the slugs.
* All framework hooks now live in `.claude/settings.json` (project-wide). The six workflow-spine hooks and the `Stop` hook moved out of `aidlc/SKILL.md` frontmatter. Re-copy the shipped `settings.json` hooks block when you upgrade; without it the relocated hooks will not fire.
* Extensibility: to add a stage, write a stage file and recompile — the stage is immediately runnable via `/aidlc --stage <slug> --single`; a dedicated `/aidlc-<slug>` runner is optional sugar you regenerate with `aidlc-runner-gen write`. See `docs/harness-engineering/02-adding-a-stage.md`.
