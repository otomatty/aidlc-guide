## [0.7.5] - 2026-06-15

Makes the Kiro conductor reliably obey backward-jump directives. On Kiro, `/aidlc --phase <earlier-phase>` (and `--stage`) from mid-workflow would intermittently run the *forward* stage instead of the jump: the conductor re-ran the engine with the user's flag dropped, or skipped the jump command the engine's `print` directive named, and the workflow advanced to the wrong stage. Root cause was a delivery gap, not the engine or the model — Kiro's conductor decided its move without the forwarding-loop contract reliably in context (the orchestrator `SKILL.md` is a lazy `skill://` resource on Kiro, where Claude's skill loader injects it deterministically). The fix moves the forwarding discipline into channels guaranteed to be in context. Re-copy your `dist/<harness>/` to pick it up.

* **The session-start hook now injects the forwarding-loop contract** (all harnesses): the engine owns all routing; the user's original arguments go on the FIRST `next` verbatim — never drop `--phase`/`--stage`; and when a `print` directive names a command to run (a jump `execute`, scope/config change, or `init`), that exact command is the immediate next action — do not re-run `next` or read files before it. Harmless and correct on Claude/Codex (which already carry these rules via their skill loaders); load-bearing on Kiro. The hook still only fires when an AIDLC workflow is active.
* **The Kiro conductor agent (`aidlc.json`) prompt is hardened** with the same first-call-verbatim-args and run-the-named-command-first invariants.
* **Cross-harness `SKILL.md` parity:** Kiro's orchestrator `print`-directive row regains the "the mutation lives in the named tool, never in `next`; act on its instruction rather than improvising the routing" clause that Claude and Codex already carried.
* No CLI surface change; no new commands or flags.
