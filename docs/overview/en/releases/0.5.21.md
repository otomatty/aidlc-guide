## [0.5.21] - 2026-06-06

Wires the swarm live: the engine now emits an `invoke-swarm` directive and the conductor acts on it natively, so an eligible Construction batch fans out automatically once a human grants autonomy at the walking-skeleton ladder. When a Construction workflow is at the per-unit build stage (code-generation) with `Construction Autonomy Mode: autonomous` and an eligible batch is ready on the compiled `bolt_dag`, the engine answers with `invoke-swarm` naming that batch; the conductor — the live `/aidlc` session — fans the batch out in-session (N parallel `Task` calls by default, or an inline Dynamic Workflow when `AIDLC_USE_SWARM=1`), consults the `aidlc-swarm.ts` referee (`prepare` / `check` / `finalize`) for the convergence verdict, and on the tool's failure envelope (exit 2) takes the baton back and re-engages the human — the swarm never escapes the conductor. The three previously-reserved batch-level swarm audit events now emit from the deterministic referee. `invoke-swarm` is an orthogonal directive kind beside the stage `mode` enum — it does NOT activate the reserved `agent-team` mode, which stays reserved. No upgrade action.

* The engine emits `invoke-swarm` for an eligible Construction batch under an `autonomous` grant; with a gated or unset autonomy mode it keeps emitting a normal `run-stage`, so nothing fans out until you grant autonomy after the walking skeleton ships.
* On an `invoke-swarm` directive the conductor owns the fan-out and the retry loop in-session — N parallel `Task` calls (the floor) or an inline Dynamic Workflow (`AIDLC_USE_SWARM=1`) — and consults the `aidlc-swarm.ts` referee for the verdict: `prepare` forks the worktrees, `check <unit>` reports per-unit convergence (exit 0 = genuine), and `finalize --claimed` re-verifies + merges the genuine passes. `finalize` exit 0 means the batch converged and merged (the loop continues); exit 2 means a unit failed or a merge failed and the conductor takes the baton — it halts and asks the human via the existing halt-and-ask seam, regardless of autonomy mode.
* The three batch-level swarm audit events now emit from `aidlc-swarm.ts`: `SWARM_STARTED` (`prepare` forks the batch), `SWARM_BATON_RETURNED` (one per failed unit, naming the unit and its typed reason), and `SWARM_COMPLETED` (batch closed, with the converged/failed tally). All six swarm events now have a real emitter; the taxonomy count is unchanged from v0.5.20 (which introduced `SWARM_DEGRADED`).
* A human may optionally type `/goal` at the autonomy grant to run the batch until a condition holds (e.g. the referee reports all units converged) — Claude Code's built-in run-until-a-condition loop. `/goal`'s judge reads the transcript and never runs the check itself, so the referee's `finalize` exit code stays the sole convergence verdict; `/goal` is a human overlay, not part of the framework's machinery.
