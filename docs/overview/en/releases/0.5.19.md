## [0.5.19] - 2026-06-06

Makes the unit dependency graph machine-readable end-to-end, the first step toward the headless build swarm. The units-generation stage (Inception 2.7) now requires a fenced `yaml` `units:` edge block on `unit-of-work-dependency.md` beside the existing prose, and `aidlc-runtime compile` parses that structured data into a `bolt_dag` node on `runtime-graph.json` — a deterministic batch DAG (topological levels of units with no mutual dependency) with no model in the compile path, so a re-compile stays byte-identical. Nothing in your workflow invokes the swarm yet; this release only lays the deterministic batch shape it will read. No upgrade action — an existing workflow simply re-runs 2.7 (or the conductor adds the block) before a batch is computed.

* Stage 2.7 (units-generation) now expects a required fenced `yaml` `units: [{name, depends_on: [...]}]` block on `unit-of-work-dependency.md`. The `required-sections` sensor validates it at the 2.7 gate and reports `edge_block` as `ok`, `absent`, `malformed`, or `cyclic` — a malformed or cyclic block fails the sensor there, upstream, instead of being silently mis-read later.
* `bun .claude/tools/aidlc-runtime.ts compile` emits a new optional `bolt_dag` node (`{units, batches}`) on `runtime-graph.json` when that block is present and valid; an absent, malformed, or cyclic block omits the node and writes a stderr diagnostic naming the reason, leaving the rest of the envelope unchanged.
