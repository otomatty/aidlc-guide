## [2.5.44] - 2026-08-06

Human-readable AI-DLC artifacts now follow the conversation language instead of defaulting to English. The framework rule layer gains four `## Mandated` rules in `org.md` that define how the conversation language is resolved, why it stays stable across short turns like `Approve`, which artifacts are localized, and which protocol tokens stay English. The rules travel to delegated agents and reviewers inside the active-stage rule bundle the dispatch-rules hook already delivers, so a subagent that never sees the conversation can still resolve the language from the rule layer, `aidlc-state.md`, or the upstream artifacts it consumes. **Upgrade:** fresh installs receive the rules with their seeded `default` space. An existing workspace keeps its own memory tree — runtime self-healing intentionally does not overwrite one — so merge the four rules into each `aidlc/spaces/<space>/memory/org.md` by hand and start a fresh session for them to load.

* Human-readable artifacts (requirements, user stories, plans, specs, reviews, questions, discovered practices, affirmed rules, evidence, decision rationale) are written in the workflow's established conversation language, including the descriptive text of a rule shaped as `ALWAYS …` / `NEVER …`.
* The conversation language is resolved in a fixed order — the `Conversation language:` line the orchestrator is now required to state in every delegated brief, then an explicit language rule in `project.md` — the only file a language switch is ever persisted to, and one that always outranks a `team.md` default, because the runtime rule chain concatenates `org → team → project → phase` and so bundle position is not recency: a newer team-level rule reaches an agent *before* a staler project-level one, and the winner is the stated precedence rather than the later position — then the verbatim `**Project**` description in `aidlc-state.md`, then any artifact or draft the agent was handed (the directive's `consumes[]` contracts, the artifact under review, or the lead draft it was dispatched against). The brief line ranks first because the orchestrator regenerates it from the live conversation on every dispatch, so it can never be staler than a rule already on disk. It is also mandatory because the file-reading sources can all be empty: a greenfield run of a stage whose `consumes` are every one `conditional_on: brownfield` reaches its dispatched lead with no upstream artifact at all.
* The language is stable: a turn carrying no language signal (`Approve`, `Looks correct`, an option letter or number, pasted code, a quoted error or stack trace, a bare path) never switches it. Only an explicit human request does, and that switch takes effect immediately — the orchestrator carries the new language in every subsequent brief. Recording it under `## Corrections` in `project.md` (never `team.md`) is durability, not activation, so nothing waits on the human-gated learnings ritual — and that ritual is the only sanctioned write path for persisting a language switch, so agents never hand-edit a memory file to record one, while the deterministic memory writers a stage invokes by contract (such as `aidlc-state.ts practices-promote`) are unaffected. A declined persistence is a correct outcome: the brief carries the language for the rest of the session. A persisted rule never outranks the brief or a later explicit switch request — it is the fallback for a brief that states no language — and because the learnings write path appends rather than replaces, the last conversation-language rule under `## Corrections` in `project.md` is the current one.
* That stability guarantee is scoped to the session, which is as far as the brief line can carry an unpersisted switch. A workflow outlives a session, and the resume context injected at session start carries scope, phase, stage, status, agent and next action but no language, so the first turn of a new session re-resolves the language before dispatching anything: the persisted rule, else the human-readable artifacts the workflow has already produced, else the verbatim initial description — and it asks the human rather than defaulting to English when all of those are silent. Re-resolving is not a switch, and is never announced or persisted as one. Accepting the learnings ritual is therefore what makes a switch survive a resume.
* The English exception is now scoped to machine-parsed syntax rather than whole files, and states a general principle: a literal a stage file spells in backticks and tells you to write exactly is a fixed token — including option labels and sentinel values, not just syntax. Named instances cover `[Answer]:` tags and the mandatory `X. Other (please specify)` option, the `A. Accept assumptions` / `B. Convert to follow-up questions` confirmation answers the engine compares literally, the `None.`/`None` sentinels, `AGREE:`/`OBJECT:` prefixes, the `**Collaborator:** <agent-slug>` first line the engine matches exactly on a contribution file, the `[desc]`/`[scope]`/`[assumption]`/`[Q<n>]`/`[memory:M<n>]` source-register tags, template H2 headings the sensors match verbatim, the `READY`/`NOT-READY` verdicts, fenced YAML keys and enums, `aidlc-state.md` and audit-shard field labels, stable IDs, code, paths, mermaid keywords, and cross-references. Glossing a literal when presenting it to a human is allowed; what is written into an artifact is the literal. Prose surrounding a preserved token is localized, and a Markdown artifact is no longer treated as English just because a tool parses part of it.
