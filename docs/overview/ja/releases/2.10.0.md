# aidlc-workflows 2.10.0

[更新履歴一覧](../changelog.md) · [改善点の日本語ガイド](../release-highlights.md)

## [2.10.0] - 2026-09-24

AI-DLC 2.10.0は2.9.0以降の変更をまとめたリリースです。会話の文脈を使うAIDAレビュー、Constructionでの人間の決定権と復旧、複数ハーネスの共存を追加し、プロバイダー・worktree・フック・センサー・ステージの振り分けを修正しました。更新は `aidlc update` の後、各プロジェクトで `aidlc config --yes` を実行します。手動コピーでは `aidlc-copy-runtime-2.10.0.tar.gz` の `runtime/<harness>/` 全体を置き換えます。

- Claude Code、Codex CLI、GitHub Copilot、Cursor、Kiro CLI、Kiro IDE、opencodeの `aidlc version` が `2.10.0` を表示します。
- AIDAのPRワークフローは、会話を考慮した複数モデルのレビュー、セキュリティの根拠、観点別の差分レビュー、指摘台帳、メンテナーコマンド、重大度に基づく次の操作、公開内容の決定的検証に対応しました。Issue分析にも意図・方向性のレビュー、ラベル、運用者向けの要約を追加しました。
- Constructionのレビューは、検証済みのUnit・バッチのチェックポイントで行います。人間が決めるゲートとエージェントの実行範囲を一貫して守り、復旧メッセージに実行可能な次の手順を示します。
- 設定が衝突しない複数ハーネスを同じプロジェクトで利用できます。共通の導入案内と各ハーネスの設定を分離しました。Amazon Bedrockを明示的に選ばない限り、現在のプロバイダーを維持します。
- Boltのブランチ・参照・worktreeをIntent別に分けました。保留した試行は元のバイト列で復元します。ConstructionとCodeKBは、リンクされたGit worktreeから正しいプロジェクトを解決します。
- フックとステージのツールで、ネイティブ実行の振り分け、Kiro IDEの委譲、Windowsパス、レビュアー委譲の記録、要約質問の検出、ゲート回答の解析、主張の根拠照合、構成したスコープの永続化を修正しました。
- 廃止した `--init`・`--force` がIntentの説明へ混入しなくなりました。`intent-create` は未知の位置引数を拒否します。よくある拒否メッセージに、受理する値や具体的な復旧操作を示します。
- 安定版の公開では、タグ付きコミットに対する独立したFull Suite成功証跡を必須としなくなりました。タグ・ソースの検証、決定的なパッケージ生成、静的検査、ネイティブ版のスモークテスト、複数OSのビルド、導入ライフサイクルのテスト、チェックサム、来歴の証明、リリース候補の検証は引き続き必須です。
