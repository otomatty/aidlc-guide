## [2.9.0] - 2026-09-15

AI-DLC 2.9.0 は、2.8.2 以降の利用者向けの変更をまとめたリリースです。Classic scope v1 の手続き設定、コミット来歴、インテントのアーカイブ、Construction の自律実行の随時切り替え、レビューループの修正、ネイティブ版のプレビュー配布を含みます。**更新手順:** `aidlc update` の後、各プロジェクトで `aidlc config --yes` を実行し、ハーネスのランタイムを更新してください。手動コピーでは `aidlc-copy-runtime-2.9.0.tar.gz` の `runtime/<harness>/` ツリー全体を置き換えます。進行中の Classic インテントは記録済みのステージグラフを維持します。以下に示す新しい手続きの既定値は、該当する設定へ直ちに適用されます。

* Claude Code、Codex CLI、GitHub Copilot、Cursor、Kiro CLI、Kiro IDE、opencode の `aidlc version` が `2.9.0` を返します。
* 新規の Classic インテントは、Build and Test までの 18 ステージで進みます。各ステージの承認は 1 回、レビューを設定した箇所では advisory レビューが 1 回です。Sensors と Learnings は有効、Summary Confirmation は無効です。既存の Classic インテントは記録済みのグラフを維持します。従来の CI Pipeline と Operation を含むグラフが必要なら `workshop` を使ってください。
* 手続きの既定値はスコープが持ち、インテントごとに `--sensors`、`--learnings`、`--summary-confirmation` で変更できます。`aidlc engine config set` は、深さ・テスト・レビュー・Change Control・手続き設定を 1 トランザクションで適用します。**スクリプトの互換性に注意:** 単独の `aidlc-utility.ts change-control` 経路は削除され、`config-change` の未知のフラグは無視されずエラーになります。
* `aidlc config` はハーネスごとにプロバイダーを扱います。Kiro CLI / IDE は Kiro がモデルへのアクセスを提供するため、初回ウィザードや `aidlc config providers` で回答を求めず、プロバイダーフラグも拒否します。旧版の設定記録は無視します。削除する場合は `aidlc config providers --reset --yes` を使います。更新時も `.kiro/settings/mcp.json` の `aws-mcp` リージョンはプロジェクトの値を保持します。他のハーネスでは Amazon Bedrock または現在の設定を保つ `unchanged` を選べます。`balanced` プリセットは deciding・reviewing・writing-up の effort をすべて medium として記録します。
* `aidlc engine orchestrate wait` は、共同作業者・成果物・レビューを、状態を変更せずに時間を区切って待ちます。レコード内のエンジン用ファイルは `<record>/.aidlc-engine/` へ移り、既存レコードは旧パスへのフォールバックで引き続き読めます。
* `/aidlc intent archive <name>` は、記録や監査ログを消さずに未完了のインテントをアーカイブします。`/aidlc intent unarchive <name>` で戻せます。`intent list --all` はアーカイブ済みも表示します。
* `aidlc attest resolve` はコミットまたは差分範囲をレビュー済み Unit と照合し、`verified`、`drifted`、`unattested`、`unverifiable`、`indeterminate`、`excluded` に分類します。`aidlc attest anchor` は監査ログへコミットの参照を記録します。2.9.0 より前のレビューにはコミット済みのソース証拠がないため、次の Unit ごとのレビューまで `unverifiable` になります。
* Construction の自律実行は随時許可・取り消しできます。該当フィールドがない古い記録でも選択を保存します。最初の Construction 承認、Code Generation Plan Approval、失敗時の停止は引き続き人間が判断します。
* ゲートで却下された後の advisory レビュー再試行は、エンジンの現在の通し番号を使い、誤った `REVIEW_BUDGET_EXHAUSTED` による行き詰まりを防ぎます。レビューの管理情報はレビュー記録と監査データに保持し、成果物本文や新たなレビュー指摘には含めません。
* Kiro IDE の Code Generation Plan Approval 復旧中も読み取りツールを利用できます。書き込み・シェル・MCP・委任を介した変更は引き続き保護されます。
* 安定版・プレビュー版の配布物を、ネイティブ版 `aidlc-runtime-2.9.0.tar.gz` と Bun ベースの手動コピー版 `aidlc-copy-runtime-2.9.0.tar.gz` に分離しました。版付きのインストーラーはプレビューを含め自身と同じリリースを導入します。同じ UTC 日付でも、変更のある複数の `main` コミットからプレビューを公開できます。
* リポジトリの管理者は、同一リポジトリの PR に対して adversarial AI レビューワークフローを実行できます。プロンプトインジェクション・セキュリティ・プロジェクトの方針に沿ったレビューと、投稿内容の決定的な検証を行います。
