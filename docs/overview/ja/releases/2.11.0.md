# aidlc-workflows 2.11.0

[更新履歴一覧](../changelog.md) · [改善点の日本語ガイド](../release-highlights.md)

## [2.11.0] - 2026-10-08

AI-DLC 2.11.0 は、2.10.0 以降にマージされた利用者に見える変更をまとめたリリースです。主な変更は次のとおりです。

- どのチャットからでも返答を読み取り、本人の言葉のまま記録します。
- 依頼はその場で実行し、元に戻す方法を添えます。
- Plan Approval はエンジンが尋ねます。
- 計画が変わっても Construction の完了済み Unit の作業は残ります。
- スコープの既定値を軽くしました。
- 設定は進行中の作業と並行して実行でき、チームのファイルを保持します。
- 許可を求める確認を大幅に減らしました。
- ツールのフックが一度も動かないときは、必要な手順を名指しします。
- すべてのハーネスで修正を行いました。

**更新方法:**

- `aidlc update` を実行してから、各プロジェクトで `aidlc config --yes` を実行し、ハーネスのランタイムを更新します。
- 複数のハーネスがあるプロジェクトでは、ハーネスごとに `aidlc config --harness <name> --yes` を実行します。
- 進行中の作業は更新の後もそのまま続きます。
- 手動コピーの利用者は、`aidlc-copy-runtime-2.11.0.tar.gz` の `runtime/<harness>/` ツリー全体を置き換えてください。手動コピーには Bun 1.3.8 以降が必要になりました。

**既存のインテントの扱い:**

- 記録済みの Guard Policy・センサー・学習・要約の確認は、そのまま保持します。
- 一方、Plan Approval と Collaborators はこれまで記録されていなかったため、スコープの新しい既定値に従います。
- そのため `enterprise` 以外では、進行中のインテントの残りのステージも主担当エージェントだけで進みます。支援エージェントが必要なら `/aidlc --collaborators on` と入力してください。

* Claude Code、Codex CLI、GitHub Copilot、Cursor、Kiro CLI、Kiro IDE、opencode の `aidlc version` が `2.11.0` を表示します。
* `enterprise` を除くすべての同梱スコープで、新しい作業が軽く始まります。
  * 承認後の変更は一度伝えるだけで実行が続き、書き込みのたびに「保留した」旨の行を出すことはありません。
  * 各ステージは主担当エージェントだけで進みます。`/aidlc --collaborators on` を指定すると、その作業でだけ支援エージェントが戻ります。
  * 各コード計画を承認のために示すかどうかは `/aidlc --plan-approval on|off` で設定します（off にできるのは本人だけです）。`express` と `poc` は off で出荷されます。
  * `bugfix` は学習の質問も要約の確認も求めなくなりました。
  * 承認ゲートと人間の操作の確認は変わりません。
* Plan Approval はエンジンが尋ねるようになり、計画のフィンガープリントもエンジンが保持します。
  * 承認済みの計画を尋ねるのは一度だけです。チャットが圧縮された後も、作業を保留した後も、ステージの規則が分割して届いた場合も同じです。
  * 計画の承認を待つ間に止まるのはビルドだけです。レビュー、設定、コミットなどの小さな依頼はその間も実行され、承認の質問は開いたまま残ります。
  * ビルド前に承認済みの計画やそのテスト手順が変わった場合は、何が変わったかを本人に伝えます。本人は「承認済みの計画に戻して」と言えます。
* すべての質問（ステージゲート、要約の確認、Unit チェックポイント、ガードの質問）で、返答を本人の言葉どおりに読み取ります。
  * 「approved」、番号、「問題ないがハンドラーの名前を変えて」のような返答は、それぞれ書かれたとおりに扱われ、記録された回答には本人が書いた内容が残ります。
  * 質問にはどのチャットからでも答えられます。Claude Code や Codex の質問ボックスでの選択はそのまま記録され、一つのボックスで複数の質問に答えられます。
  * 記録済みの返答を再び求めることはありません。「どの方法で回答しますか？」の質問も、一つの作業につき一度だけです。
* 新しいセッションで `/aidlc` だけを入力すると、Resume / Redo / Jump / Start Fresh のメニューを出さずに進行中の作業を続けます。新しく clone した場合は、コミット済みの作業を名指しし、一度の返答で引き継ぎます。
* 本人の依頼はその場で実行し、元に戻す方法を一行で示します。対象は次のとおりです。
  * `/aidlc --skip <stage>` と `--add <stage>`
  * スコープの変更
  * チャットで伝えた Construction の設定（「チェックポイントをオフに」「Unit を一つずつビルドして」など）
  * 保留中の作業に対して入力した設定
* 新しい作業と一緒に入力した設定は、本人が選んだ作業に適用されます。返答は画面上の質問にだけ答え、依頼の中のフラグのような語（「--version フラグを追加して」など）は依頼の一部として扱われます。
* Construction は完了済みの作業を保持します。
  * 次の操作をしても、完了済みの Unit は完了のままです: スコープの変更、Unit を一つずつ進める方式とステージ単位で進める方式の切り替え、チェックポイントのオン・オフ、ジャンプ、一つの Unit のステップのやり直し。
  * 後戻りのジャンプでは、本人が指定したものだけをやり直します。
  * 承認済みの Unit は新しい clone でも承認済みのまま残り、中断したビルドは止まった所から再開します。
  * 完了しなかったレビューを越えて承認できます（`Approved. The <Stage> review did not finish.`）。ただし、チームのメモリーで Guard Policy が strict に固定されている場合は除きます。
  * Unit チェックポイントをオフにして Unit を一つずつビルドする場合、最後の Unit の後に必要な Unit ごとのステージ承認は、一つの質問でまとめて確認します。
* 構成した計画は、その作業に属するようになりました。
  * 再利用できるスコープとして残すには、ゲートで **Approve and save as scope** を選ぶか、後から「この計画を quick-fix として保存して」と伝えます。
  * 計画の提案は短くなり、ステージ表とスコアは求めに応じて表示します。一覧の各計画には、エンジン自身が数えたステージ数を示します。
  * 調整した計画はゲートで表示した名前を保持し、カスタム計画は `classic` の設定を基に Guard Policy `off` で始まります。
  * `bugfix` と `security-patch` では、本人が別のスコープを指定しない限り、コードの調査結果レポートを計画に含めます。
* `/aidlc --project-type <greenfield|brownfield>` で、新規プロジェクトか既存コードかを指定できます。
  * 作業の途中で入力しても、言葉で伝えても、再スキャンを行い、既存コードなら Reverse Engineering を実行します。
  * 新規プロジェクトのフォルダーに Construction より前にコードが加わった場合は、一度だけ確認します。
* そのほかの変更は次のとおりです。
  * 本人が名前を挙げた PDF や Word ファイルは、移動を求めずに取り込みます。
  * `/aidlc --status` は、プロジェクトの種類、深さ、ほかの進行中の作業、誰かがオフにしたチェックだけを表示します。
  * Requirements Analysis は、各コンポーネントをコーナーケースのチェックリストと照合します。
  * Reverse Engineering は .NET の `bin/` と `obj/` の出力を読みません。
* ツールが AI-DLC のフックを一つも実行しないときは、最初のメッセージで止まり、そのツール固有の手順をそのツールの言葉で示します。これまでは、承認が記録されないまま進んでいました。各ツールの手順は次のとおりです。
  * Codex: `/hooks` と入力してすべてを信頼する
  * VS Code: そのフォルダーで Chat: Use Hooks をオンにする
  * Kiro CLI: `/agent` と入力して aidlc を選ぶ
  * Kiro IDE: フォルダーを信頼してウィンドウを再読み込みする

  setup と doctor も同じ手順を示します。Copilot のチャットでは、フックが一度も動いていないことを知らせます。
* 許可の確認と、エージェントの読み書きも変わりました。
  * Claude Code、Cursor、VS Code の GitHub Copilot、Kiro CLI、Kiro IDE では、AI-DLC 自身のワークフローコマンドを許可の確認や承認カードなしで実行します。
  * マシンの AI-DLC のインストールを変更するコマンドは、引き続き事前に確認します。
  * エージェントはファイル操作をファイル用のツールで行います。
  * `date -u` や監査ファイルを手で読む代わりに、読み取り専用の `aidlc engine now`、`aidlc engine log answers --stage <slug>`、`aidlc engine audit history` を使います。
* 作業が進行中でも、`aidlc config` の実行は拒否されずに実行されるようになりました。
  * 更新、ハーネスの追加、ピン留め、設定の変更では、変わった内容とその戻し方を表示します。更新の最後には `Updated. Your open work (<name>) carries on.` と表示します。
  * `--download` を付けると、config コマンドがプロジェクトに必要なリリースを正確に取得します（ネイティブ導入の場合はそのリリース、コピーしたプロジェクトでは `aidlc-copy-runtime-<version>.tar.gz`）。チェックサムを検証し、`gh` がインストールされていればアテステーションも検証します。
  * `aidlc config --show` は、何も変更せずにすべての節を表示します。更新では削除したファイルも一覧にします。
  * config と doctor（`Harness trees on different releases`）は、別のリリースのままになっているハーネスのツリーを名指しし、揃えるためのコマンドを示します。
* 更新はチームのファイルを保持します。
  * `.claude/settings.json` は、プロジェクトのフック、許可設定、`statusLine` を保持します。
  * Codex の更新では、`.codex/config.toml` の AI-DLC のキーだけを変更します。`opencode.json` には AI-DLC の項目だけを追加します。
  * `.gitignore` の AI-DLC の部分は、チームの規則の後に置く一つの `# AI-DLC: local working files` ブロックになりました。
  * Windows の改行コードの clone で config の競合が報告されなくなりました。バイトオーダーマーク付きで保存した設定ファイルでも `aidlc config` は止まりません。
  * コピー用アーカイブには、`.gitignore`、`AGENTS.md`、`opencode.json`、Claude Code の `.mcp.json`（コピーは MCP サーバーなしで始まります）、Copilot の `.vscode/settings.json`、チームのメモリーファイル、`aidlc/active-space` が含まれなくなりました。そのため、新しいリリースをプロジェクトにコピーしても、これらは保持されます。
* `aidlc update` とインストール管理の変更は次のとおりです。
  * 単に `aidlc update` を実行しても、実行中のものより古いリリースはインストールしません。安定版のマシンで新しいプレビュー版を実行している場合は何も変更せず、`aidlc update --channel stable` と `aidlc config --channel preview` の両方の進め方を示します。
  * `gh` がインストールされていても更新の確認は速いままです。`gh` が既定で Enterprise ホストを使う設定でも、リリースの検証には `github.com` を使います。
  * 端末上で `aidlc uninstall` と `aidlc system versions prune` を実行すると、削除する対象を示し、`[y/N]` を尋ねずに進めます。端末がない場合は、引き続き `--yes` が必要です。
  * Windows では、拡張子のない `bin\aidlc` ランチャーにより、Git Bash から `aidlc` を見つけられます。2.10.0 に戻したマシンも、再び新しいバージョンに切り替えられます。
  * 停止したコマンドが残したロックは、その PID が再利用されていても解除されます。ハードリンクを使えないマウントでもトランザクションのロックが動作します。
  * Bolt の worktree は、サブモジュールのあるリポジトリでも、Windows の `MAX_PATH` の制限を超えても動作します。
* Kiro では、`kiro-ide` のインストールが一つの `.kiro/` ツリーで Kiro IDE 1.x と Kiro CLI の v3 エンジンの両方に対応しました。
  * Kiro IDE 1.1.70 以降、または Kiro CLI 2.24.1 以降が必要です（`kiro` のインストールは引き続き Kiro CLI 2.6 以降が必要です）。
  * `aidlc config --harness kiro-ide`（または `--harness kiro`）で、Kiro のプロジェクトを二つのインストールの間でその場で切り替えられます。
* Kiro CLI での変更は次のとおりです。
  * setup はセッションのモデルを尋ね、プリセットの effort とともに個人の Kiro 設定に保存します（`aidlc config models --session-model <id>` を使うと、確認なしで設定できます）。
  * ネイティブ導入でも `/aidlc --doctor`、`--version`、`--help` が動作します。
  * 別のエージェントに入力した返答に対しては、戻る方法として `/agent` と aidlc を示します。
* Kiro IDE での変更は次のとおりです。
  * 初回の実行で、フォルダーの信頼、ウィンドウの再読み込み、aidlc エージェントの選択を順に案内します。
  * Kiro のメニューが `/aidlc` だけの入力を専門エージェントに変えても、AI-DLC が始まります。
  * AI-DLC 自身のコマンドは承認カードなしで実行します。
  * フックのカードは、ツール呼び出しの前に一つ、シェルコマンドの後に一つに減りました。読み取りでは表示しません。
* Codex CLI での変更は次のとおりです。
  * 起動のたびに「Under-development features enabled」と警告されなくなりました。
  * setup、doctor、フック未実行での停止は、Codex 自身の信頼の手順を示します（`/hooks` と入力し、`t` ですべてを信頼してから Esc）。AI-DLC があらかじめ設定するフックの信頼も、Codex が確認する内容と一致するようになりました。
  * 返答と拒否では、`/aidlc` ではなく `$aidlc` を示します。
  * 時間切れになった質問ボックスが、本人の代わりに答えることはありません。
  * 別のツールと共有しているプロジェクトでは、Codex 自身のインストールを使います。
* opencode での変更は次のとおりです。
  * setup と更新では、チームの `opencode.json` に AI-DLC の項目だけを追加します。
  * ターン終了時の促しと `/aidlc` コマンドの本文が、本人の発言としてチャットに表示されなくなりました。
  * 拒否されたコマンドでターンが終わります。
  * 引用符や改行を含む依頼を貼り付けても、どのシェルでも作業が始まります。
* GitHub Copilot での変更は次のとおりです。
  * VS Code で、AI-DLC 自身のコマンドを Allow のクリックなしで実行します。
  * 各ステップの結果が、VS Code の端末結果の上限である 20,000 文字に収まります。
  * Windows のプロジェクトは、VS Code の二通りのドライブ文字の表記をまたいでも続きます。
  * 承認の後にチャットが先へ進みます。
  * ステージランナーは、本人が入力したときにだけ始まります。
* Cursor での変更は次のとおりです。
  * 本人のプロンプトを捨てることがなくなりました。
  * チャットがどの作業を扱っているかを一度だけ伝えます。
  * プロジェクトが git リポジトリの外にある場合はそう伝えます。
  * バックグラウンドのエージェントを前面のワークフローから切り離します。
* Claude Code では、生成されたステージランナーとスコープランナーは入力したときにだけ始まります。新しいチャットは、セッション開始時に作業の状態と、作業に戻るかどうかの提案を受け取ります。
* 長い実行で扱う量が減りました。
  * Claude Code、Codex CLI、Kiro CLI、Kiro IDE、opencode では、チャットがすでに持っている規則を再送せず、名前で示します。
  * 各ハーネスは自分用のツールの説明だけを含みます。
  * Code Generation では、生成したファイルごとに助言用のリンターと型チェックのセンサーを実行しなくなりました（型チェックは引き続き Build and Test で実行します）。
* レビューが差し戻される頻度が減りました。
  * エンジンが各ステージの指摘一覧を保持するため、決着した指摘を言い換えたり、再び尋ねたりすることはありません。
  * 空のプレースホルダー行や、紛れ込んだ `##` 見出しだけで、二度目のレビューが必要になることはなくなりました。
  * Unit のない計画で、トレーサビリティのセンサーが Unit 単位のステージを失敗にすることもなくなりました。
* 既定値の変更: `enterprise` を除くすべての同梱スコープで、Guard Policy が `off` になりました（これまで `security-patch` と `infra` は `strict`、ほかは `relaxed` でした）。チームのメモリーに `Mode: strict` がある場合は、引き続きそちらが優先されます。
* 既定値の変更: 新しい `collaborators` 設定は、`enterprise` を除くすべての同梱スコープで `off` です。`/aidlc --collaborators on` を入力しない限り、各ステージは主担当エージェントだけで進みます。
* スクリプトに影響する変更: `aidlc engine testing-posture fingerprint --reapprove` は廃止され、`next` を実行するよう案内する一行で失敗します。計画が変わった場合は、エンジンが Plan Approval を再び尋ねます。
* スクリプトに影響する変更: 構成した計画はスコープファイルを書き出しません。本人が計画の保存を求めたときに、`aidlc engine scope save --name <name>` がスコープファイルを書きます。
* スクリプトに影響する変更: Windows では、UAC 下の「管理者として実行」のウィンドウで `install.ps1` を実行すると、拒否ではなく警告して確認を求めます。非対話の実行は、`-Yes` を渡さない限りそこで停止します。フルトークンのセッション（組み込みの Administrator、または UAC がオフ）では警告なしでインストールします。`AIDLC_ALLOW_ADMIN_INSTALL` は読まれなくなりました。
