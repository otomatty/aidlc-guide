# Kiro Windows 出力エンコーディングの証跡

このディレクトリは、`2.6.75` の Kiro コマンド出力修正に関する、秘匿化済みのネイティブ
Windows 証跡を保持します。完全な診断キャプチャには一時的な
ワークスペースパス、セッション識別子、IDE の完全な DOM スナップショットが含まれます。
チェックインされた NDJSON は、正確なコマンド出力とモデルのフォローアップ文面を保持しつつ、
これらのマシンローカルなフィールドを安定したメタデータへ置き換えています。

## キャプチャが証明すること

`kiro-ide-windows.ndjson` は 3 つの面を分離します。

1. 現行ベースラインの決定論的なツール出力。
2. その出力の後に付加されるシェルトランスポートのサフィックス。
3. モデルによる別個のフォローアップ文章。

Kiro IDE 1.0.242 では、復元された指摘の Unicode 破損はもはや
再現しませんでした。`█`、`▒`、`░`、`─`、`✓`、`⇄`、`—` は本変更の前から
無傷でした。ESC バイトで終わるシェル断片は、status と doctor の両方の後で
依然として再現しました。この区別が重要です。ホストバージョンの挙動は変わっていた
一方で、残っていたトランスポートの欠陥とモデルの言い換えは独立していました。

修正版のキャプチャは `aidlc-terminal-command` と
`aidlc-terminal-command-guard` を使います。正確な Unicode 出力を保持し、
PowerShell/ESC のサフィックスを記録せず、Allow クリックを一切必要とせず、モデルの要約が
あれば別個の `model_followup` フィールドに残します。

`kiro-cli-windows.ndjson` は、現行ベースラインと修正版のペアを保持します。すべての行が、
実際の ACP の `model` 面とは別に、ネイティブアダプターの `transport` を
含みます。現行ベースラインでは、CLI のトランスポートはすでに UTF-8 を保持しており、
残骸も運んでいませんでした。モデルは決定論的なブロックの後にフォローアップ文章を
加えていました。修正版の行は同じトランスポート／拒否のセマンティクスを保持します。4 つの
ACP ターンはすべて `stop_reason: "end_turn"` で終わり、ツール呼び出しはゼロ、
ツール呼び出しの問題もゼロです。

## 焦点を絞った検証

- ローカルの `t218-kiro-ide-hook-adapter`: 58 件成功。
- ネイティブ Windows の `t218-kiro-ide-hook-adapter`: 58 件成功。
- ネイティブ Windows の Kiro CLI ACP キャプチャ: status と doctor はツール呼び出しなしで
  クリーンに終了。
- ネイティブ Windows の Kiro IDE キャプチャ: status と doctor は一致し、代表的な
  グリフはすべて生き残り、シェルの残骸は存在せず、Allow クリック数はゼロでした。
