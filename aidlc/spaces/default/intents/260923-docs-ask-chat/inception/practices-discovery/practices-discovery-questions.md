# Practices Discovery — Questions

既に決まっている進め方（短いブランチで main に squash、ローカル専用、oxlint / oxfmt、単一の `bun run check`）は聞き直しません。下は、下書きとレビューで決まらなかった点だけです。

## Question 1

チャット画面を足すとき、テストはどの順で書きますか。実装してからテストを足すのが test-after、先に失敗するテストを書くのが TDD、受け入れシナリオを先に書くのが BDD です。

A. test-after — 実装してから、その層のテストを書く
B. TDD — 先に失敗するテストを書き、それから実装する
C. BDD — 受け入れシナリオを先に書き、それから実装する
D. custom — 画面の受け入れは先にシナリオ、下位の単体テストは実装後
X. Other (please specify)

[Answer]: B. TDD — 先に失敗するテストを書き、それから実装する

## Question 2

ドキュメント質問（docs-qa）専用のカバレッジ下限は、今は設定されていません。公式ドキュメント読み込みの一部には、分岐 95% の下限が既にあります。

A. 新設しない — 既存テストが緑ならよい
B. チャット経路の UI と契約テストを足す。数値の下限は新設しない
C. 新設する — 対象パスと、行または分岐のパーセントを Other で指定する
X. Other (please specify)

[Answer]: C. 新設する — docs-qa を分岐 70% 以上にする

## Question 3

チャット画面の UI テストと契約テストを、品質ゲートの必須項目にしますか。必須にすると、`bun run check` に含めない変更は通りません。

A. テスト方針のメモに留める
B. 必須にする（ALWAYS: チャット画面化の UI/契約テストを `bun run check` に含める）
X. Other (please specify)

[Answer]: B. 必須にする（ALWAYS: チャット画面化の UI/契約テストを `bun run check` に含める）

## Question 4

質問履歴の上限が、画面側（完了 3 件・6000 字）とサーバ側（history 8 件）で違います。今回のチャット化で、どちらかに揃えますか。

A. 今回揃える — 画面とサーバで同じ上限にする
B. 後回し — 今回は上限を変えない
X. Other (please specify)

[Answer]: A. 今回揃える — 画面とサーバで同じ上限にする

## Question 5

classic の行カバレッジ 80% は、どこに掛けますか。既存の分岐 95% の床は、その対象パスではそのまま残します。

A. ワークスペース全体
B. 今回変更するパッケージと、新しく足すパスだけ
X. Other (please specify)

[Answer]: A. ワークスペース全体

## Question 6

最初に、端から端まで通る薄い一本を先に作りますか。walking skeleton は、部品がつながることを先に確かめる最小の通し実装です。今のチーム方針は、スコープが骨格セレモニー無しなら通常の実装として進める、です。

A. 先に薄い通しを作る（ソロで、承認してから残りを進める）
B. セレモニーはしない — 最初の実装も通常どおり進める
X. Other (please specify)

[Answer]: B. セレモニーはしない — 最初の実装も通常どおり進める
