# ユーザーストーリー

分け方は操作の流れである。入口、チャットでの続き、保存、引用から戻る、の四本。すべて Must Have。主人公は質問者ひとり。

## US1.1 ホームからチャットへ入る

質問者として、ホームの入口から質問を送り、チャット画面へ移りたい。回答カードの列ではなく、続きを聞ける画面で質問を始めたい。

- **優先**: Must Have
- **依存**: なし
- **INVEST**: 入口だけの流れとして独立している。2000 字の判定はこの流れに含める。

- **AC1.1.1** ホームを開いたとき、質問の入口はある。回答カードは無い。
- **AC1.1.2** 2000 字以内の質問を送ると、チャット画面へ移る。ホームに回答は積み上がらない。
- **AC1.1.3** 2000 字を超える質問は、その入口から送信できない。
- **AC1.1.4** ホストモードでは、入口からの送信が拒否される。チャット画面へは移らない。

## US2.1 チャットで続きを聞く

質問者として、チャット画面で前のやり取りを踏まえて次の質問を送りたい。応答が終わるまでは次を送らず、止めたくなったらキャンセルしたい。

- **優先**: Must Have
- **依存**: US1.1
- **INVEST**: 送信と待ちとキャンセルに閉じる。保存と記事遷移は別の物語。

- **AC2.1.1** 完了したターンのあと、次の質問をチャット画面から送れる。
- **AC2.1.2** その送信の履歴は、直近 8 件の完了ターンである。各回答は文字数で切られない。これは送った内容を見て判定する。
- **AC2.1.3** 2000 字を超える続きの質問は、チャット画面から送信できない。
- **AC2.1.4** 応答が完了するまで、次の質問は送信できない。待ち行列は無い。
- **AC2.1.5** 進行中の応答を、いまと同じキャンセルで止められる。
- **AC2.1.6** 進行中に送信を試みても、そのジョブは切り替わらない。試みは拒否され、進行中の応答が残る。
- **AC2.1.7** 進行中の質問が 1 件あるあいだ、もう 1 件は処理されない。2 件目の送信は拒否される。
- **AC2.1.8** ホストモードでは、チャットからの送信、取得、キャンセル、根拠の取得が拒否される。

## US3.1 次に開いても会話が残る

質問者として、アプリを閉じたあとに同じ会話を開きたい。モデルへ渡す件数で、見えていたターンが消えてほしくない。

- **優先**: Must Have
- **依存**: US2.1
- **INVEST**: 残ることだけを見る。渡す履歴の件数は US2.1 が持つ。

- **AC3.1.1** アプリを閉じ、次に開いたとき、チャットが一覧にしていたターンが残っている。画面に一度に映る分だけでなく、スクロールで届く分も含む。
- **AC3.1.2** 一覧が 8 件を超えても、古いターンは一覧から消えない。
- **AC3.1.3** 次の質問へ渡す履歴だけが直近 8 件である。これは送った内容を見て判定する。
- **AC3.1.4** 会話の保存は、このマシン上で完結する。保存のためにクラウドへ送らない。

## US4.1 引用から記事へ移って戻る

質問者として、回答の引用から記事を開き、チャットへ戻りたい。戻ったとき、会話と書きかけの文が残っていてほしい。

- **優先**: Must Have
- **依存**: US2.1
- **INVEST**: 記事への往復だけを見る。チャットを残した分割表示はしない。

- **AC4.1.1** 引用を選ぶと、記事の画面へ移る。
- **AC4.1.2** 記事からチャットへ戻れる。
- **AC4.1.3** 戻ったとき、会話と書きかけの文が残っている。
