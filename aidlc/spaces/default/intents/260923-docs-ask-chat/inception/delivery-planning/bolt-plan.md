# 通しの計画

通し（Bolt）は、一塊の作業を一度に作り、動くところまで持っていく区切りである。この変更の通しは一つである。根拠は `requirements.md`、`stories.md`、`mockups.md`、`unit-of-work.md`、`unit-of-work-dependency.md`、`unit-of-work-story-map.md`、`team-practices.md`。部品一覧（`components.md`）と契約（`contract-summary.md`）は作られていない。

## 順序

| 順 | 通し | 含む塊 | 骨格 |
| --- | --- | --- | --- |
| 1 | B1 | `docs-ask-chat`（U1、`u1-docs-ask-chat`） | しない |

骨格用の最初の通しは行わない。B1 は通常の通しである。塊が一つなので、依存の順から外れる並べ替えは無い。

## B1

チャット画面、質問の履歴、このマシン上の会話の保存、送信中の制御を、一度に作る。

### 完了の条件

- US1.1、US2.1、US3.1、US4.1 の受入条件を満たす。
- アプリを閉じて開き直したとき、一覧にしていたターンが残っている。画面に一度に映る分だけでなく、スクロールで届く分も含む。
- モデルへ渡す履歴は直近 8 件の完了ターンで、各回答は文字数で切らない。画面の一覧は 8 件では切り詰めない。
- 質問は 2000 字まで。応答が終わるまで次は送れない。キャンセルはいまのまま。
- ホストモードでは、入口とチャットの送信、取得、キャンセル、根拠の取得を拒否する。
- チャット画面の UI テストと契約テストが `bun run check` に含まれる。
- 先に失敗するテストを書き、それから実装する。

### この通しが確かめること

アプリを閉じたあと、次に開いたときに同じ会話が残る。これが、この通しで先に確かめることである。

### 見せるもの

ドキュメントを開き、質問を送り、チャットで続きを聞く。アプリを閉じて開き直し、会話が残っていることを見る。引用から記事へ移り、チャットへ戻ったとき、会話と書きかけの文が残っていることを見る。
