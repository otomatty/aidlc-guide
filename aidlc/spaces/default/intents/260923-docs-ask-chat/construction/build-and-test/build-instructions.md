# ビルド手順

docs-ask-chat は既存のワークスペースに載る。新しいデータベース、コンテナ、環境変数はない。

## 依存関係

リポジトリのルートで、ロックファイルに従って入れる。

```bash
bun install
```

## 環境

クラウドの認証も、追加の設定ファイルも要らない。拡張の実行時は VS Code 同梱の Node を使う。ここでの確認はワークスペースの品質ゲートで行う。

## ビルド

品質ゲートが型検査、lint、フォーマット、ドキュメント索引、互換性、カバレッジ付きテスト、監査をまとめて実行する。定義は `package.json` の `check` だけを見る。

```bash
bun run check
```

型だけを見るときは次を使う。

```bash
bun run typecheck
```

## 確認

`bun run check` が終了コード 0 で終わること。カバレッジは `vitest.config.ts` の `coverage.thresholds` が落とす。`packages/api-core/src/handlers/docs-qa.ts` の分岐は 70% 以上、ワークスペースの行は 80% 以上、既存の 95% ブロックはそのままである。

## 詰まったとき

- `bun install` のあとロックファイルが変わっていたら、コミット済みの `bun.lock` に戻してからやり直す。
- カバレッジだけが落ちるときは閾値を下げない。対象テストを足す。
- 引用ボタンがリンクに戻っていると、既存の `useDocsQa.test.tsx` がボタン名で失敗する。表示名は `参照 N: 題名` のままにする。
