# Stakeholder Map — Docs i18n

> ステージ: intent-capture (Ideation 1.1) / 作成日: 2026-07-31  
> 根拠: [intent-statement.md](./intent-statement.md) + intent-capture-questions.md

## Key Stakeholders（主要ステークホルダーと関心事）

| ステークホルダー | 役割 | 関心事 |
|----------------|------|--------|
| 初学者エンジニア | 主受益者（Q2 = A） | 日本語で公式相当を拡張内だけで読めること。英語原文への切替もできること |
| ドライバー | 利用・説明者 | モブやレビュー中に docs をその場で見せられること。外部ブラウザに依存しないこと |
| ドキュメント整備担当 | 翻訳・承認の運用者 | upstream 差分が分かり、別 PR で翻訳をレビュー・マージできること（Q6 = B） |
| プロダクトオーナー（本ワークフロー承認者） | 意思決定者 | スコープ（guide+reference、置き換え方針、Operation SKIP）が守られること |
| aidlc-workflows フレームワーク保守者 | 上流依存の所有者 | 本機能が公式 docs をコピー／翻訳するだけで、エンジンやステージ定義を変更しないこと |

## Decision-Makers vs. Influencers（意思決定者と影響者）

- **意思決定者**: プロダクトオーナー（各ステージゲートで承認）／ドキュメント整備担当（翻訳 PR の内容承認 — Q6）
- **影響者**:
  - 初学者 — 言語切替 UI の分かりやすさが成否を測る（S-docs-1）
  - ドライバー — 日常の説明導線での使い勝手
  - フレームワーク保守者 — docs ツリー構造・見出し変更が差分運用コストを左右

## Communication Requirements（コミュニケーション要件）

- **承認ゲート（本ワークフロー）**: intent / scope / design / code の各成果物はプロダクトオーナーがゲートでレビュー
- **翻訳ゲート（運用）**: upstream 差分レポートを起点に、翻訳変更は**別 PR**でレビューし、承認後にのみ `ja` を更新（Q6 = B）
- **利用者向け**: 表示中の `sourceVersion`（同梱 upstream 版）と locale を UI 上で明示する
- **非ゴールの周知**: 社内 Confluence 等の「別ドキュメントサイト」を本機能の正本にしない（Q4 = C の意図）

## 非技術者向け要約

AIDLC Guide の拡張の中に、公式ドキュメントの英語版と日本語版を同じ並びで入れ、画面上で言語を切り替えられるようにします。公式の更新があったときは差分を自動で知らせ、日本語の反映は人が確認した PR だけで行います。社内に別の日本語ドキュメントサイトを用意しなくてよくするのが狙いです。
