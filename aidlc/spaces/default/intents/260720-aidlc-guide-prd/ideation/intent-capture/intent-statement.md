# Intent Statement — AIDLC Guide

> ステージ: intent-capture (Ideation 1.1) / 作成日: 2026-07-21
> 根拠: [docs/prd/PRD.md](../../../../../../docs/prd/PRD.md) v0.1（本ワークフローでは承認済みベースラインとして扱う — Q1回答）+ intent-capture-questions.md の回答

## Problem Statement（解決する業務課題）

aidlc-workflows v2 は5フェーズ・32ステージで監査可能性・再現性を担保するが、その構造が人間側に4つの課題を生んでいる（PRD §1）:

- **P-1 現在地がわからない** — 経験の浅いエンジニアは、今どのフェーズ・ステージにいて次に何が来るのかを状態ファイルの生テキストから読み解けない
- **P-2 成果物が多すぎて把握できない** — ユニット×ステージで同名ファイルが増殖し（実例: 1インテントで約593ファイル）、全体像・欠落・薄い箇所が見えない
- **P-3 調べ物が本線セッションを汚す** — ワークフロー実行中の技術質問・用語質問が本線のAIセッションの文脈を濁す
- **P-4 モブ時のリアルタイム共有ができない** — 同期的にワークフローを回すとき、ドライバーのブランチ状態を参加者全員が確認する手段がない

直接のトリガーは**直近のモブセッションで初学者のオンボーディング負荷が顕在化したこと**（Q4回答）。

## Target Customer（誰がどう恩恵を受けるか）

社内のaidlc-workflowsユーザー3ペルソナ。**初期から全ペルソナを均等に扱い、マイルストーン順で価値を届ける**（Q2回答）:

| ペルソナ | 恩恵 |
|---------|------|
| 初学者エンジニア | 現在地・次のステージ・用語を自力で理解できる |
| ドライバー | 本線セッションを汚さずに調べ物ができ、状態を参加者に見せられる |
| モブ参加者 | ブランチの中身とAIとのやりとりをライブで追える |

## Success Metrics（測定可能な成果）

PRD §10 の4指標。**北極星は S-1**（判断に迷ったときのタイブレーク — Q3回答）:

- **S-1（北極星）**: 初学者が「現在のステージ・次のステージ・そこで求められること」をツールだけで**1分以内**に説明できる
- S-2: モブ参加者がドライバーへの口頭確認なしにブランチ状態を把握できる（モブ後アンケートで確認）
- S-3: 本線セッションのやり直し（文脈汚染起因）が減る（定性）
- S-4: ステージに関する「これ何？」系質問がツールで自己解決される割合

## Initiative Trigger（なぜ今か）

- 直近のモブセッションで初学者のオンボーディング負荷が顕在化した（主トリガー — Q4回答）
- 参考事例として tb-lxp インテント（約593ファイル）が成果物把握の限界を示している（PRD §1）

## Initial Scope Signal（初期スコープの手がかり）

- **実装範囲**: PRD §9 の M1〜M4 すべてを本ワークフローで実装する（Q5回答）— 状態読み取りライブラリ、サイドセッションからの照会手段、ダッシュボード、成果物ビューア、モブ共有モード、運用ガイドまで完走
- **読み取り専用の原則**: 本ツールはワークフロー成果物を閲覧するだけで、書き込まない（質問ファイルの回答記入のみ例外 — PRD §2 非ゴール）
- **ローカルツールに徹する**: クラウドサービス化・アカウント管理はしない（PRD §2 非ゴール）
- **適用スコープ**: カスタムスコープ `prd-implementation`（21/32ステージ、Standard深度）で運用系ステージの大半をSKIP済み
- **正式名称**: 「AIDLC Guide」に確定（Q6回答 — PRD §12 の未決事項を解消）

## 前提（Assumption）

- PRD v0.1 は形式上「レビュー待ち」だが、本ワークフローでは承認済みベースラインとして扱う（Q1回答）。PRD自体の変更が必要になった場合は各ステージのゲートで扱う
