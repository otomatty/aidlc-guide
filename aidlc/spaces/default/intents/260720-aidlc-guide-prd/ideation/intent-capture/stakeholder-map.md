# Stakeholder Map — AIDLC Guide

> ステージ: intent-capture (Ideation 1.1) / 作成日: 2026-07-21
> 根拠: intent-statement.md のペルソナ定義 + PRD §3

## Key Stakeholders（主要ステークホルダーと関心事）

| ステークホルダー | 役割 | 関心事 |
|----------------|------|--------|
| ドライバー（ワークフロー実行者） | 本ツールの直接ユーザー兼運用者 | 本線セッションの文脈を守りたい。状態を参加者へ見せたい。ツール導入・維持のコストが低いこと |
| 初学者エンジニア | 本ツールの最重要受益者（北極星S-1の主語） | 現在地・次のステージ・用語を気軽に知りたい。質問の心理的ハードルを下げたい |
| モブ参加者 | 閲覧ユーザー | ライブでブランチ状態・成果物・AIとのやりとりを追いたい。準備の手間なく参加したい |
| プロダクトオーナー（PRD著者 = 本ワークフローの承認者） | 意思決定者 | PRDのゴールG-1〜G-5が達成されること。スコープ逸脱（書き込み機能・クラウド化）が起きないこと |
| aidlc-workflows フレームワーク保守者 | 上流依存の所有者 | 本ツールがフレームワークの状態・成果物を読み取り専用で扱い、本体に変更要求を出さないこと（PRD §2 非ゴール）。構造変更時の追従は本ツール側の責務 |

## Decision-Makers vs. Influencers（意思決定者と影響者）

- **意思決定者**: プロダクトオーナー（本ワークフローの各承認ゲートで承認・差し戻しを行う）
- **影響者**:
  - ドライバー — 日常運用のフィードバックで機能優先度に影響
  - 初学者エンジニア — S-1/S-4 の達成度がツールの成否を測る
  - モブ参加者 — S-2 のアンケート回答者
  - フレームワーク保守者 — 状態ファイル・ディレクトリ構造の変更が本ツールの追従コストを左右（PRD §11 リスク）

## Communication Requirements（コミュニケーション要件）

- **承認ゲート**: 各ステージの成果物はプロダクトオーナーが本ワークフローのゲートでレビュー・承認する
- **マイルストーンごとの実データ検証**: M1〜M4 の各完了条件は実インテント（tb-lxp、約593ファイル）を使った読み取り確認で示す（PRD §9）— 検証結果はゲートで報告
- **モブでの実地確認**: M4 完了条件は「モブセッション1回の完走」— モブ参加者へのアンケート（S-2）で効果を確認
- **利用者向け案内**: サイドセッションの既知の制約（分岐時に直近の会話文脈が含まれない場合がある等）はヘルプ・ドキュメントに明記して周知する（PRD FR-3.4）

## 非技術者向け要約

「AIDLC Guide」は、AI駆動開発ワークフローの“今どこにいて、次に何をするのか”を誰でも1分で分かるようにする社内向けの閲覧ツールです。作る側（ドライバー）、学ぶ側（初学者）、見る側（モブ参加者）の3者が主な利用者で、承認はプロダクトオーナーが各段階のゲートで行います。
