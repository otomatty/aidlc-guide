# Personas — AIDLC Guide

> ステージ: user-stories (Inception 2.4) / 作成日: 2026-07-22 / lead: product（mob draft round 0）
> 入力: intent-statement.md（3ペルソナ均等）+ requirements.md
> 3ペルソナは均等に扱う（優先度は同格。実装順はマイルストーン M1→M4 の依存順、タイブレークは北極星 S-1）。

## P1: 初学者エンジニア（Novice）

- **役割**: aidlc-workflows の経験が浅い。モブに参加する立場で、ワークフローの全体像を掴もうとしている。
- **ゴール**: 「今どのフェーズ・ステージにいて、次に何が来て、そこで自分（人間）に何が求められるか」を、人に聞かずに理解したい。用語（Bolt/gate/unit）も自力で引きたい。
- **ペイン**: `aidlc-state.md` の生テキストや 593 ファイルの成果物ツリーからは現在地・全体像が読み解けない（P-1/P-2）。
- **コンテキスト**: デスクトップブラウザで Dashboard を見る。技術用語に不慣れ。
- **成功の形（北極星 S-1）**: ツールだけで現在地・次ステージ・求められることを 1 分以内に説明できる。

## P2: ドライバー（Driver）

- **役割**: 本線の Claude Code セッションでワークフローを実際に進める人。モブのドライバー。
- **ゴール**: 本線セッションの文脈を汚さずに技術質問・用語質問・実装状況調査をしたい。自分の状態を参加者に見せたい。
- **ペイン**: ワークフロー実行中に調べ物をすると本線 AI セッションの文脈が濁り、`/clear` ややり直しが増える（P-3）。
- **コンテキスト**: ターミナル（Claude Code）中心。別ターミナルや別ウィンドウを併用できる。
- **成功の形**: 調べ物起因の本線やり直しが減る（S-3）、質問が自己解決される（S-4）。

## P3: モブ参加者（Mob Participant）

- **役割**: ドライバーの画面を見ながら議論・質問回答する参加者。
- **ゴール**: ブランチの中身（成果物）と AI とのやりとり・状態変化をライブで追いたい。
- **ペイン**: 同期的にワークフローを回すとき、ドライバーの状態を確認する手段がなく口頭確認に頼る（P-4）。
- **コンテキスト**: 自分のブラウザで参加者ビューを見る（read-only）。ドライバーとは別マシン。
- **成功の形**: 口頭確認なしにブランチ状態を把握できる（S-2）。

## ペルソナ関係と優先順位

- 3ペルソナは **均等**（intent-statement）。誰か一人のためのツールではなく、モブという場を3者で成立させる。
- 依存関係: ドライバーが回す → 初学者が理解する → 参加者が追う。3者が揃って完全な価値（M4完了時）。
- タイブレーク: 判断に迷ったら北極星 S-1（初学者の現在地理解）を優先（project.md Decided）。
