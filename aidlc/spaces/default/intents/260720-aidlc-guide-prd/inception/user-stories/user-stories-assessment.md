# User Stories Assessment — AIDLC Guide

> ステージ: user-stories (Inception 2.4) / 作成日: 2026-07-22
> 入力: requirements.md + team-practices.md + intent-statement.md（3ペルソナ）

## Decision

**Execute（ユーザーストーリーを作成する）。**

## Rationale

本ツールは「開発者ツール」だが、単純な内部ライブラリではなく **明確にユーザー対面の UI（Dashboard F-04）を持ち、性質の異なる3ペルソナ**（初学者エンジニア / ドライバー / モブ参加者）を **均等に** 扱う（intent-statement）。各ペルソナの目的・ペインは異なり（現在地理解 / 本線を汚さない調べ物 / ライブ状態把握）、同じ機能でも価値の出方が違う。したがって「開発者ツールだからストーリー不要」の除外条件には当たらず、ペルソナ別のストーリーで価値と受入基準を明確化する意義が大きい。

スコープグリッドでも user-stories は EXECUTE。

## Factors Considered

| 因子 | 評価 |
|------|------|
| ユーザー対面か | Yes（Dashboard・ビューア・参加者ビュー）|
| 複数ペルソナか | Yes（3ペルソナ均等）|
| 業務ロジックの複雑さ | 中（state パース・マトリクス構築・リアルタイム反映）|
| 除外条件（純粋なリファクタ/バグ修正/インフラ/開発ツール）該当 | 開発ツールだが UI+複数ペルソナのため除外に当たらない |

## 価値が最も出る領域（ストーリーの重点）

- **初学者の現在地理解フロー**（S-1北極星）— Now strip + Stage rail + ステージカード
- **ドライバーの本線非汚染**（P-3）— btw + MCP 5ツール
- **モブ参加者のライブ共有**（S-2）— Mob モード + read-only 参加者ビュー
- **成果物閲覧**（P-2）— マトリクス + WYSIWYG ビューア
